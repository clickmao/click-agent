# R437 · 按任务长度分档的降幅评估（「一轮任务 ≠ 一次链调用」口径）

- 轮次来源：用户口径澄清（2026-09-14，逐字）「一轮任务，应该是长任务30%左右，中短任务啥的具体降低多少你要自己评估下(注意一轮不是走一次链，可能很多次也可能只用一次)」
- 性质：**分析/评估轮**（零产品源码、零 dotnet、零测量窗占用）——对侧 R436（`v0.57.0-r436-e2e-brj-token-kpi.md`）正在跑真机臂，本侧按并发铁律只做离线证据。
- 器具：`eval/capability/r437-task-length/model_task_length.py`（纯 stdlib，可复现）→ `result.json`

## 1 口径

一轮任务 = 一个会话，含 N 次链调用（N 可能 = 1）。判据 = `1 − Σ_B / Σ_A`，其中 A = 门关（现状），B = 门开（r1 判认可族 ⇒ 跳远端主调用）。
门只在**残余带**（无机械信号的短消息）生效 ⇒ 可跳轮 = 会话内的「认可族」消息。

## 2 模型（参数全部来自 R434 真机实测，非拍脑袋）

| 项 | 形式 | 标定值（p8 / p12） | 实在含义 |
|---|---|---|---|
| 主答单次 token | `T(i) = T0 + g·i` | T0 = 1848 / 1815，g = 90.4 / 108.6 | 每次远端调用携带全部历史 ⇒ 线性增长 |
| 角色块偏移 | `δ(i) = δ0 + dg·i` | δ0 = 79 / 77，dg = 2.25 / 2.74 | 门要 role ⇒ 每次远端调用**多带** role 块（只多不少） |
| 关系判官 J | 53.2 tok/次（n=7/8） | — | 有 role 时每轮一次（R434 实测 J 本地成功 1/7 ⇒ 默认远端） |

`A = Σ_{i∈answered} T(i)`；`B = Σ_{i∈answered∖S} [T(i)+δ(i)] + |answered|·J`；`降幅 = 1 − B/A`。

## 3 回验（模型 vs R434 实测，两格）

| 格 | 模型 | 实测 | 绝对误差 | 相对误差 |

## 5 结论（三条，可直接引用）

1. **长任务 ≈ 可跳轮占比**：N≥20 且认可轮散布时，降幅 27.6–28.5%（可跳比 1/3）⇒ 「长任务 30% 左右」成立，前提是**可跳比 ≈ 1/3**；可跳比 1/2 ⇒ 47–61%。
2. **中任务 = 可跳比 × 位置折扣 − 固定开销**：8–12 轮、可跳 1/3 ⇒ 24–37%（实测锚 33.3% / 27.8%）；同可跳比下**越靠后跳越省**（早 24.3% ↔ 晚 34.6%，差 10.3pt）。
3. **短任务与单次：收益由「那一轮是不是认可」决定，非长度决定**：单次真诉求 = **净亏 6.9%**（白付 role 块 79 + J 53 ≈ 132 tok）；单次认可 = 省 97%。N≤3 且可跳 1/3 ⇒ 28–30%，与中任务同档。

**固定开销的规模**：δ+J ≈ 132 tok/轮、J 独立 53/轮（远端）⇒ 无认可轮的任务一律净亏 4.6–6.9%；随 N 增大摊薄（N=40 时 ≈ 4.6%）。

## 6 诚实边界

1. 模型为**双点标定**（p8/p12 实测），回验 ≤1pt，但**未在第三、第四格上验证**（N=1/3/20/40 均为外推）⇒ 「未测到」≠「已验证」。
2. 参数取自桩器具的 `prompt_tokens_est`（估算法），与真实 LLM 计费 token 存在系统性偏差；结论是**比例关系**，不是绝对 token 数。
3. 位置权重来自模型，未做「可跳轮靠后」的独立实测格。
4. 单机单次会话；未含墙钟/CPU 成本（本地 r1 的门判自身有算力开销，不花 API token）。
5. 未含产品澄清 ask 机制造成的「吞轮」效应（A/B 两臂同源，不改变比值）。
6. J 通道：R434 口径为远端兜底 6/7；对侧 R435 已修至本地 5/6 ⇒ 本表 J=53/轮 为**保守（偏高）**；按其修复折算，各档约 +1.1…+1.9pt 改善。
