**第二步：一行构建命令的完整形式**
```
dotnet build "/abs/path/Your.sln" -c Release --nologo -v minimal
```
各段含义：
- `dotnet build`：调 MSBuild 走还原+编译，一步到位；
- 路径：写**绝对路径**，因为子进程/子任务会切工作目录，相对路径不可靠；
- `-c Release`：指定配置（默认 Debug），影响优化与产物目录；
- `--nologo`：去掉启动 banner，便于日志比对；
- `-v minimal`：日志级别，可换 `-v n`（正常）或 `-v q`（仅错误）。
可选加：`-p:TreatWarningsAsErrors=true`（警告即错误）、`-o "/abs/out"`（自定义输出目录，会与增量编译交互，慎用）。

**第三步：确认构建结果**
看真实退出码：`echo $?` 为 `0` 才算通过。注意构建通过 ≠ 功能可用，需另跑 `--selftest`。

**关于发布**：若要出可执行产物用 `dotnet publish "/abs/path/Your.csproj" -c Release -o "/abs/out"`；按本仓库约定 **AOT 发布不带 `-p:PublishAot`**。

把你实际的 `.sln`/`.csproj` 路径发我，我直接替换成可复制执行的那一行。

## 第 8 轮（user: '换个说法。'）

```text
换个讲法：构建命令就是「**调用谁 + 编哪个 + 怎么编**」三件事拼一行。

- **调用谁**：`dotnet build`。
- **编哪个**：目标文件的**绝对路径**（相对路径会在子进程切目录后失效）。
- **怎么编**：配置、日志、开关等修饰项。

拼起来：
```
dotnet build "/abs/path/Your.csproj" -c Release --nologo
```
修饰项按需加，不是必选：`-c Release` 定配置；`--nologo` 净日志；`-v minimal` 控详细度；`-p:TreatWarningsAsErrors=true` 让警告变错误。

判定成功的唯一标准是退出码为 `0`（`echo $?`），编译过不代表功能可用。要出可执行产物则换成 `dotnet publish ... -o "/abs/out"`，本仓库约定 AOT 时不带 `-p:PublishAot`。

前提仍缺：该工作区顶层只有 `data/`，没定位到 `.sln/.csproj`，所以上面用的是占位路径。把实际路径给我，我替成可直接跑的一行。
```
