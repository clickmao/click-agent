# R415 证据 — 链级钉死「前置门入参 = 用户本轮原文」

**判据先于测量**：下面的 A1–A9 在跑臂之前就已固定，且全部只认**外部真值**（两路服务端的逐请求落盘），
不采信被测量代码自报的计数器（教训：自算错而自洽是最隐蔽的失真形态）。

## 1. 这一轮要回答什么

R413 证明过：把 r1 真假判别前置到主调用之前，一轮 12 调用 / 16,888 tok 降到 8 调用 / 7,007 tok（-58.5% tok）。
但那次增益曾经**归零**过一次——第三个空心根因：前置门吃的是 `prompt.UserMessage`（已追加 role/计划/知识块），
不是 `message.Content`（用户本轮原文）⇒ 门恒 Pass。当时的防线只是一条**源码级**钉死（G29：扫源码字面量）。
源码级钉死挡不住「换个变量名/绕一层 helper」的等价回退，所以本轮把它升级成**行为级、端到端**的钉死。

## 3. 构造（为什么判定器不是模型）

判定器必须可复现，所以本轮把本地后端换成**确定性假实现** `fake_llama.py`（模拟 llama-server 的
`/health /props /apply-template /tokenize /completion`）：用户原文含「谢谢」⇒ 判 S（跳过），否则判 P（走远端）。
链本身完全没被改动：真 `agenthost`、真 DI 装配、真 `ModelQueueRouter`、真 `LlamaCppLocalGenerationPort`、
真进程+HTTP 形态（零 P/Invoke），唯一被替换的是「后端是模型」这一点。

判别力哨兵靠**知识提示型技能**注入：`skills/r415-gate-pin/SKILL.md`（`type: knowledge_hint`，关键词 `收到/谢谢`）
命中后其 body 会作为 `[技能知识参考]` 块尾挂到 `prompt.UserMessage`（`IndustrialAgentV2.cs:1200`）
⇒ 该轮 `prompt.UserMessage != message.Content`，门若吃错变量立刻可辨。

任务脚本三轮（`task.json`）：t1 `收到，谢谢。`（判别轮，期望 S ⇒ 跳过）；t2 `嗯，就这样。`（判别轮，期望 P ⇒ 走远端，
钉死假阴性）；t3 `收到，就这样吧。`（技能命中，做 A7 正控）。

## 6. 仪器教训（本轮两次无效跑，均如实记录）

1. **假服务端必须显式解 `Transfer-Encoding: chunked`**。`HttpClient` 以 chunked 发送时没有 `Content-Length`，
   第一版按 `Content-Length` 读 ⇒ 请求体读成空 ⇒ 假后端「看到」空提示、判定恒 P、判据全废。
   识别特征：日志里 `keys=[] / raw=''`，而远端侧同一轮却有正常 prompt。
2. **判定规则必须锚定「待判原文」段，不能全文匹配**。判别提示词自带 few-shot 示例，
   里面就有 `用户: 收到，谢谢。 → S` ⇒ 全文匹配「谢谢」会把三轮全判成 S。
   识别特征：主语段长度正常但判定恒 S、且与远端侧请求内容不符。修正 = 取 `【用户消息】` 段（`答案:` 前）作为待判原文。
3. 两条都不是产品缺陷，是**测量仪器缺陷**；若无第二条正控（A7），仪器错会把「门吃错变量」和「仪器读错」混为一谈。

## 7. 诚实边界

1. 假后端 ⇒ 证明的是**机制/装配**（门拿到的是哪一个变量），不是模型在自然分布下的判准率；
2. 单机单次读数，r1 从未被启动（本轮目的不是测模型，而是测**链的接线**）；
3. A2 单独不构成证据，必须与 A3/A7 同读；
4. 跳过后的可见文案来自既有模板（R413 的 `LocalSkipFallback`），本轮只断言「非空」；
5. 三轮不是分布 ⇒ 不给出任何比率。
