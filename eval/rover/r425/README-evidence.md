## 4. 事故与器具修复（轮内入档）

1. **batch b1 = 器具阴性对照（漏传 `--role`）**：首跑 A/B **逐格逐位相等**（k1:14092/14092 k2:13823/13823 k4:13714/13714 k6:13606/13606 k8:13155/13155），且每轮无本地推理时延 ⇒ 门未进判。源码坐实 `src/agent/IndustrialAgentV2.cs:1464` ⇒ `if (_modelRouter is { TurnGateEnabled: true } && ActiveRole is not null)` ⇒ 门生效的必要条件含 `ActiveRole != null`；**无 role 的臂静默走未门路径**。教训：一切门相关臂必须显式传 `--role`（b1 批次保留为「无 role = 未门」阴性对照，**不作治疗读数**）。
2. **归因口径修正 + 判据操作化缺陷**：首版按「首个覆盖窗口」归因，因轮窗口重叠把整程调用全记到第 1 轮 ⇒ 改**顺序分区** `[t_start_i, t_start_{i+1})`（未归属 0）。同时预注册的 C-c/C-d 未把「臂 A 侧澄清短路」排除 ⇒ 报出 6 例伪假阴性；**事后**改用 A 参照口径（臂 A 有调用而臂 B 无）⇒ 假阴性 0。预注册项**保留为失败**，不作放宽。
3. **回收缺口**：器具 cleanup 只杀 host/stub，框架自启的 `llama-server`（r1/bge）成**孤儿**（`ppid=systemd`，r1 一只占 1.4 GB）；清理 11 只孤儿并在 `run_arm.sh` 增 `pkill -P $HOST_PID` 递归回收 ⇒ b2 跑后残留 **0**。
4. **结算器读数路径 bug**：`prov-*.json` 被测物字段在 `under_test` 之下，首版读顶层键 ⇒ 全 `null`；修正路径后 C1 绿（判据未改，只修读数路径）。
5. **write_file 静默截断（复现）**：本文件首次经 `write_file` 落盘仅 266 B ⇒ 改由 `execute_code` 按机检数据整篇生成（本轮产物文档一律走该路径）。

## 5. 诚实边界

1. **不作全称宣称**：单任务族 + 单机单批（5 格 × 2 臂 + 1 归因臂）；降幅总体随占比上升，但 **k=6 66.44% < k=4 67.97%** ⇒ 「占比」**不是充分统计量**（各格实质轮内容不同、臂 A 侧澄清短路位置不同），只按占比预测降幅会错。
2. **门槛适用面**：本任务族内 **占比 ≥25%** 时 token 降幅 >30%（25%→30.17% 仅擦线越过；12.5%→14.23% 不达标）⇒ 用户令「≥30%」的适用面 = 非实质轮占比 ≳25%，**不外推**。
3. **token 为 `chars/2` 估算**，非真 tokenizer；仅在同口径两臂间可比。
4. **非实质轮为构造文本**，不覆盖真实会话中「像寒暄但含隐含任务」的形态 ⇒ 假阴性只在构造上为 0。
5. **门提示内容不可直接观测**（只能由源码 + ProfileSeed 推断）；role 数据是否进入门提示本轮未复核。
6. **b1 对照用途受限于单侧**：「无 role ⇒ 门不进判」有源码 + 行为两侧证据，但未做「传 role ∧ 门禁用」的正交臂。
7. 未测并发会话、未测 `--session-id` 跨进程续聊下的占比敏感性（各格独立会话）。
