## 0. 本轮问题（先拆解）

R410 结论: K2b 三条件 = **长驻进程 + 稳定长前缀 + cache 开**，且产品通路缺「长驻」（每次调用新起 server ⇒ `cached=0`）。R411 要回答三件事:
1. 「长驻」能不能做成产品侧端口（本进程一个 server 跨轮保活）？

3. 本地生成接进产品既有 K2b 红线时，分母按谁的语义算？

## 4. ★ 自错与判据修正（如实记录，不掩盖）

1. **口径错（最重要）**: 我按字段名字面把 `tokens_evaluated` 当成「新评估数」，得出 `总长 = evaluated + cache_n`。
   - 后果（产品日志可见）: 热轮总长虚增成 1042；同一轮出现 **`有效命中率 = 1.0302 > 1`（物理不可能）**，下一轮又出现 **0.523 的假越线**。
   - 独立实现推翻: `/tokenize` 测出该渲染串只有 529 token ⇒ 1042 物理不可能；`530 == 18 + 512` ⇒ `tokens_evaluated` 就是总长。
   - 已固化: 单测 `LlamaCppPromptAccountingTests.Trap_OldFormulaHalvesTheRatio`（口径错的机检特征 = **比率 > 1**；且错算会把整体复用率腰斩 0.9660 → 0.4914）。
2. **前缀长度误判**: 我把 R410 的 `session-prefix.txt`（780 字符 ≈ 496 token）当成「4249 token 长前缀」——4249 是 R410 探针**运行时重复 25 次**的产物，不是该文件本身。⇒ 首跑「正例/负例」结论颠倒（正例越线、负例不越线），且暴露出上面第 1 条。
3. **判据 N1 预注册写错**: 我预言负控「比值达标、仅长度不足」，实测 19 token 前缀下比值也掉到 0.963（粒度效应）⇒ 判据修正为「双条件均不达标」，并把「比值达标/长度不足」分支**另立由单测隔离覆盖**（不为了让脚本变绿而放宽）。
4. **异常逃逸成 core dump**: 会话分支最初写在 `try` 之外 ⇒ 输入错误时 .NET 未处理异常 ⇒ 进程 abort（exit 134）。已改为 `TryReadSessionRequest` 前置校验（用法错 exit 2）+ 运行期异常映射 4/5。
5. **STJ 大小写敏感**: 请求文件用小写 `turns` ⇒ 反序列化成空 ⇒ 「无 turns」。已给上下文加 `PropertyNameCaseInsensitive`（只影响读取）。
6. **实现缺陷（由单测抓到）**: 命中「未上报」时被误判越线 ⇒ 违反「缺失 ≠ 错误」。已修: 未上报既不算达标也不算越线。
