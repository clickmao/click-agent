## §3 逐例五分（失败层定位，守恒严格）

对 A1 未召回的 30 条查询，按「最小充分路线集合」（P = 池宽可救；S = 同宽形态可救；PB = 形态+更宽池可救）：

| 桶 | 条数 |
|---|---|
| 仅形态即可（S∧¬P） | **0** |
| 仅池宽即可（P∧¬S） | 8 |
| 任一路线即可（P∧S） | 8 |
| 两者皆需（¬P∧¬S∧PB） | **14** |
| 结构性不可召回（全不可） | **0** |
| **合计（须 == 30）** | **30 ✅** |

**前提证伪（原样归档）**：预注册四桶字面定义在实测结构 **S ⊆ P**（形态可回收 ⊂ 池宽可回收）下**构造上不守恒**（P∩S 的 16 条按「仅 A」「仅 B」都不收、「两者皆需」又排除含 P/S 者 ⇒ 必丢，首跑得 14 ≠ 30）⇒ 修法 = 按最小充分路线改**五桶**（守恒严格），四桶 v1 读数原样入 `verdict-r624.json · P5_v1_four_bucket_literal`，**不翻案**。

## §4 本轮捕获的器具缺陷（三条，全部入档）

1. **归档路径缺陷**：`run_r624.sh` 的 `OUT` 用相对路径，而 `dotnet test` 的 cwd = `src/agent.tests/bin/Debug/net10.0` ⇒ 7 臂 payload 全部落在 bin 下（`payload=no`，读数未损坏）。修法 = 绝对路径；已复跑取干净归档。
2. **键集单位缺陷（最贵）**：源码重建的切块按 **Python 码点**计数，实现按 **C# UTF-16 code unit**（`RAGRecall.cs:203-228`）⇒ 文档含星面字符时边界错位 1，键集缺 3 条（实证：3 条残留 miss 的边界恰落在 UTF-16 第 440 单元 = 码点第 439，文档含 💡/📋）。修法 = 按 UTF-16 切块；并以「**实发文本落盘差分**」（默认关的 missdump 闸）证明修复后 **miss_dump_n == 0**。
3. **形态泄漏（承 R623）**：R623 申报「生产 DI」而 `EmbeddingFunction` 未设 ⇒ 兜底形态；本轮把该形态轴做成可切换器具，兜底/生产/负控三态同窗可比。
