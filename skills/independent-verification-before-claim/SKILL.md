# 独立验证先于结论 (independent verification before claim)

**判据零语言特性**: 下面的每一条都只谈"结论/证据/判据"的关系, 与实现语言、框架、工具无关。

## 何时触发

- 你要宣布"某个东西是正确的/通过的/达标的" (代码能跑、答案正确、指标达标、闸门通过)。
- 你要评估一个"能力" (通过率、准确率、命中率、成功率)。
- 你只有一个来源在说"没问题" —— 而那个来源就是被测对象本身。

## 硬判据

1. **禁止自证**: 被测对象给出的"我通过了"不是证据。证据必须来自**另一条独立路径**
   (不同算法族 / 不同实现 / 不同数据来源 / 外部权威)。
   - 追问形式: "这个结论是被测对象自己算出来的, 还是另一条路径复算出来的?"
   - 若两条路径共享同一个底层假设 (同一整数语义、同一标签来源、同一个解析器),
     它们**不算独立** —— 共同盲区不会自发现。
2. **判据必须在被测对象看不到的数据上成立**: 公开样例 (示例、文档、对答案的暗示) 只能用于
   理解任务, 判定必须落在**未公开的用例**上, 否则"硬编码示例"与"真会做"不可区分。
3. **拒绝发未验算的题/未复算的结论**: 生成方若能给出"预期答案", 该答案必须由独立路径复算;
   不一致时**宁可不发**, 也不发一个"可能是错的标准答案" —— 错的标准答案会把后续全部判定污染成噪声。
4. **失败必须分类, 不能只算通过率**: 只报总通过率是空心指标。必须给出失败模式分布
   (缺产物 / 解析失败 / 运行错 / 超时 / 结果错 / 部分错), 否则无法归因、无法改进。
   追问形式: "这个数字里, 有多少是'没测到', 有多少是'测到了但错'?"
5. **判定器自身必须过负控**: 判据必须能被**反向验证** —— 故意注入一个已知缺陷 (错答案、
   跳过比对、恒真判据), 判定器必须变红。不能变红的判据等于没有判据。
   - 具体做法: 把判据内部的关键比较函数替换为"恒真", 看正向负控是否转红;
     若仍全绿, 说明原判据本来就抓不到东西。
6. **分母与口径必须钉死, 并量化口径敏感度**: 任何比率都先写清"分子/分母/弃权项如何处置"。
   若换一种合法口径就能让数字大幅变化, 那么该数字**不是结论**, 只是口径的产物;
   必须报告口径敏感度 (不同合法口径下的极差), 再谈达标与否。
7. **"达到目标 X"必须同口径**: 与外部或历史数字对比时, 分母、数据集、单位必须一致。
   分母不同、任务不同、来源不同的两个数字放在一起比较, 是伪对比。

## 自查问句 (落地时逐条问)

- 这个"通过"是谁说的? 有没有第二条路径?
- 两条路径是否共享同一个前提/同一个解析器/同一份标签? 共享的部分是盲区。
- 判定用的数据, 被测方有没有可能提前看到过?
- 我只报了通过率吗? 失败模式分布在哪?
- 如果我把判据改坏一点, 测试会红吗? 现在红不红?
- 这个比率的分母是什么, 弃权/失败算在哪一侧? 换口径能差多少?
- 我与被比较的数字, 口径真的一致吗?

## 常见失效 (都是"看起来在验证"其实没有)

- 用被测实现给自己打分 (自证闭环)。
- 公开样例当判据 ⇒ 硬编码/记忆即可通过。
- 只报一个总分, 没有失败分类 ⇒ 无法区分"没测到"与"测到了且错"。
- 判据恒真 / 判据从未被反向验证 ⇒ 通过率永远是 100%。
- 报告一个比率但不写口径 ⇒ 同一个数据集可得出差异极大的结论。

## 实例 (语言/工具细节只出现在本节)

- 随机题自检: 期望答案由"参考实现 + 独立校验实现"两条路径复算, 不一致则拒绝发题;
  判定只用隐藏用例; 明细落到"题族 × 失败模式"; 判定器的比较函数被替换为恒真时,
  缺陷解必须由红转绿 (证明判据非空心); 同一份数据在不同合法口径下极差可达数十个百分点。
- 相关候选 (未展开): 组合数用"公式 vs 递推取模"、行列式用"消元 vs 全排列展开"、
  最短路用"标号法 vs 松弛法" —— 换算法族而非换写法, 才算独立路径。
