# 决策路径可复现性 —— 先与复用态解耦, 再谈收益

## 何时用
判定 / 门控 / 分类类调用 (其输出会改变主链走向) 与其它调用**共用**一个可复用缓存的执行面
(前缀缓存、KV 缓存、批次拼装、连接或会话池、共享推理进程) 时;
或已观察到「同一输入、判定时好时坏」。

## 核心判据
1. **判定路径不得依赖复用态**。同一输入在「命中复用」与「未命中复用」两种状态下必须给出同一结果;
   做不到就关掉该路径的复用 —— 宁可多算, 不可判不准。
2. **交错本身就是变量**。复用态由「上一次调用了什么」决定 ⇒ 要隔离的不是线程, 而是**调用序列**;
   单飞 / 串行化并不能消除它。
3. **判定层不可复现 ⇒ 主链预算不可复现**。判定翻转的代价通常落在别处 (多走一次主调用、多一次重试),
   「省下的开销」会被吃掉甚至反超。

## 做法 (顺序不可换)
1. 先钉死复用态 (决策路径显式关闭复用), 再谈收益。
2. 加可观测量: 该路径每次调用的**复用命中数**必须可见 (钉死后应恒为 0), 外加被使用计数 (证明确实走到该路径)。
3. 计数只在**真发起请求**时增加: 无设备 / 无执行面不得计数 (否则计数是空心的)。
4. 保留默认值 = 旧口径, 让非决策路径逐位零回归; 用一条**不变量检查**钉住「只有决策路径改了」。
5. 产品级判据用**同输入重复**: 同一输入重复 N 次, 判定必须恒定。
   不要拿两个不同配置的臂互相比较 —— 那是把配置差异与复用态差异混成一个变量。

## 两个强度的宣称必须分开
- 「输入不可复现」(同一输入生成不同序列) = 弱宣称, 容易证。
- 「结果不可复现」(判定结论真的翻转) = 强宣称, 需要直接的判定对比证据。
- 弱宣称**不能**自动升级为强宣称: 概率性翻转往往低频, 样本小就测不到 ⇒ 记「没测到」, 不记「没有」。

## 反模式
- 把「缓存开关」当纯性能项, 不管它落在哪条路径上。
- 用「重跑就好了」「偶发」结案 —— 概率性缺陷必须取确定性等价类。
- 只测正控 (钉死后可复现), 不测负控 (关复用前确实不可复现) ⇒ 无法排除「本来就恒等」。
- 用两个不同配置的臂做可复现性结论 (把配置差异误当成复用态差异)。
- 只报告「判定一致」而不报告「判定可用性」(未判定 / 降级也是结果的一种)。

## 检查表
- 判定路径的复用开关是显式的吗? 默认值在哪一边?
- 命中数可观测量有吗? 钉死后是否恒 0?
- 无设备负控下计数是否保持不动?
- 同输入重复 N 次的判定序列是否恒定? N 是多少?
- 结论属弱宣称还是强宣称? 边界写清楚了吗?
