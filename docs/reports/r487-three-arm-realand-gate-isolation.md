## 1. 因果链（为什么本轮这样设计）

1. R485 交付了「微问询形态分流预发送闸」但**真机臂未跑**（无 L3），R413 验收②③**无读数**。
2. R486 巡检发现：微闸在 `IndustrialAgentV2.cs` 的接线**两臂均无条件** ⇒ 用「闸开/闸关」两臂**结构上无法隔离**该闸。
3. 因此本轮改为**三臂同夹具同时窗**，并用**同臂参只换二进制**做真正的隔离：
   - `A0` = `/tmp/pub_r479v2/agenthost`（旧，sha256 `6a9b7aed22a22f48…`），臂参 = 门关 + relation_judge 开。
   - `Arole485` = `/tmp/pub_r485/agenthost`（新，sha256 `03c77d56e8c485af…`），**臂参与 A0 逐字同** ⇒ 二者差分 = **微闸单独效应**。
   - `R485` = 同新二进制 + `turn_gate=on` + `repeat_skip=on`（生产 R 形态）。
4. 上述三臂把「闸效应」与「配置效应」**拆开**：这正是本轮唯一能回答「闸是否真有增益」的设计。
5. 同时把上一轮遗留器具项（④多因标签 ⑦起手闸单一源 ⑥分档/语料清单）并入同一轮。

## 3. 归因（不是猜测，是可验算的算术）

- R485 每次上游调用的 prompt = **5,540** vs Arole485 **4,071**（+36%），
  而调用数只少 1（15→14）⇒ 总 token 上升。**闸没有引入额外调用，是「剩余调用带的上下文更长」**。
- 与 skip 类答复同时出现（6/12）⇒ 假设：`repeat_skip` 回放上一轮原文使对话状态含糊，
  后续主轮携带更长的纠正性上下文。**本轮未做因果分离实验**（`turn_gate` 与 `repeat_skip` 同时改动 ⇒ 混淆），
  故只报「相关」，不主张因果。
