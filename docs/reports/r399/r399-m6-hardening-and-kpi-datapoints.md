## 3. 加硬做了什么（可复核的三层）

1. **对抗用例机制**：`HARD_INPUTS`（`tasks.py:437`）为每个程序族钉死 3–5 条边界输入（全负数组、单元素、
   `10^9` 量级、并列/重复、满字母表…），生成期强制并入**隐藏集**（只进 hidden，不进 public）；每族对抗用例
   `< 3` 条即**拒发题**。⇒ 隐藏用例从 21 → 35（同种子 20260913），对抗性由生成器保证而非人工挑选。
2. **新陷阱族 `pair_closest_abs_sum`**：两数之和中绝对值最小者（并列取数值最小）——朴素写法在"同下标复用/并列
   取值"上翻车；参考解/校验解走两条不同实现（双重循环 vs `combinations` + 元组排序），不一致即拒发题。
3. **见证型数学题**（答案不唯一 ⇒ 判据改为**独立验证见证**）：
   - `witness_sqrt_mod`：求 `x² ≡ a (mod p)` 的任一 `x`；判定端**自己算** `x² mod p`（`grade.py:_verify_witness`），
     不比对任何标签，越界/错解 ⇒ `wrong_witness`。
   - `witness_min_counterexample`：给最小反例 `n` 使命题为假，判定端独立复核 `claim(n)=False` **且** `∀m<n claim(m)=True`
     （少一步"最小性"就判错）。

**读法（诚实）**：
- 加硬**确实生效**：作弊解用例级通过率 22.2%(v1) → **6.25%**(v2 全量批)，且**整题全对恒 0/3**；新陷阱族上
  作弊解 18.18% 用例级、整题 0/3（3 例分别是 3/11、2/11、1/11 用例命中公开样例）。
- 但 **agent 仍 100%**（35/35、36/36 全绿）⇒ 当前加硬强度对 agent **仍饱和**，没有区分度。这是本轮最重要的
  诚实结论：**"加硬"目前只加硬了"对作弊解的判别力"，还没加硬到"对 agent 有区分度"**。下轮必须换加硬维度
  （多步需落盘、故意缺信息需反问、证明链而非终值）。
- 见证型题的真机代价可见：同规模下 `witness_*` 3 题只花 8/9/6s，而新陷阱族每题 ~57–72s ⇒ **耗时/token 的分布
  信息本身是 KPI**（打点已记录 `tok/题`：全量批 4,396 vs 定向批 11,215）。
- `oracle` 0.7s 满分是**管线正控**（证明"题集可解、判定器不误杀"），不是能力证据。

## 4.1 本机 agent.rover 引擎读数（真 7B Q4_K_M, CPU, 预算 1500MB）

| 输入 tokens | 退出码 | 墙钟 | 峰值 RSS | 每 token 流式扫描 | 说明 |
|---|---|---|---|---|---|
| 1 | 0 | 15.87s | 2,384,605,184 B (2.22 GiB) | 4,023 MiB (×1.00 模型体积) | 冷启（`hits=0 misses=61`）：ATTN 4.69s + FFN 9.58s + LMHead 1.43s |
| 2 | 0 | 40.64s | 2,395,119,616 B (2.23 GiB) | 7,717.8 MiB (×1.92) | 每 token 增量 ≈ 24.8s |
| 4 | 0 | 107.06s | 1,943,183,360 B (1.81 GiB) | 15,107.4 MiB (×3.75) | 每 token 增量 ≈ 33.2s |
| 8 | 0 | 189.81s | 1,945,251,840 B (1.81 GiB) | 29,886.8 MiB (×7.42) | 每 token 增量 ≈ 20.7s |
| 64 | **124 (timeout 900)** | >900s | - | - | **未在 900s 内完成** ⇒ 与本表外推一致（64 × ~20s ≫ 900s） |

- **真机结论（本机 2 vCPU / 3.6 GiB、唯一 Vulkan 设备是 llvmpipe 软件 ICD）**：`agent.rover` 能**跑真 7B Q4_K_M**，
  但该档位下 **≈20–33 s/token**（每 token 都要**重新流式扫描 ≈1×模型体积的权重（4.0 GiB/token）**；驻留峰值仅 976 KiB ⇒ 预算 1500 MB
  装不下 4.2 GB 模型，权重全靠流式），**不可交互**，只适合离线/批量校验类用途。
- 引擎内部**跨实现对账**每条都带：`rope_check{impl_a=RopeTable impl_b=CpuKernels.Rope max_abs_diff=7.15e-7 verdict=match}`；
  `top-1=185` 与本仓既有 7B 读数一致（同模型同 token 复现）。
- 台账落盘：`data/probe/rover_engine_kpi.jsonl` + `data/probe/rover-forward-{1,2,4,8}tok.json`（`data/` 按仓库惯例不入 git ⇒
  报告内数值即版本化证据）。

- 唯一可用 Vulkan 设备是本机 llvmpipe（软件 ICD）⇒ 引擎读数**只反映 CPU + mmap 流式**，不代表真 GPU。
- **rover 目前不是解法后端**：CLI 只有 `forward <gguf> --tokens a,b,c`（token→logits + top-k），**没有
  tokenizer / 采样 / 解码环** ⇒ 无法"用 rover 生成程序解"。本轮把这条列为下一轮首要工程项（见 §7）。

## 5. 本轮抓出并修掉的 5 处真缺陷（含 2 处空心指标风险）

| # | 缺陷 | 性质 | 修法 | 固化负控 |
|---|---|---|---|---|
| 1 | 见证型族**从未被抽到**（`run_probe` 题池只取 `MATH_FAMILIES`） | 死代码：新功能"看起来已实现"实则不可达 | `run_probe.py:_family_pool` 把见证族并入数学池 | run_probe selftest "见证型族可达(反死代码)"：不给族池就失败 |
| 2 | 题集 sha **双口径**（生成路径 vs `--tasks` 复用路径算法不同） | KPI 失真：同批题集 sha 不同 ⇒ 误判"不可比" | 统一为规范化 JSON 哈希（`_canon_sha`） | 本轮实测 sha 一致 `b8e796a6d803918d` |
| 3 | KPI 时间窗锚点写反（`[ts, ts+elapsed]`，而 `run_probe` 的 `ts` 是**结束**时刻） | **口径假设错 ⇒ 空心 token 指标** | 改为 `[ts-elapsed, ts]` | selftest "锚点写反 ⇒ 读不到窗内调用"（必须 None） |
| 4 | 遥测时间戳 7 位小数（`...12.9531864Z`）解析失败被 `except: continue` **静默跳过** | 空心指标：token 全 None 却无任何报错 | `_parse_ts` 兼容 7 位小数；解析失败**抛错**（不再静默） | selftest "7 位小数可解析" + "非法时间戳必须抛错" |
| 5 | `grade_program` 无 `since` 参数 ⇒ "产物新鲜度"负控从未真正跑到 | 假绿：控件存在但立即 TypeError | 补 `since` 形参并透传到候选收集 | 该控件事后真跑到（判定器 25/25） |
| 6 | **R398 漏下的登记表回归**：`evidence_path` 写成 `';'` 多路径（校验器按**整串**当路径） | 校验判红；上一轮全量回归跑在登记表改写**之前** ⇒ 漏检 | `evidence_path` 改单一存在路径 + 独立 `evidence_report` 字段 | `VerificationFormTests` 6/6（改前单独跑=1 红，改后全绿） |

> 其中 #3/#4 是同一类错误的两例：**KPI 侧的口径假设错不会报错，只会把指标变成 None/0**。已按铁律补反向负控。

## 6. 三处"判定口径"变更（全部先立负控再改判据）

1. 见证型判定：**不比对标签**，改为独立复核见证语义（`wrong_witness` 单列失败模式）。
2. 计分口径：用例级通过率**只作参考**，KPI 新增 **整题全对**（`tasks_ok/n_tasks`）并列为一级指标。
3. 打点口径：`oracle`/`mutation` 这类**不走 LLM** 的运行 ⇒ token 记 `n/a`（**不记 0**），避免污染均值。
