## 1. 因果链

R464 门开臂已 −38.52%（Arole 21 调用/33,323 tok → B3B 8 调用/20,487 tok）。剩下的「不必要的 LLM API 请求」
有两处不在跳面里：

1. **`再讲一遍。`/`从头再说。`（t6/t9）** 是「把上一条答复原样重来」的真诉求，却仍走远端主调用。
   它们**不需要新内容** —— 上一条答复就在会话里 ⇒ 可直接回放，零远端、零本地生成。
2. **本地 3B 的全部代价落在用户可见路径**：Ack 轮在门里叫 r1（342 tok / 轮），且 3B 服务的启动+装载
   （实测 **26.0 s**）也发生在**首个**门控轮上。
3. **`FileLock.Release()` 的 `unlink` 竞态**：老持有者 B 仍持 inode I1 时删除路径，新来者 C 打开同名路径
   得到新 inode I2 ⇒ 两个持有者同时进临界区（历史观测 120 段得 119）。本轮给出**确定性机理复现**（§5）。

## 5. 锁纪律真修（候选③）

- 代码：`Release()` **不再 unlink 锁文件**（锁身份 = inode；存在性 ≠ 是否被持有）；`TryBreakStaleLock` →
  只读 `IsHolderDead`；`OccupantDetector.Describe` 优先 `/proc/locks` 的活持有者，锁文件内容过期时报
  「无持有者（上次持有者已退出）」。
- 机检：新 `G43_跨进程死持有者_内核放锁且不删文件`（python 子进程持 flock ⇒ 我方拒锁；子进程退出 ⇒ 内核放锁、我方接管、
  锁文件全程未被删）+ `G44_锁实现不得删除锁文件`（**剥注释**后结构门，防回归）。
- 确定性机理复现（`eval/rover/r465/mech_unlink_race.json`）：删锁文件 ⇒ `both_inside=true`（两个持有者）；
  不删 ⇒ `c_holds=false`（互斥成立）。
- 复跑：`ExecutorHardeningTests` 类 **10×13 全绿**（含 120 段并发追加）。
