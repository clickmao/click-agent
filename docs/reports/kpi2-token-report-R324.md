# KPI-2 Token 使用量长期监测报告 (R324 专项 — 用户质询: "是否持续观察统计了 token 使用量? 并长时间保持 KPI 监测?")

> 数据源: data/logs/eval/rounds/mass_*.json (429 个批测文件, mass_1 → mass_488)
> 统计口径: tok/case = (prompt_total + completion_total) / cases; 排除 cases<4 的 smoke/tiny 批
> 生成: R324 (2026-09-09), 全量重算非抽样

## 1. 结论先行

**持续观察 = 是, 但形式有缺口。** token 打点自 R129 (D3) 起每批必采 (prompt/completion/total 三分量),
KPI-2 曾有专项报告 (R238) 与 429 感知调度 (R242)、C07 瘦身计划等跟进动作; **但 R238 之后 80 轮
(R246→R322) 未再出过 token 专项统计** — 观察是连续的 (每批落盘), 分析是断续的 (专项驱动而非周期驱动)。
本轮补上机制: token 周报进入每 10 批 audit 制度 (与 compression audit 同节奏)。

  C07 -312 (瘦身生效) / C18 -98 / C03 -117 / C01 ±0

### 4.1 非 C19 漂移 +175 的定性 (诚实边界)
- C14/C13/C17 的上涨与**功能叠加期** (T2d FixMemory 注入 / 路由打点 / L1-L3 文案追加) 时间重合,
  但单批样本无法归因到单一功能 — 需要下一批 A/B (AGENTFRAMEWORK 自由变量逐个开关) 才能定论。
- C14 历史 (196 个数据点) 抽样: 1823-2361 tok 波动带, 本期 2765 略出带顶 — **登记观察, 不定论**。
- C07 -312 证明瘦身可持续; 漂移案 (C14/C13) 列入下轮候选靶点。

## 5. 监测机制 (本轮补齐的常态化)

- **每 10 批 token 周报** (与 compression audit 同节奏): run_round 已有全量数据, 补 summarize 汇总脚本
  (eval/token_report.py, R324) — 输出 era 均值/口径细分/top 消耗案/周环比。
- **口径变更登记制度**: quick 扩容 (11→12→13) / 新口径 (XL/route-3) 必须在当轮报告登记
  可比性断点 (本轮已补: §3 表)。
- **新功能的 token 预算制**: T2 SelfCritic 预算 ≤8% (plan 已立); 后续新源 (Guardrail 注入) 同制。
