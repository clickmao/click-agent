## 4. 上游契约面退化（本轮主障碍，定因）

- 逐窗机检（本轮新增器具，承接 R551 候选③）：按 adapter `side-agent-*.json` 的 **mtime 时间片**统计该窗 `response.text` 的 JSON 可解析率，`>0.25 ⇒ void_upstream`；**判据有牙自检**（`void_gate_selfcheck.json`）：坏样本判红 ∧ 好样本判绿 ∧ 恰 25% 不触发 ⇒ `has_teeth=True`。
- 实测：**15/24 窗触发**；与 `rc=4` 的 15 窗**高度重合**。逐条文本级抽查（b1 dump）：退化形态 = ①模型输出**JSON 后跟续写的第二个对象**（`Expecting property name enclosed in double quotes`）②模型**复读指令**（60 字符 / 32 completion tokens 的退化回复）。**不是截断**（`finish_reason=stop`，usage 正常）⇒ 属**契约面不合格**，R1 的 fail-closed（rc=4）按设计拒绝继续。
- 判据**过宽**（按纪律照原样判定、修正形态只作 `checks_posthoc`）：`rc=4` 与「退化率 >0.25」都**不等于「窗无信息量」**——实测反例：`rc=4` 的 w43=45/58、w51=55/58、w53=56/58、w57=58/58；退化率 0.333 的 w38/w48/w55 均 **58/58**。⇒ 下一轮改写为「**仅『无产物/无用例可判分』判 VOID**；`rc` 与退化率降为 hygiene 读数」，判据与阈值改动在 R553 预注册中生效，**本轮不改**。
