### 2.3 本地 r1 成本与口径（R443 真值化，本轮 M20，同档案三计算）
| 口径 | M20 中簇 | 说明 |
|---|---|---|
| `D_remote`（用户 API token） | **46.18%** | 桩侧外部真值 |
| `+ 本地(R442 字符/2 折算)` | 33.25% | 复现 R442 的 33.26 ✓ |
| `+ 本地(tokenizer 真值)` | **25.32%** | llama-server 上报 `tokens_evaluated/prompt_n/gen` |

逐分量折算误差: 门 prompt **1.398×**、门生成 1.267×、判官 prompt **1.496×**、本地合计 **1.613×**（7919.5 → 12775）。
⇒ 轮均本地成本 c = **638.8 tok/轮**（真值；折算口径为 396），单跳省 s ≈ 4040 tok，转正闭式 `k/N > c/s` = **15.81%**。

**由 P1+P2 得到的完整判据（取代单标量「≥30%」）**:
* **API 口径**（用户计费，主张的本体）: `k/N ≥ 25%` 时实测 32.24%（V2b）与 46.18%（M20）；`k/N` 低时达不到 30%（W8 13.77%、W20 3.20%），零可跳净亏 −2.40%。
* **含本地真值口径**（不看漏成本）: M20 25.32%（<30%），低占比格转负 —— 根因是门在**每个非机械轮**都付固定成本 c，与 k/N 无关。
* ⇒ 「≥30%」不是普适真理，而是 **(口径 × 任务长度档) 的函数**；机制级解法 = 压低 c（门前置筛选），见 §6.3。

### 2.4 「被跳轮不回放」的单变量实测（R443 消融臂）

### 2.5 转正条件（闭式，R442 建立、R443 复验为真值口径）
`降幅 > 0 ⟺ k/N > c_per_turn / s_per_skip`
⇒ 「≥30%」不是 30% 附近的阈值问题，而是**可跳轮占比 × 轮均成本占比**的乘积问题。

## 3. 优缺点评测

**优点（要保住）**
1. 判据预注册 + 负控 + 复现闸（D1–D7）⇒ 指标不是空心的；每轮都有外部真值（桩侧 calls）与产品遥测**双源**。
2. 反号发现被保留并升级为口径并列（R442）⇒ 「方向断言」可被证伪，不是自我确认。
3. 轮次成本可控（器具 + 跑测 + 判定 + 台账 ≈ 1 小时/轮），主循环可持续。
4. 每一次失败都抽象成语言无关的通用工程教训（skill），复用面在扩大。

**缺点（要修）**
1. 终点不可见：没有一页能回答「还差几格」。
2. 器具层无自身验收：器具缺陷只能靠下一轮踩到才发现。
3. 混淆量未入册：路径后缀、NS、并发写者都是「事后才发现」。
4. 口径未强制：同一 KPI 在不同轮里用不同分母（跨网格代理两次复发）。
5. 审计面分裂：数据/断言/叙事三处，人工对不齐。

## 4. 机制提案：四层契约（可审可控 + 终点可见）

### L1 「验收矩阵」= 终点定义（机械可判）
* 行 = 任务长度档: `单跳 1/8`、`单跳 1/20`、`短 1/4`、`中 7/20`、`长 ≥12/20`、`零可跳(负控)`、`无设备(负控)`。
* 列 = (口径 `D_remote` | `D_remote+local_truth`) × (质量 `逐位/正确率`) × (形态 `AOT/0 IL`)。
* 判据（预注册，任何一轮不得事后收窄）:
  * **零净亏硬约束**: 每一格 `D ≥ 0`（含本地真值口径）。
  * **长档达标**: 长档 `D_remote ≥ 30%` **且** `D_remote+local_truth ≥ 25%`（数值待用户钦定）。
  * **质量格全绿**: 非跳轮逐位相同 ∧ `fn=fp=0` ∧ `acc=1.0` ∧ 归属 `ok`。
  * **形态格全绿**: AOT 0 IL 警告 ∧ V0 形态闸 PASS ∧ 无设备负控仍为负（说明收益确实来自门）。
* **终点 = 全格绿**；未测的格显式记 `未测到`（≠ 通过，≠ 失败）。
* 契约须写明**短档不承诺 30%**：门在每轮都付固定成本 `c`（≈ 390 tok 真值待定），`k/N` 小则必然为负 —— 这是机制的数学必然，写进契约而不是当 bug。

### L2 「器具验收面」= instrument registry
* 每个器具（predict / analyze / settle / stub / drive）登记: `id`、版本、`self_test_cmd`、负控（必须判红的样例）、输入指纹（输入文件 sha256）、口径四元组 `{分子范围, 分母来源, 本地入账, 截断规则}`。
* **机器闸**: 未过 self-test 的器具读数不得进台账（pre-commit 校验 registry 的 `self_test_cmd` 退出码）。

### L3 「单一审计面」= one ledger, generated
* 唯一权威 = `docs/verification-registry.json`（断言）+ `eval/capability/kpi.jsonl`（数据）。
* `improvements.md` / `status.json` **由生成器派生**（禁手写），`status.json` 一页给出: 矩阵格状态、未决挂账、下轮候选（人只看这一页）。
* `capability_cycle.py status` 必须覆盖**全部**历史行（含 R419–R443），否则视为台账红。

### L4 「写者仲裁」= 同 worktree 单写者
* 轮号取 `max+1` 前复跑占用序列（已有铁律）；新增: 写者心跳文件 `.git/WRITER_HEARTBEAT`（每轮写点更新）。
* pre-commit hook: 心跳 mtime < 10 分钟 且 不是本进程 ⇒ 拒绝提交（提示「对侧活跃，只写证据面」）。
* 目录约定: 同轮号允许两个写者时，一侧只写 `eval/**`（证据面），产品/台账面单写者。

## 5. 模块完成契约（Click-Agent 真假判别模块）
* 模块边界 = `r1 门判 + role 额外数据挂载 + 关系判官端口`（`LocalGenerationPort` / `ModelQueueRouter` / `IndustrialAgentV2` 三处）。
* **完成 = L1 矩阵全绿 ∧ L2 器具全过 ∧ L3 单源一致 ∧ 三次独立通道互证**（① 真机档案 ② 离线 tokenizer 真值重建 ③ 桩侧外部真值）。
* 明确排除: 真实计费/时延口径、跨网格代理外推、矩阵外的长度档推断。
