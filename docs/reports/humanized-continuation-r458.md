状态: 已实施 (R458)

**诚实边界**
1. **调用数 17 > R457 15（+13%）、> codex 13**：本轮差异来自模型自身多用工具（`run_command` 3 次跑 python 校验、读回校验），非承接机制成本；承接块 1 次 ≈ 288 字符（只进 T5 一轮）。同输入跨轮调用数有波动（R455 7 / R456 9 / R457 15 / R458 17），单轮读数不作趋势结论。
2. **run1（修正前）实测缺陷已修**：判定面只看 flags ⇒ 把「当前目录下一共有几个 .py 文件？」（门置信 0.8、门未发问）也判成承接轮，注入了块，模型还把它写进回复（「注：会话承接状态里只列了 c.py、d.py…」）。修法 = 判定与门**同一判据**（flags 弱 **且** 置信度 < 0.60），并补上「共 11 项, 只列最近 8 项」的如实标注。run2 承接块只触发 1 次（T5）✅。
3. 构建期曾出现**假绿**：`/tmp/r458_build_test.sh` 无 `set -e` + `--no-build` ⇒ 构建失败时跑陈旧二进制仍报 13/13。已加 `set -euo pipefail`；修正后 15/15（含新增负控）。
4. 缓存命中率仍低于 97% 红线（本跑 90.4%，`cache_redline_violation` 遥测逐轮给出），与 R456b 结论一致：前缀受会话增量支配，本跑不跨轮比。
5. 判分口径：产物 = 磁盘逐字节归一比较（不采信回复文本）；T5/T6 文本 = 落盘 turns 原文；承接块落地 = 遥测 + 实发请求回显 + 引用名与磁盘比对（零编造）。

## 3. 机制（禁关键字/提示词补丁）

| 面 | 实现 | 位置 |
|---|---|---|
| 判定面 | 复用意图层既有分支（弱意图/过短 **且** 置信 < 0.60，且无缺参数/指代不明/疑似省略依赖） | `ContinuationBrief.IsContinuationTurn` |
| 接地面 | 扫描工作区**真实**产物（名=首行 (字节)，噪声目录排除，有界扫描，截断如实标注）→ 本轮注入 `[承接状态 v1]`，要求「先逐项承接再反问」 | `ContinuationBrief.ScanArtifacts/BuildBlock` |
| 问句面 | 门的承接问句不再是固定菜单，改为**由真实产物接地**（无产物则明确说「还没有」且列不出文件名） | `EvidenceGate`（`facts` 注入） |
| 收口面 | fail-closed：承接轮回复若既无问句又不含任何真实产物名 ⇒ 链自身用同一批事实组装反问 | `ContinuationBrief.NeedsFallback/ComposeFallback` + `IndustrialAgentV2` |
| 告知面 | 「答复落不到槽位」的内部判定改一句人话，内部术语/理由只进遥测 | `PlanResumeService.HumanizeVoidNotice` |

块只进本轮 user 内容 ⇒ 静态前缀/缓存前缀字节不变（非承接轮零增量）；事实全部来自磁盘扫描 ⇒ 零编造可机检。
