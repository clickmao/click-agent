- **J4 达成(记录列)**: completion 按类分解 = 末端正文 A / 工具调用骨架 C / 逐步叙述 B。F2 三窗: `A=1040/1226/1209`, `B=2420/6624/5422`, `C=13502/140966/22702`(C 含 codex 臂 w2 的 476 次抖动), 天花板算式乐观界 headroom `79.2% / 81.8% / 67.8%`, 叙述占比 `14.3% / 4.5% / 18.5%`。**结论: 支配项是 C(每次工具调用的载荷), 不是叙述 ⇒ 降 completion 的唯一杠杆仍是「降步数/合批」**(与 R413 期结论同向)。
- **J5 达成**: F1 本侧 **58/58 × 3 窗**。

## 5. 诚实边界 (没测到什么就说什么)

1. **本轮不宣称 token 降幅**: 闸 rc=1。F2 上 A1-on 相对基线在 w1/w2 省调用(↓33%、↓29%)但在 **w3 反超 4.1×**; F1 上三窗里两窗显著更贵。3 窗极差极大 ⇒ 按「单窗读数=噪声」口径, **「role 门控 ⇒ 调用/ token ↓≥30%」在本轮不可复现**。
2. **外部真值本身不稳**: codex 同题 F2 三窗 calls `18 / 476 / 61`、w2 单臂耗时 **896.6s**(w1 仅 42.8s)且 128.6k new_prompt;w3 漏判 1 例(`\u0007` 码点 <0x20 必须 `ERR`, 它输出原始 BEL)——**该例本侧 A1-on 判对**。codex 的 w2 抖动含其自身工具策略拒绝(`rm -f` 被拒)导致的重试, 属真值侧环境伪影, 不能当模型能力直接读。
3. **F2 判分口径**: `run_cases_r529.py` 的用例名 `mod#i` 里 `i` 是**全局 0 基序号**(`jsonmini#27` ≠ 第 27 例), 报告按内容引用, 不改器具(避免中途改版)。
4. **天花板是乐观界**: `ceil` 用「观测到的最小单次纯工具调用 completion」当每步下界, 因此 headroom 偏高, 不等于可达目标。
5. **w2 基线臂 55/58 的 3 例失败未逐个定因**(`wythoff#44/#45/#49`), 只记读数与 rc。
