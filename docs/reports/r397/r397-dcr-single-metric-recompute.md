# R397 — DCR 单一口径重算（FAVA 语义）+ 口径敏感度实测量化

**日期**: 2026-09-13 · **状态**: 完成（口径定稿）· **前置**: R396 附带解锁的 FAVA 正文取证（`docs/reports/dcr/dcr-align-fava-source-2026-09-13.md`）

## 0. 一句话结论

按 FAVA 正文口径把 DCR 从「双口径并列」收敛为**单一口径**（`DCR = (TP+TN)/(TP+TN+FP+FN)`，**无弃权项**，非 `Proceed` 一律 fail-closed 记 block）：

| | 值 |
|---|---|
| **DCR（单一口径，fail-closed）** | **145/145 = 100.00%** |
| 混淆矩阵 | TP=94 · TN=51 · **FP=0** · **FN=0** |
| 独立实现（C# 装配报表）交叉对账 | **4/4 恒等式通过** |
| **同一数据的口径敏感度跨度** | **30.34 pp**（69.66% ↔ 100.00%） |

⇒ **"±5pp 裕度"此前不成立的真正原因是口径本身，不是测量噪声**：口径未钉死时，同一份数据、同一批裁决可读出 69.66% 与 100.00% 两个数，跨度 30.34pp，**远大于 ±5pp**。口径现已钉死，但**"达到 90.5%±5pp"仍不构成可断言结论**（理由见 §6）。

## 1. 为什么必须重算：口径分裂的三个数

同一份 `eval/dcr/dcr_cases.jsonl`（145 条）× `eval/dcr/assembly_out.jsonl`（145 条裁决），此前存在三种读法：

| 口径 | 定义 | 结果 |
|---|---|---|
| 旧口径（本仓原报表） | **四类处置一致率**：`实际处置 == 期望处置`（Proceed/Violation/Abstained/Malformed） | 145/145 = 100.00% |
| FAVA 口径（本轮定稿） | **二元矩阵 + fail-closed**：非 `Proceed` 一律记 block | 145/145 = 100.00% |
| 「保守」口径 | 弃权/畸形按**放行**，只有 `Violation` 记 block | 101/145 = **69.66%** |

- 旧口径**不是 DCR**：它是四类一致率，分母含弃权/畸形两类，与 FAVA 的二元矩阵不是同一个量（数值巧合相同）。
- 「保守 69.66%」被误读为「能力不足」过：它其实等于**可决断集上限**（19 `out_of_fragment` + 25 `malformed` = 44 条设计上不该决断 ⇒ 101/145 是上限）—— **口径设定问题，不是能力问题**（R388 已定性）。
- 本轮把这三种读法**在同一脚本内一次算出并显式标注**，其中一个为权威口径，另两个降为敏感度/对照行（禁止再并列汇报）。

## 2. 口径定义（逐条可审计）

| 侧 | 数据字段 | 规则 |
|---|---|---|
| 期望侧 | `dcr_cases.jsonl :: expected_disposition` | `Proceed` ⇒ **allow**；其余（`Violation`/`Abstained`/`Malformed`）⇒ **block** |
| 实际侧 | `assembly_out.jsonl :: disposition` | `Proceed` ⇒ **allow**；其余 ⇒ **block**（**fail-closed**：弃权与畸形都算阻断） |

数据锚（实际观测，非假设）：`Proceed 51 = entail 33 + absent 18`；`Violation 50 = refute 30 + vacuous 20`；`Abstained 19 = out_of_fragment`；`Malformed 25`。
`absent ⇒ Proceed` 与 FormalAssertionContract 铁律①（**缺失 ≠ 错误**）一致 ⇒ 期望侧不存在"该放却被算 block"的构造性偏置。
标签来源：**z3 独立推导 83 条** / **构造定义 62 条**。

|---|---|---|
| **期望 block** | **TP = 94** | FN = 0 |
| **期望 allow** | FP = 0 | **TN = 51** |

`DCR = (94+51)/(94+51+0+0) = 1.0000`

| category | N | DCR | 期望处置 | 实际处置 |
|---|---|---|---|---|
| entail | 33 | 1.0000 | Proceed | Proceed |
| absent | 18 | 1.0000 | Proceed | Proceed |
| refute | 30 | 1.0000 | Violation | Violation |
| vacuous | 20 | 1.0000 | Violation | Violation |
| out_of_fragment | 19 | 1.0000 | Abstained | Abstained |
| malformed | 25 | 1.0000 | Malformed | Malformed |

### 3.3 跨实现交叉对账（独立实现 = C# 侧报表，非本脚本推导）

`eval/dcr/dcr_align.py` 只从 C# 报表（`scripts/kpi_dcr.py` 产出）**独立计数**里抽数对账，**4/4 恒等式通过**：

| 恒等式 | 结果 |
|---|---|
| `N == 145` | ✓ |
| `Proceed 计数 == TN 侧 == 51` | ✓ |
| `可决断集 == Proceed + Violation == 101` | ✓ |
| `弃权 + 畸形 == N − 可决断 == 44` | ✓ |

（对账用独立实现，符合"跨实现对账必须换独立解析实现"铁律；本脚本不 import C# 侧任何代码。）

## 5. 负控（7/7，含解析 oracle）

`python3 eval/dcr/dcr_align.py --selftest` —— **7/7 通过**：

| # | 负控 | 判据 |
|---|---|---|
| 1 | 混淆矩阵计数 | 合成样本 `(tp,tn,fp,fn) == (2,1,1,1)` |
| 2 | DCR 算术 | 合成样本 DCR = 3/5 = 0.6 |
| 3 | **洗牌负控 vs 解析 oracle** | 400 次随机独立标签的 DCR 均值 ≈ 解析值 `(51²+94²)/145² = 0.5440`（±0.05） |
| 4 | 单点翻转分辨率 | Δ == 1/145（恰好一格） |
| 5 | 常量分类器下界 | 全 allow ⇒ 51/145 = 0.3517 |
| 6 | 常量分类器下界 | 全 block ⇒ 94/145 = 0.6483 |
| 7 | 敏感度方向 | 弃权折算为放行必须**降** DCR |

第 5/6 条同时给出**判别力基线**：常量 block 策略已得 64.83%、常量 allow 得 35.17% ⇒ 100% 的信息量全部落在"能同时拿到 51 个 allow 与 94 个 block"上。

**自捕的两个缺陷（本轮，已修）**：① 自检计数写死 `6` 而实际 7 条 ⇒ 恒 rc=1（"闸门自己恒假"的镜像缺陷）；② 敏感度表混用原始处置与二元值 ⇒ `bad pair 'allow'/'Proceed'` 崩。两者都是被 `--selftest` / 真跑自己抓出来的。

## 6. 诚实边界（不可省）

1. **题集饱和 ⇒ 该数字对"能力提升"零灵敏度**：145/145、FP=FN=0，任何能力改进都无法在 100% 上体现。**下轮必须加硬**（长轨迹 / 语义降层类用例），否则 DCR 是"无区分度的满分"。
2. **与 FAVA 的 90.5% 不可比**：FAVA 的 90.5% 是 **801 例 aggregate 二元矩阵**、跨三个基准（OpenAgentSafety/OctoBench/ActPlane），且**包含自然语言 → 权限图/IR 的降层损失**；本仓是 145 例、受限算术片段、零 LLM 调用、降层不参与 ⇒ **不同分母、不同构成、不同失败模式**。故 **"DCR=100%"不构成"达到 90.5%±5pp"**。
3. **标签独立性有限**：62/145 期望标签为**构造定义**（非经验结论，已明示）；83/145 由 z3 独立推导，但 z3 与形式化内核**共享整数语义** ⇒ 二者的共同盲区不可自发现（独立审计器 `audit_decisions.py` 同属该盲区）。
4. **口径是工程裁定，不是论文原值**：FAVA 正文只说"不确定 fail-closed 记 block"，本轮把它落成 `非 Proceed ⇒ block` 的显式映射；映射表本身可审、可改，改则数字随之变（见 §4）。
5. 本机无真 GPU 等无关边界不影响本轮（本轮零 C# 改动）。
