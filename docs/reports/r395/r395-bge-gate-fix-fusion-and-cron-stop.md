## 2. 闸门修复（两个真缺陷，用户点名"修完闸门"）

| 缺陷 | 原状（取证） | 现装 |
|---|---|---|
| **G3 口径分叉** | 文档 §5 写「延迟 ≤15% ∧ RSS ≤15%」；代码 `train_adapter.py:177` 判「算力占比 <5%」——**两者不是同一件事**，且代码侧从未测量任何真实耗时 | 三子判据同阈值实装：**算力 ≤5% ∧ 延迟 ≤15% ∧ 内存 ≤15%**。延迟分母 = **绕缓存实测真前向** `ms/向量`；内存为**静态代理**（适配器对象字节 / 模型文件字节），口径在文档中明写 |
| **G5 空心闸门** | 代码即 `g["G5"] = True` —— 确定性**从未被检查**，却每轮都在报告里记"G5 通过" | 真跑 **4 条逐位判据**：① encode 重复性 ② 顺序无关性 ③ 秩可复现（与择优时记录的秩**逐位比较**） ④ 扰动负控（证明判定器有判别力） |

**防漂移机检**：`eval/bge/test_gates.py`（新）—— 文档 §5 的 G3 行必须与代码常量 `MAC_BUDGET/LAT_BUDGET/MEM_BUDGET` 同阈值、同语义（算力/延迟/内存三词都必须在），并覆盖 G3 三子判据的**过/不过两侧**构造样例。

**修后真机证据（v11，同一 1112 对数据、同算法、仅闸门代码变）**

```
G1 true  (r@10 0.6667 ≥ 0.6583 门槛 —— 该线首次过 G1)
G2 true  (r@1 0.3167 未倒退)
G3 true  {mac_ratio 0.00137, fwd_ms_per_vec 96.304, lat_ratio 0.0109, mem_ratio 0.00566}
G4 false (过拟合 0.8273 − 0.6667 = 16.06pt > 15pt)          ⇒ rolled_back
G5 true  {encode_repeat ✓, order_invariant ✓, ranks_reproducible ✓, negative_control ✓}
指标  r@1 0.3167 / r@10 0.6667 / mrr@10 0.4183 —— **与 v10（旧闸门）逐位相同**
```

**A/B 的意义**：改判定**不改变结论**，只把"结论"从名义变成实测。v11 小报已自动带 G3/G5 明细（模板同步改）。

## 4. 融合线实测（`eval/bge/fusion.py`，脚本自写报告 `docs/reports/bge/fusion-2026-09-13.md`）

**口径冻结**：1299 块语料 + 120 查询（1 条 = 0.83pt）；三路检索器 = 词法（字符二元组 Jaccard）+ dense-small（`bge-q8`）+ dense-base（`/tmp/models/bge-base-zh-v1.5-q8.gguf`）。**RRF**：`score(d) = Σ_r w_r/(k0 + rank_r(d) + 1)`，只用**秩**（Cos 与 Jaccard 尺度不可比，分数归一化不在口径内）。

| 单路 | r@1 | r@10 | r@20 | mrr@10 | miss@50 |
|---|---|---|---|---|---|
| 词法 | 0.4417 | 0.7500 | 0.7667 | 0.5571 | 0.2000 |
| dense-small | 0.3083 | 0.6333 | 0.7000 | 0.4150 | 0.2333 |
| dense-base | 0.4417 | 0.7417 | 0.8000 | 0.5430 | 0.1083 |

| 融合 | r@1 | r@10 | r@20 | mrr@10 | miss@50 | union@10（参考） |
|---|---|---|---|---|---|---|
| **lexical+base, k0=10, 1:1（网格最优）** | **0.5333** | **0.8500** | 0.8750 | **0.6439** | 0.0917 | 0.8667 |
| lexical+base, k0=60, 1:1（**RRF 默认参数**，推荐读数） | 0.5333 | 0.8000 | 0.8250 | 0.6248 | 0.1083 | 0.8667 |
| lexical+small, k0=20, 1:1 | 0.4750 | 0.7917 | 0.8083 | 0.5799 | 0.1667 | 0.7917 |
| small+base, k0=10, dense-heavy | 0.4083 | 0.7917 | 0.8417 | 0.5357 | 0.0917 | 0.8167 |
| lexical+small+base, k0=20, 1:1 | 0.4833 | 0.8333 | 0.8750 | 0.6077 | 0.1167 | 0.8667 |

- **收益来源是"词法 × base"的互补**（+9.83pt）；换成 dense-small 只 +3.33pt；三路混合（0.8333）**不优于**两路（0.8500）⇒ 与小模型融合无增量。
- **选择性偏差披露**：0.8500 是 36 格网格在**同一 120 条评测集**上选优的结果；RRF 默认 `k0=60` 读数为 **0.8000**（仍 +5pt over 词法）。两个读数并列，主张取保守值 **+5pt ~ +9.8pt**。

**判据（全部真跑）**

| 判据 | 结果 |
|---|---|
| ① 同口径对账 | 自建排秩的金标准秩向量与仓库冻结实现 `L.lexical_baseline` **逐位一致**；dense 两路与跨运行冻结节账（small 0.6333 / base 0.7417）一致；词法 r@1 0.4417 / r@10 0.7500 / mrr@10 0.5571 复现 |
| ② 秩级不变量 + 负控 | 严格单调无饱和变换（x³ / x+3 / 5x）后融合**逐位不变**；负控：随机改 5% 分数 ⇒ **120/120** 条排秩改变（判据有判别力） |
| ③ 秩单调性 fuzz | 300 例：金标准在某一路名义上移一名 ⇒ 融合秩**不变差** |
| ④ 负控 | 随机路融合 r@10 = 0.375（远低于词法 0.7500）；标签洗牌后 r@10 = **0.0083** ≈ 随机水平 10/1299 = 0.0077 |

**两条伪不变量（明确不采用，见教训 10.9）**：`融合 ≥ 单路最优` 与 `融合 ≤ union@k` 均**数学为假**。实测：union@10 = 0.8667 只是"至少一路命中"的集合口径，RRF 可达 0.8500（差 1.67pt = 2 条查询）；融合也可能低于单路最优（dense-heavy 变体 r@10 0.75 即等于词法）。

## 6. 诚实边界

1. **评测集只有 120 条**（1 条 = 0.83pt），+5pt/+9.83pt 的绝对量仍属小样本结论；`dense-base` 路径依赖 110 MB 模型文件在盘（产品侧需评估体积）。
2. 融合的**产品侧端口尚未实现**（本机仅脚本级实测）——下一步应做成与 R393 同规格的**可替换执行面端口**（构造注入 / 缺省 CPU / 被使用计数 / 无设备负控）。
3. G3 的"内存 ≤15%"是**静态代理**（对象字节/模型文件字节），非进程 RSS 实测；已在文档与代码注释中明写，不得表述为"RSS 实测"。
4. `lexical` 一路在中文语料上依赖字符二元组的天真实现（`bge_lib.lexical_baseline`），未做分词/同义扩展；换语料需重标定。
5. 训练线的**唯一翻盘前提**仍是"接真实检索标注"（现训练对为 LLM 合成），但那是**领域微调**而非底座训练，且本机（3.6 GiB）不支持 T2/T3。
