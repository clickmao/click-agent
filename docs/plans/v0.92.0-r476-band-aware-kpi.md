# v0.92.0 · R476 — 红线判定**分档化**：分档上限 + 达成轮占比 + 分通道

状态: 已收口（R476）｜前轮：R475（`3d49bef`，未 push）｜判据来源：用户钦定「一轮任务总 token ↓≥30%（按任务长度分档）」+ 97% 红线（R393）

## 1. 问题（承 R469/R470 两条已收口结论）

- R469（`199afbf`）：`命中率 = 1 − 新/前缀`，其中**用户轮长度不可压**（压了就是改用户输入）⇒ 单值 97% 对长档**结构性不可达**，须按档给「理论上限」。真实 400 轮分档（0-30 字 130 / 31-93 字 68 / 94-200 字 64 / 201+ 字 138）；可达 97% 的轮 = 49.5%，**结构性不可达 50.5%**。
- R470（`5540eb4`）：真实遥测 43 条远端调用 `effective_hit_rate` 全为 −1（同会话前驱 0）⇒ 首要 KPI 对真实流量 100% 不适用；供应商侧 32/43 命中（饱和 2,048~2,304）⇒ 收益客观存在却无度量。
- 结论：继续用「单值 0.97 是否达标」当判据，等于用一把**不可能量到的尺**判红每一轮长任务 ⇒ 必须把判据换成「**分档目标 = min(红线, 该轮结构上限)** + **达成轮占比** + **分通道**」，且**红线 0.97 一字不动**（改的是目标的分档，不是红线本身）。

## 2. 设计（产品面，只增不改）

### 2.1 `src/agent.modelqueue/PromptCacheRedline.cs`（分档判定器，AOT 安全纯函数）

| 成员 | 语义 |
|---|---|
| `TurnOverheadTokens = 21` | 承接开销上界（R469 实测 15~21 字符 ⇒ 取上界） |
| `TurnBands` / `BandOf(u)` | 4 档：0-30 / 31-93 / 94-200 / 201+（与 R469 夹具档界逐值相同）；`u<0` ⇒ −1（未知，禁猜） |
| `CeilingFor(prefix,u)` | 模型上限 `prefix/(prefix+u+21)`（= R469 夹具口径，三方一致） |
| `CeilingFromGrowth(cacheable,growth)` | 实测上限 `cacheable/(cacheable+growth)`，`growth = prompt − cacheable` 由实发遥测取得 |
| `TargetFor(prefix,u)` | `min(0.97, CeilingFor)` —— **短档目标=红线，长档目标=结构上限** |
| `ToleranceFor(prefix)` | 1 个缓存单元（64 tok）对齐损耗折成命中率 |
| `JudgeBand(...)` | 5 态：`not_applicable`（首轮/冷启动，无前驱）/ `unreported`（rate=−1）/ `at_target` / `below_ceiling`（**上限内还有空间 ⇒ 可修，判红**）/ `below_target`（短档未达红线，判红） |
| `JudgeByGrowth(...)` | 产品路径：档与上限由**实测 growth** 派生，`band_source=growth_upper_bound`（growth ≥ 用户轮，明示上偏代理，禁当实测档） |
| `BandFields(...)` | 遥测 7 字段：`cache_band` / `cache_band_source` / `cache_ceiling` / `cache_target` / `cache_margin` / `cache_band_growth` / `cache_band_verdict` |

### 2.2 `src/agent.modelqueue/ModelQueueRouter.cs`（遥测，3 处 emit）

`llm_call` 三处（主调用 / retry / failover）**追加**上表 7 字段 ⇒ 分档判定可离线复算；**既有键一个不动**（R469/R470 通道键保留，`cache_redline_violation` 语义不动）。

### 2.3 `scripts/kpi_cache_hit.py`（离线聚合 + 常数机检）

- `check_source_parity()`：py 侧（红线 0.97 / 承接 21 / 单元 64 / 档界）与**产品源码逐值**比对，差异非空 ⇒ **fail-closed**（`--no-parity` 仅自检用）。
- `aggregate_bands()`：按档 + 按通道给 `judged / at_target / below_ceiling / below_target / unreported / at_target_rate / ceiling_median / verdict`；`unreported` **不进分子分母**；不适用（首轮）单列。
- 判红条件 = 存在 `below_ceiling`（结构空间内没达上限）或 `below_target`（短档未达红线）轮；判定轮=0 ⇒ 只报计数，**禁渲染成达标**。

### 2.4 计价面 fail-closed（`eval/rover/r475/join_usage_truth.py`）

`pricing_block()` 两态：`unreported`（无价格表，`cost_cny=None`，`hit_discount_known=False`）/ `from_table`（显式 `--price <json>`）。`pricing_violations()` 抓「status≠from_table 却给 cost=0」的**伪造 0** ⇒ 判红。

## 3. 约束

- 红线 `PromptCacheRedline.Threshold = 0.97` **一字未动**；`Violated(...)` 既有语义与 `cache_redline_violation` 遥测不变（R393 至今的越线记录不遗忘）。
- 分档判定的「档」在真实遥测里只能由 `growth` 上偏代理派生（产品路径不持有用户轮 token 数）⇒ 字段名与笔记必须显式标注 `growth_upper_bound`，禁冒充实测档。
- 档只能来自**实发**遥测或已入库夹具；缺字段 ⇒ `unreported`/`unknown`，禁按 0。
- 不改用户输入、不改解码约束、不新增关键词表。

## 6. 待确认

- 档界（0-30/31-93/94-200/201+）源自 R468 语料 400 轮样本的**分位**，非业务定义；若用户有业务分档口径，应以业务口径替换。
- 目标函数 `min(红线, 上限)` 假设「达上限即无结构空间」；若某档上限本身可被压低（例如前缀去重），该档目标应随之上移 —— 属后续轮的机制面工作。
