## 3. 设计（三面，全部走可替换执行面端口）
### 3.1 声明面（tools[]）
- 由**能力注册表**派生 `tools[]`（只读类：读文件/列目录/检索；写类：写文件；执行类：跑脚本）。
- 请求体新增 `tools` + `tool_choice:"auto"`（`ModelQueueRouter.SerializeChatRequest` 走手写 `Utf8JsonWriter`，零反射）。
- 工具 schema 由 STJ Source Generator 或手写 JSON 常量生成（AOT 安全）。

### 3.2 解析面（tool_calls → 执行）
- 解析远端应答的 `tool_calls`（手写 JSON 读取，零反射），映射到既有执行面：
  - `read_file` / `list_dir` → 文件端口（有界读取，默认上限如 64 KiB）
  - `write_file` → 写端口（**须在允许根下**，路径规范化 + 越界拒绝）
  - `run_script` → `SkillScriptRunner`（复用超时/杀树/输出有界）
- **零关键字路由**：执行与否只由结构化 `tool_calls` 决定。

### 3.3 回灌面（tool result → 再推理）
- 执行结果作为 `role:"tool"` 消息回灌（含 `tool_call_id`），进入下一次远端调用。
- **步数上限 N≤3**（每轮任务），超限即收敛为最终答复。
- 每步审计落盘：工具名、参数、rc、stdout 截断（有界）、耗时；**Authorization 永不落盘**。
- 失败即 fail-closed：不可读写/超时 ⇒ 明确回灌错误，不伪装成功（反「空心」）。

## 4. 约束
- AOT 零反射、零 shell 拼接（跨平台）、`TensorPrimitives` 无关、禁 `Console.WriteLine`；发布必重发 AOT 并跑形态自证。
- 缓存前缀不得退化：`tools[]` 属静态面 ⇒ 必须**会话内恒定**（焊进首个请求的前缀），不得每轮变化。
- 预算闸：每轮任务远端调用数 ≤ 基线（动作环不得增加轮数）。
- 不得引入新的 LLM 调用点做「路由判断」（禁用模型决定用不用工具？—— 用 provider 原生 `tool_choice:"auto"`，不额外付费调用）。

## 8. 实施记录（2026-09-15 R456 实做）
- 状态: 已实施（单测 9/9 绿；AOT 发布 + 工具面烟测通过；E2E 见 eval/rover/r456/）
- 声明面: `src/agent.modelqueue/ActionLoop.cs` `ActionToolDecl.ToolsJson` — 4 件工具 (list_dir/read_file/write_file/run_command)，静态常量，手写 JSON，AOT 零反射。
- 解析面: 复用 source-gen DTO — `OpenAIChatResponseMessage.ToolCalls` (`tool_calls`) + `ChatChoice.FinishReason`；`CallEntryAsync` 映射为 `QueueResponse.ToolCalls`。
- 回灌面: `QueuePrompt.PostUser` (`QueuePostUserMessage`) 追加在 messages **尾部** (system/context/history/user 前缀逐字节不变 ⇒ 缓存前缀单调增长)；`SerializeChatRequest` 手写 writer 输出 `tools` / `tool_calls` / `tool_call_id`；无工具请求仍走 source-gen (单测断言逐字节相同)。
- 执行面: `src/agent/action/WorkspaceActionPort.cs` (IActionPort 实现) — 工作区根约束 (越界即拒)、输出 8 KB 上限、命令 120 s 超时、进程树回收、审计 JSONL (UTF8 无 BOM)。
- 接线: `ModelQueueAdapter` 在 `AGENTFRAMEWORK_ACTION_LOOP != off` 且注入了 IActionPort 时启用动作环 (≤6 步)；DI 见 `ServiceCollectionExtensions`。
