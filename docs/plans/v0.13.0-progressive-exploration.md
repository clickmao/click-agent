# v0.13.0 渐进式探索 (Progressive Exploration) 设计文档

> 状态: 设计中 (文档先行, 用户钦定 2026-09-08)。
> 用户定义 (逐字要点): 内部逐步向上下文、指定目录、指定网页链接自动探索有关信息;
> **需要渐进式探索** — 如从上下文中探索到网页链接时, 该网页链接**大于**在上下文外的指定目录
> (优先级/深度判定), 可以在 config 内设置 agent 在一块上下文区域、一个文本或是一个网络链接内
> **最大渐进探索步骤**。

## 一、核心概念
### 1.1 探索图 (Exploration Graph)
- 节点 = 探索源: `context` (上下文区/RAG snippet) / `url` (网页链接) / `dir` (指定目录) / `file` (目录内文件) / `text` (文本片段)。
- 边 = 探索中发现的新源引用 (上下文含 URL → url 节点; 网页含相对路径 → file/url 节点)。
- 渐进 = BFS 分层 + 每层预算控制, 非无限递归。

### 1.2 步数预算 (config 可设, 用户钦定)
```yaml
# config/base/exploration.yaml (新增)
exploration:
  max_steps_per_context_block: 4   # 每块上下文区域最大探索步
  max_steps_per_text: 2            # 每个文本片段最大探索步
  max_steps_per_url: 3             # 每个网页链接最大探索步 (抓取+抽取+追问)
  max_steps_per_dir: 5             # 每个指定目录最大探索步 (列目录→读文件→追引用)
  max_total_steps: 16              # 单轮请求全局预算 (防爆)
  url_depth: 1                     # URL 内发现的新 URL 是否继续 (0=不追, 1=追一层)
  priority:                        # 源优先级 (用户例: 上下文内链接 > 上下文外目录)
    context_block: 1
    url_from_context: 2
    url_other: 4
    dir_in_context: 3
    dir_external: 5
```
- 预算耗尽 → 节点标 `budget_exhausted`, 不再展开, 如实打点。

### 1.3 优先级语义 (用户例的泛化)
- 探索队列 = 优先级队列 (priority 小者先); 同级 FIFO。
- "上下文中探索到的网页链接 > 上下文外的指定目录": url_from_context(2) < dir_in_context(3) < dir_external(5) ✓。

## 二、思考链集成 (v0.13.0 任务1 协同)
- 挂载点: IntentRecognizer 之后, ContextAssembler.AssembleAsync 之前 — 探索产出作为增强上下文注入。
- 逐步: LLM 思考链每步产出 `ExploreStep` (源类型/引用/假设), 内核执行抓取 (url: HttpClient; dir/file: Workspace; context: RAG snippet 扩展), 结果回填思考链。
- 打点: `explore_step` (source_type, ref, priority, step_n, budget_left, ms, ok, bytes) — KPI 检测:
  - 新维度 `exploration_index` (步数分布/命中率/预算耗尽率) — 登记 test-dimensions-ledger.md。
  - 假设: 探索开启后 reply_rel/EvidenceGate 提升, tok/case 上行 (带宽重新校准)。

## 三、AOT/工程约束
- 禁反射; 探索 DTO 走 source-gen (ExplorationJsonContext)。
- URL 抓取: HttpClient + 超 512KB 截断 + Content-Type 白名单 (text/html, text/plain, application/json)。
- 目录探索: Workspace 现有 API, 禁越 root (路径穿越防护)。
- config 热读走 load_env()/yaml 现有模式 (缺陷57 教训)。

## 四、里程碑
- M1: ExplorationConfig + ExplorationPlanner (队列/预算/优先级, 纯逻辑+单测)。
- M2: URL/File 探索执行器 (真机抓取/读目录) + explore_step 打点。
- M3: 思考链集成 (LLM 逐步决定探索方向) + harness 用例 (T-E01: 带链接的问答; T-E02: 带目录的任务)。
- M4: KPI 校准 (探索开/关 A/B) + 文档收口。

## 五、排除项
- 不做 JS 渲染浏览器级抓取 (纯 HTTP 文本)。
- 不越出 Workspace root 的目录探索。
- 不在探索中执行任何写入操作 (只读探索)。
