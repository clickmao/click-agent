# R466 —— 复述回放 vs 承接反问的优先级 (修 R465 预注册判据 C3 FAIL)
- 状态: 已收口（R466）

- 上游: R465 (`docs/reports/r465-repeat-skip.md`, `eval/rover/r465/verdict-r465.json`)
- 缺陷读数 (外部真值, 桩侧 calls + turns): 「再讲一遍。」(t6) 是本会话第 2 个复述轮 ⇒ 前置门
  Skip 支已按 `repeat_verbatim` **逐字回放**上一条答复 (21 字符, 零 r1 调用, telemetry 有据)；
  但 R458 收口面 `if (!grounded) → 承接反问` 无条件覆盖, 用户可见答复变成 46 字符承接反问
  ⇒ 预注册 C3 (复述轮答复 == 上一条答复) **FAIL**, 质量面负增益。
- 因果链: 承接反问的**前提** = 「本轮无可确定的答复对象」(见 `ContinuationBrief.IsContinuationTurn`)。
  纯复述轮的答复对象 = 会话历史里上一条助手答复原文 (真实、逐字可核验) ⇒ 前提不成立
  ⇒ 覆盖非法。t9「从头再说。」未被覆盖 (其 `_continuationFacts` 为 null, 不进入收口面) 正是对照。

## 修法 (最小面, 单源 + 可消融)

1. `ContinuationBrief.SettleRepeatVerbatim` = `"repeat_verbatim"` —— 结算类**唯一字符串口径**。
2. `ContinuationBrief.ShouldApplyFallback(settleKind, reply, facts)` 纯函数 = 优先级判据单源:
   `settleKind == repeat_verbatim ⇒ false (不得覆盖)`; 其余一律回到 `NeedsFallback` 原语义。
3. `IndustrialAgentV2`: 前置门 Skip 支把结算类写入 `_localSettleKind` (与打点**同一变量**;
   逐轮清零); 收口面消费 `ShouldApplyFallback` 并按 `grounded / apply_fallback / settle_kind /
   suppressed / priority` 全量打点 (静默抑制 = 读数与真实走向相反, R433 教训)。
4. 消融开关 `AGENTFRAMEWORK_CONTINUATION_REPEAT_PRIORITY` (默认 on; `=0` 复原 R465 行为)
   —— 供**同一二进制、同一网格**上的单变量负控 (判据必须绑机制, 不许拿跨版本差异当证据)。
