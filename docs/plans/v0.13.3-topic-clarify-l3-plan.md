# L3 主动澄清牵引 — 开发计划 (R314 立项)

## 现状 (代码事实)

- L1 轻牵引 (R307, `IndustrialAgentV2` steering 块): 连续偏题 ≥`AGENTFRAMEWORK_TOPIC_STEER_THRESHOLD`(默认 2) 轮 → 回复尾追加 `💡 提示` 行; 答案本体零改动; 打点 `topic_relevance{stage:steering}`。
- 判定: `TopicRelevanceEvaluator.Evaluate` (R308 合并) — 无锚轮词面模式 (R312) + 衔接副词精修 (R313)。
- L2: drift 计数与 `SteerHint` verdict 已打点 (R304/R308)。
- **缺口**: 提示是单向陈述, 用户不回锚则计数持续, agent 被动等待。L3 = 连续偏题达更高阈值时 agent **主动发起二选一澄清问句**, 把"是否回锚"变成对话显式状态。

## 设计

1. **触发**: `_consecutiveDrift >= L3_THRESHOLD` (env `AGENTFRAMEWORK_TOPIC_CLARIFY_THRESHOLD`, 默认 4, 即提示后用户再偏 2 轮) — 低于 L1 不并发。
2. **行为**: 本轮回复尾将提示行升级为问句: `💡 需要我回到「{coreTopic}」继续, 还是继续当前话题?` — 仍不改答案本体 (与 L1 同位追加, 同一 ProcessAsync 后置点)。
3. **打点**: `topic_relevance{stage:clarify}` (与 steering 同点位区分 stage); 用户次轮回复含回锚词 (继续/回来/项目/核心 或 coreTopic 词面) → 计数清零 (既有逻辑)。
4. **开关**: `AGENTFRAMEWORK_TOPIC_CLARIFY=0` 关闭 (默认开); AOT 零反射纯字符串拼接。
5. **度量 (拉回率)**: clarify 触发后 ≤2 轮内出现回锚轮 (drift=false 且消息含 coreTopic 词面) 记 pulled_back=1; 打点 `topic_clarify{pulled_back}` — 首批真机数据 ≥5 案后评估 KPI 贡献。

## 关键约束

- 追加点必须在区段路由之后 (R307 教训: SegmentRouter 重写 Content)。
- 无锚轮 coreTopic 为空时不触发 (L3 依赖画像 top-1)。
- clarify 问句不进 SessionMemory 用户消息存储 (与 L1 提示同策略, 避免污染历史)。

## 验收标准

- [ ] 单测: 阈值边界 (≥4 触发/3 不触发) + 开关关闭不触发 + coreTopic 空不触发 (3 例)
- [ ] 真机 E2E: 6 轮会话 (锚定→3 偏题→clarify 问句出现→回锚轮→计数清零)
- [ ] 批测: quick-11 零回归 (C01-C18 全绿)
- [ ] AOT 重发布 0 IL 警告

## 排除项

- 不做 LLM 参与的澄清生成 (纯模板问句, 与判定器同哲学: 规则确定、无额外 token 成本)。
- 不改 L1/L2 既有行为 (L3 是增量档位)。

## 待确认 (下次开发核实)

- clarify 阈值 4 是否合适 — 待 L1 拉回率真机数据 (当前 0 案)。
- pulled_back 度量的回锚词表是否需要用户自定义。
