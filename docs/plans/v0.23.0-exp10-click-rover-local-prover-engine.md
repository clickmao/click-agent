## 5. 设计（逐条回答口径）

### 5.1 mmap 惰性加载（C2）
1. `MemoryMappedFile.CreateFromFile(path, FileMode.Open, null, 0, MemoryMappedFileAccess.Read)` → `CreateViewAccessor(0,0,Read)` → `AcquirePointer` 得 `byte*`，按 64 位偏移寻址。
2. **元数据在头部（几 MB）→ 立即解析**；**权重数据永不预读**：张量 = `(base + dataSectionOffset + tensor.offset, byteLen)` 的窗口，只有在某层被真正计算时才触碰页（缺页由内核按需调入 = 惰性加载）。
3. 读窗口用 `Span<byte>`/`ref byte`，**无托管副本**（否则等于全量加载）。跨平台：Windows/Linux/macOS 同 API；AOT：`MemoryMappedFile` 与 `NativeMemory` 全支持。
4. 大页/顺序提示不承诺（本机不可验证，标「待确认」）。

### 5.2 驻留与回收（C3/C4）
- 张量状态：`NotLoaded → Loading → Resident → Evicted`；**预算 = 可配 MB 上限**（默认 512 MB，本机可跑）。
- **分层流式**：进入第 L 层 → 装载该层 9 张权重张量（q/k/v/o/gate/up/down + 2 norm）→ 算完 → 立即 `Evict`（原生缓冲 `Free` + 引用置空）。
- **热集常驻**：`attn_norm`/`ffn_norm`（极小）、**高频张量**按访问计数晋升：`token_embd` 按行取（只驻留用到的行块，不是整表）；`output.weight`（Q6_K，~230 MB）默认**流式按需行块**，避免吃光内存。
- 记账（证据源）：每张量 `loads / evictions / resident_bytes / reclaimed_bytes`，运行结束打印 `ResidencyLedger` 汇总；**回收额 = Free 前 bytes − 后 bytes**，与 `GC.GetTotalMemory(true)`/`NativeMemory` 计数交叉核对。
- 失败即如实：预算不足且无法驱逐 → 明确报 `residency_budget_exhausted`，不静默降级。

### 5.3 量化内核正确性（C1，真值对账）
- 标量参考实现（C#）+ 融合 SIMD 实现（`TensorPrimitives.Dot`）双轨；两者互相对账。
- **外部真值**：从 `/tmp/ggml-quants.c` 抽 `dequantize_row_q4_K`/`q6_K`，编译成 `libggmlref.so`（gcc + ctypes），对 **`/tmp/models/bge-m3-q4km.gguf` 与 7B GGUF 的真实张量字节**逐元素比对：要求 **bit-exact（float 逐位相等）**，不容差。
- 覆盖类型：F32/F16/Q4_K/Q6_K/Q8_0（+ Q4_0/Q5_0 视文件实际出现）。
- `dequant-check` 子命令输出：张量名、类型、块数、最大绝对误差、逐位相等计数 —— 机检断言 `max_abs_err == 0`。

### 5.4 CPU + GPU 混合（C5/C6）
- **CPU 路径（本机实测）**：`FusedGemv` 按块反量化 → `TensorPrimitives.Dot`；`Parallel.For` 只在行维并行（2 核）。
- **GPU 路径（实现，不在本机运行）**：
  - 设备层：`vkCreateInstance` → `vkEnumeratePhysicalDevices`（**本机真调，期望 0 设备 → 如实输出 `gpu_devices=0`**）→ 选 compute 队列族 → 设备/内存/缓冲/描述符/管线/dispatch/回读全链路代码。
  - 着色器：**手写最小 SPIR-V 模块生成器**（`SpirvModule.cs`，零外部工具链依赖，跨平台且 AOT 安全；glslang 在本机不存在，不假定）→ 本机校验 = 模块字长/魔数/操作码序列自检 + 单测。
  - 混合策略：权重留宿主内存（mmap），GPU 只接收**当前层/当前块**；本机无设备 ⇒ 运行时按 `--device auto|cpu|gpu` 如实选择，`gpu` 不可用即**明确失败**（不静默回退到 cpu 假装成功）。

### 5.5 真机 E2E（C1 验收链）
1. `probe --gguf <bge-m3-q4km.gguf>`：mmap 成功、KV/张量目录、`ResidencyLedger`。
2. `dequant-check --gguf <bge-m3-q4km.gguf> --tensor <q4k 张量>`：与参考实现逐位相等。
3. `gemm-check`：融合 GEMV vs 标量参考，误差 ≤1e-5（浮点累加顺序差允许），速度对比。
4. `run --gguf DeepSeek-Prover-V2-7B-Q4_K_M.gguf --prompt <t> --max-new 8 --ctx 256`：真模型出 token；**与 `llama-server`（本机在场）同 prompt 贪心首 token 对照**；输出墙钟 tok/s、峰值内存、驻留账。
5. `verify --prover`：本地 prover 出形式化符号 → 内核检查 → 报告；**同题远程 LLM 对照**（KPI：tokens 是否下降）。
6. 端到端：`agent` 侧装配插件 → 回答外附带验证报告 → 验证结论回灌计划（`formal.verify` 节点零 token）。

### 5.6 形式化闭环（C7/C8）
- **本地内核**（`Formal/Kernel`）：λ 演算 + 依赖类型子集（Sort/Pi/Lam/App/Var/Const + WHNF 归约 + 定义等价），**零 shell、零反射、确定性**（同输入同结论，可重放）。
- **插件在场与否决定提示词**（C8 机械可检）：
  - 在场（默认）：静态前缀注入「形式化输出契约」（块语言 ```clickproof、语法、要求：命题 + 证明项；**回答外附带**，不占正文）。
  - 不在场：前缀**不注入任何形式化要求**（LLM 不被要求返回形式化数据）⇒ 不增加 token。
- **闭环**：命题/证明项 → `ClickRoverSegmentPlugin` 本地检查 → `FormalReport`（`verified=true/false` + 失败位置/反例）→ 结论作为计划节点产出 → 规划下一任务（失败则进修复循环，不重问同一句）。
- 与 R351 边界：本引擎**只服务形式化验证**，**不接常规对话生成**（常规仍走 api 调用），口径见 §9「待确认」。

## 10. 缺陷修复记录：GGUF 数据区偏移（2026-09-13，三方对账抓出）

- **现象**：真实 7B Q4_K_M 前向实测 `y_sum`/`span_sum` = NaN；反向定位发现所有张量窗口整体前移。
- **根因（代码事实）**：`src/click-rover/Gguf/GgufReader.cs` 原在 **KV 段解析之后、张量信息段解析之前**执行 `DataSectionOffset = Align(pos, Alignment);`。GGUF 规范要求数据区起始 = **张量信息段之后**按 `general.alignment` 对齐；本模型少算 **16,192 字节**（= 273 条张量信息的字节量），故所有 `DataSectionOffset + t.Offset` 皆错。
- **修复**：`DataSectionOffset` 计算后移到张量信息循环之后；`tensor_out_of_range` 上界校验同步改为按 `Align(pos, Alignment)` 判定（修后 `GgufReader.cs` 该行位于循环末尾）。
- **判据（可机检）**：
  - `data_offset = 3,990,784`，与第三方解析实现 `python-gguf` 逐字节一致（修复前差 16,192）；
  - **三方对账**（自研 click-rover / 官方 ggml 参考内核 `ggml-quants.c` / 第三方 `python-gguf`）在 5 张量 × 2 模型文件（4.2 GB Prover-7B Q4_K_M、334 MB 检索模型）× 两类量化（Q4_K、Q6_K）上全部 `diff=0, max_abs_diff=0`；
  - `matvec blk.0.attn_q.weight`：`y_sum=-49.438913714140654`（有限），融合路径 vs 物化路径 `max_abs_diff_vs_fused=1.9E-06`（fp32 精度内）；4096² 约 88 ms/pass（2 vCPU）。
- **方法论教训（语言无关，已同步进 HTML 报告 §8.7）**：验证者与被验证者共享同一前提推导时，「通过」不构成证据。初版 "exact_match" 是自研解析与官方参考内核**在同一个错误偏移上达成共识**——同源对账 = 自证。跨实现一致性必须至少有一个**不共享该推导**的独立观测点，否则一律按未验证处理。
- **未覆盖（诚实边界）**：Vulkan/CUDA 路径未跑（本机无 GPU）；`TensorResidency` 的 evict 分支未被预算触发（真机 `evicts=0`）；跨实现一致 ≠ 与 llama.cpp 端到端逐 token 一致；AOT 校验未跑。
