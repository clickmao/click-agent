## 1. 问题陈述 (为什么本轮必须做计量)

| 事实 | 来源 | 影响 |
|---|---|---|
| R465–R467 的 `total_tokens = 32,097 → 14,529` 是**桩侧** `字符数//2` 估算 | `eval/rover/r467/arm-R.json:stub_est` | 与用户 KPI「总 token 使用量」**不同源**，不能作为对外结论 |
| 真实流 43 条 `llm_call` 中带 `cache_channel` 者 0 条 | R471 | 产品链实发缓存样本为 0 |
| 真实流 43 条 `effective_hit_rate` 全 = -1（会话首调） | R472 | 多轮命中**无样本**；机制定律只在合成 filler 上验过 |
| 供应商 `usage.prompt_cache_hit_tokens` 只在**响应体**里 | DeepSeek API 契约 | 桩不可能凭空造出命中 ⇒ 必须真端点 |

**结论**：分母不换源，任何「降幅 ≥30%」都是自证。

## 2. 设计 (器具)

`eval/rover/r474/relay_real.py` — 本地中继（宿主以为它在跟桩说话）：

```
宿主 --(dummy key, http://127.0.0.1:48110/v1/chat/completions)--> 中继 --(真 key, Bearer)--> api.deepseek.com
                                                                  |
                                        calls-<ARM>.jsonl (实发 messages 全文, 请求面)
                                        usage-<ARM>.jsonl (供应商 usage, 读数面)
```

- **请求面**仍可外部捕获（与 R467 桩同口径，可与桩臂逐位比对）⇒ 保留「不信被测量自报」的性质。
- **读数面**改为供应商 `usage`（prompt / completion / prompt_cache_hit_tokens / prompt_cache_miss_tokens）。
- **预算闸 fail-closed**：`max_calls=40 ∧ max_cny=0.15`（按 `config/base/models.yaml` deepseek-flash 0.27/1.10 CNY per 1M，命中不折价=上界）。越限 ⇒ 回 402 并记账，**不静默超额**。
- **凭据卫生**：key 只存在于中继进程 env（`R474_UPSTREAM_KEY`），宿主侧一律 `dummy-key`；key 不入配置文件、不入日志、不入 git。
- **配置改写**：只改写 3 个聊天端点，`/user/balance` 余额面不改写（非聊天面；dummy key 下只读 401，不计费）。

臂定义（唯一变量 = 门控 + 判官路由标志，与 R467 同）：

| 臂 | turn_gate | relation_judge | repeat_skip | 含义 |
