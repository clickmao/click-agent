## 1. 设计（最小契约位，非布尔打补丁）

新增**内容可见性契约位**，把「这句 Content 是给用户看的」提升为显式标记，而不是从 `Success` 反推：

| 层 | 变更 |
|---|---|
| `agent.modelqueue.QueueResponse` | `bool ContentIsUserFacing { get; set; }`（默认 false） |
| `ModelQueueRouter`（D1 两条终局分支） | 置 `ContentIsUserFacing = true`（文案即面向用户） |
| `agent.modelqueue.ModelQueueAdapter` | 透传 `ContentIsUserFacing = r.ContentIsUserFacing` |
| `LLMResponse`（`IndustrialAgentV2.cs:2778+`） | 同名契约位 + 文档注释 |
| `IndustrialAgentV2` 失败分支 | `response.Content = UserFacingFailureContent(llmResponse)`（`internal static` 纯函数） |

**安全属性（关键）**：未标记的失败 Content **一律不透出** ⇒ 原始报错正文/内部片段（可能含 provider 细节）不会外泄给用户；`Success=false` 语义不变（不假装成功）。

---

## 2. 约束 / 排除项

**约束**
1. 只透出被显式标记的内容；`Success` 布尔不得作为可见性判据。
2. 可见降级文案**不得拼接 `ex.Message`**（凭据/内部信息卫生）；异常原文保留在 `Error` 字段供排查。
3. 零回归：`ContentIsUserFacing` 默认 false ⇒ 既有一切失败路径行为逐位不变。
4. 真实失败仍必须 `Success=false`。

**排除项（本轮不做）**
1. 不做降级文案的模板化/多语言（超出范围）。
2. 不改前端渲染（后端只负责把可见文案送到 `reply`）。
3. 不把失败 Content 重写成「看起来成功」的内容。

## 4. 口径澄清（本轮如实记录，非缺陷但必须文档化）

1. **`llm_call.truncated` 反映「最终正文是否截断」**：D7 救回成功后该字段为 `false`；「首轮被截断」的事实只存在于 `llm_call_continue`（`before_len` / `tail_before`）。⇒ 只看 `llm_call.truncated` 会漏掉已救回轮，审计须以 `llm_call_continue` 为主键。
2. `llm_call_continue.added_len` 是**续写原文长度（去重前）**；增量 = `after_len - before_len = added_len - overlap`。两者不可混用。

## 5. 诚实边界

1. 桩驱动的端到端链（真进程 / 真 HTTP / 真链），但**模型是确定性桩** ⇒ 本判据证明的是**机制**（触发/续写/去重/透出），不是「模型在自然分布下的截断率」。
2. `empty_always` 是**构造的病态分布**（人工 100% 空正文）；真实 provider 下该分支罕见。
3. 单机 / 单模型配置 / 单次读数；含 `-np 1 -c 4608` 等既定本机参数。
4. 建计划轮（轮 1）在修复前是「空白 + `success=false`」；修复后为「文案 + `success=false`」——**失败仍然是失败**，只是不再静默。
