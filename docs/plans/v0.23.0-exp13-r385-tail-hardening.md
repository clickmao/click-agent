## §1 D7c 决策回填（原待办：「契约前置注入落点不存在」）

**决策：不拆逐节点远程生成；契约判据由契约层定，由 `PlanNode.Formal` 承载，判定在节点执行前门本地完成。**

理由（可证伪）：
1. 计划是确定性构建（§0 行 1），远程节点**没有**逐节点生成步骤 —— 「拆逐节点」等于给每个节点新增一次 LLM 调用，与用户钦定的「降低 TOKENS 使用，不能全让 LLM」直接冲突；
2. 形式化判据若由模型自选，即「模型自定标准再自证合规」，与用户审计标准（断言必须绑定真实行为，不得空心）冲突。故判据归**契约层**（框架侧），模型最多提供被检查的**取值**；
3. 落点已实装：`PlanNode.Formal`（`src/agent/intent/TaskPlan.cs`，STJ 自动生成，无需改源生成器）→ `PlanNodeFormalGate.Evaluate` → 内核；
4. 消融开关：`AGENTFRAMEWORK_FORMAL_GATE=0` ⇒ 全节点视同未声明（对照组）。

**已交付**（S2，本轮）：契约层 `FormalAssertionContract`、处置层 `PlanNodeFormalGate`、节点前门接线 `PlanRunner.cs`、装配级评测入口 `--formal-eval`、单测 44 例。

## §3 WaitUs 墙钟锚点（⑤修：跨进程等待可对账）

问题：`StartedUs/EndedUs` 来自进程内单调时钟（§0 行 5），跨进程/跨轮无法与外部时间线对账（R384 真机 `wait_ms=9` 只能自证）。

设计（最小改动、可证伪）：
1. `NodeWaitRecord` 增 `StartedWallUtcMs`/`EndedWallUtcMs`（`DateTimeOffset.UtcNow.ToUnixTimeMilliseconds()`），**保留** `StartedUs/EndedUs` 不动（单调时钟仍是时长唯一事实源，墙钟只做锚点）；
2. 写入点与 `StartedUs/EndedUs` 同处设置（同一写点，禁止两处各自取时钟）；
3. 对账判据（探针断言，逐条机检）：
   - `EndedWallUtcMs >= StartedWallUtcMs`；
   - 跨进程场景：后一进程的 `EndedWallUtcMs >=` 前一进程落盘的 `StartedWallUtcMs`（时间线不倒流）；
   - `(EndedWallUtcMs - StartedWallUtcMs) >= 0` 且与 `WaitUs/1000` 同量级（允许 ±2s 时钟容忍，不做等价断言）。
