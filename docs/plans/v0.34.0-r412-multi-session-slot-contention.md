## 2. 判据（**预注册**：跑之前写死，跑完不许改）

臂设计（同一 server 进程；P1 = `eval/rover/r411/long-prefix.txt`（R411 实测渲染 4337 token ≥ 4224 红线）；
P2 = 同长度变体（前插唯一标记，长度仍 ≥4224，两会话系统前缀不同））：

- **A** 同会话连续: S1 t1 → S1 t2（基线；期望携带复用率 ≥ 0.97，复现 R411）
- **B** 会话交替（串行请求）: S1 t1 → S2 t1 → S1 t2 → S2 t2
- **C** 会话交替（真并发: 两个线程同时发 t1，再同时发 t2）
- **D** 处置候选: `-np 2 -c 12288` 重跑 C（每 slot 6144 ≥ 4224）

判据:

- **C1（争用签名）**: B 或 C 中任一会话的携带复用率 < 0.97，且 A 中 ≥ 0.97 ⇒ 争用成立。
- **C2（静默 vs 显式，必须分类）**: B/C 出现 HTTP 错误 / 503 / 超时 ⇒ 记「显式失败」；
  返回 200 而 `cache_n` 崩塌 ⇒ 记「静默失效」。两类分别落盘，**不合并成一个通过率**。
- **C3（绝对长度）**: 记录 `cache_n` 绝对值；`cache_n < 4224` ⇒ K2b 在该臂**不达标**
  （R410 口径: 比值不是 KPI，绝对长度才是）。
- **N1（负控，防“永远判红”）**: A 必须 ≥ 0.97。若 A < 0.97 ⇒ 记 **INCONCLUSIVE**（探针/环境无效），
  **不得**判争用。
- **D 的可判性预声明**: 若 D 的每 slot 上下文 < 4224 token ⇒ D **不可判**（不许把「长度不够」当「并发已解决」）。

携带复用率口径（与 `LocalSessionCacheLedger` 一致，分母不用远端 64 单元界）:

```
ceiling      = 上一轮 prompt 总长 + 上一轮生成 token（首轮无）
carryOver    = min(本轮 prompt 总长, ceiling)
carryReuse   = cache_n / carryOver
```

## 2.1 判据修订（冒烟后、正式臂之前 —— 记录在案，非跑后调整）

冒烟（同一探针、前缀缩到 ~70 token、`-np 1 -c 2048`）实测: 臂 A/B/C 的携带复用率**完全相同**

token 子序列，llama.cpp 的 `cache_prompt` 复用把两边都救了（S2 的**冷启**请求都拿到 79/80 命中）。
