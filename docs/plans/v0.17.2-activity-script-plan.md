# v0.17.2 窗口&任务感知 + 脚本插件协议计划 (R336 立项 — 用户钦定 2026-09-10)

> 用户指令 (逐字核心): "新增增强计划 v0.17.2 窗口&任务相关，获得当前所有激活窗口活动的任务，简单API和skill在外部程序接口和指令可以任务会话中得到激活任务信息（除本CLI外，其他CLI任务状态也需要得知，并通知进程和job_id名称），该skill可以完成诸如【如果当前没有其他任务存在则XX（分钟/小时/天）执行XXXXX...】与【定时任务skill】定时任务需要执行脚本编写和脚本调用，走增强计划script内的相关插件层【脚本增强计划】关于执行层自行需求（非用户指定的脚本）都使用py来编写，并交给插件服务执行脚本（CLI验证PY正确后交给插件服务），需要明确规划好与插件层的对接协议，比如脚本执行时是否需要定期回复给CLI一些信息，脚本结束时是否需要在结束前返回信息，脚本长时间执行时是否需要定时反馈信息给CLI等"

## 0. 现状差距

- 任务状态仅 TaskCharter active.json **单活动章程** (单任务槽) — 无多 CLI/多窗口活动视图; 无运行时心跳/过期。
- AgentRegistry = 持久 UID 身份 (agent_registry.json) — 非运行时活动。
- SkillExecutor 执行 executive 脚本本地 subprocess — 无标准输出协议 (进度/心跳/结束约定)。
- Hermes cron (外部) 有 job_id — AgentFramework 内无 job_id 概念 (env AGENTFRAMEWORK_JOB_ID 可注入)。

## 1. v0.17.2-a 活动任务注册表 (ActivityRegistry)

### 设计 (跨进程, 复用 v0.17.0 文件锁/原子写)
- 每活动 CLI 进程一个心跳文件 `data/activity/<pid>.json` (写经 LockedFileWriter, TTL 5s 心跳, 退出清或过期):
  `{Pid, WindowId(env AGENTFRAMEWORK_WINDOW 或 "cli"), JobId(env AGENTFRAMEWORK_JOB_ID 或 ""), AgentName, TaskId(当前 TaskCharter? 无则 ""), TaskSummary(当前目标/首 80 字), StartedUtc, LastHeartbeatUtc, Status(running/idle/exiting)}`。
- **汇总视图** (查询免扫全目录): `data/activity/index.json`? 查询频率低 → 直接扫目录 (≤几十进程) 即可, 免 index 双写竞态。**不建 index** (扫目录 + 每文件读; 过期判定 LastHeartbeatUtc > 10s → 忽略/清理)。
- 心跳: V2 每轮 OnProcessAsync 开始/结束时 Heartbeat() (异步, 失败静默); 空闲也保活 (last active turn > 60s → 降 idle)。
- **API**: `ActivityService` (agent.activity): Register/Heartbeat(turn summary)/QueryActive()/QueryCondition(排除自身 pid) → List<ActivityEntry>; IsOtherAgentBusy() (除自身外有 running 条目)。
- **指令** `/activity`: 列全部激活窗口/agent/任务/job_id/pid/状态/心跳龄。外部程序可直接读 data/activity/*.json。
- **skill** `activity-check` (normative 轻量): 问 "当前有其他任务吗/空闲吗" → 调 ActivityService.IsOtherAgentBusy → 直出 bool + 条目数。**条件调度原语**: "如果当前没有其他任务存在则 X 后执行 Y" → 指令/skill 内: IsOtherAgentBusy()==false → 注册 Hermes cron/内部延时执行; busy → 回复拒绝/顺延。一期 skill 输出判定结果由上层 (任务循环) 决策。
- 与 TaskCharter 关系: 单 agent 多轮任务 = 一个 activity 条目, TaskId 取当前 charter (running 时); 无 charter 的普通对话 = activity running 但 TaskSummary=当前意图。

### 验收 (a)
1. 单测: 注册+心跳+查询; 过期 (>10s 无心跳 → QueryActive 不含); 退出清理; IsOtherAgentBusy (自身排除); 并发双进程写各自文件无串扰 (LockedFileWriter)。
2. E2E: 双 host 实例同跑 → /activity 互相可见 (pid/窗口/job_id); 一个退出 → 另一查询其条目消失。
3. 全量单测绿 + AOT 0 IL 警告 + quick-13 零回归。

## 2. v0.17.2-b 脚本插件协议 (执行层自需脚本 py 化)

### 原则 (用户钦定)
- 执行层**自行需求** (非用户指定) 的脚本一律 Python 编写 (弃 shell/其它)。
- 流程: CLI 产出/编写 py → **CLI 验证** (py_compile 语法 + 可选 --self-check 干跑) → 交给**插件服务**执行 (agent 主进程外, 长任务不阻塞 CLI 主循环)。
- 对接协议 (本文档 = 权威):
  - 脚本 stdout 必须 **JSON Lines 事件流**: `{"type":"progress"|"checkpoint"|"done"|"error","ts":...,"msg":"...","data":{...}}` (一行一事件; 非 JSON 行 = 调试噪声, CLI 忽略并打点)。
  - **定期反馈 (长执行)**: 脚本启动参数 `--heartbeat-secs N` (默认 30s) → 每 N 秒发 `{"type":"heartbeat","progress_pct":..,"msg":"当前阶段"}`; CLI 侧 >2×N 无事件 → 判疑似挂起 (打点, 不杀 — 观察再 N)。
  - **结束前返回**: 脚本退出前必须发 `{"type":"done","exit_code":0,"summary":"..."}` 或 `{"type":"error","exit_code":1,"error":"..."}`; CLI 以 done/error 为准, 不以进程退出码单判 (退出码作兜底)。
  - 参数与上下文: 脚本收 `--task-json <file>` (任务结构化描述 + 上下文路径); 产物写指定输出目录, 路径在 done.data.outputs 返回。
- CLI 侧包装: SkillExecutor py 执行改为: 验证 (py_compile, 失败 → 拒绝执行 + 教训 Record "script-invalid:<name>") → 插件服务 subprocess 异步 (v0.17.0 FileLock 保护共享产物? 脚本产物默认走 v0.17.1 staging 若改用户文件) → 事件流解析 → 进度打点 + 结束回填。
- 定时任务 skill (v0.17.2-c, 接 a+b): /schedule 指令或任务内 skill → 条件 (空闲) + 延时 + py 脚本 (走插件层) → 到期条件满足 → 执行 + 事件流回报。

### 验收 (b/c)
- 单测: 协议解析器 (事件流 → 状态机 done/error/超时无事件); py_compile 验证拦截坏脚本; 心跳超时判定。
- E2E: 长跑 py (120s sleep + heartbeat) → CLI 事件流接收 + 进度打点 + done 回填; 坏 py → 拒绝 + 教训。
- 本计划分期: a 本期 (R336); b/c 下期 (R337+, 依赖 a 的条件原语与 SkillExecutor 改动)。

- Activity 文件不进 git (data/ 已 ignore)。
