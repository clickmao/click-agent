## 1. 目标口径钉死 — 90.5% 是什么

**来源(本轮独立核实, 非本仓库自述)**: FAVA — *Formal Authorization for Verified Agents with Evidence-Backed Permission Graphs*, arXiv **2607.27267** (2026-07-29)。
原文逐字:

> "We evaluate FAVA across OpenAgentSafety, OctoBench, and ActPlane scenarios. Our evaluation demonstrates that FAVA achieves a **90.5% Decision Compliance Rate (DCR)** over the aggregate dataset, successfully intercepting dynamic violating traces in the evaluated trace-conditioned scenarios."
> "…with a negligible **median JIT overhead of < 1 ms**…"

**FAVA 自陈边界(逐字, 决定对标可行性)**:

> "FAVA does not provide an end-to-end proof that an agent is safe from natural language alone; its formal guarantee begins once available evidence has been **lowered into the permission graph**."

⇒ 90.5% 里**包含「自然语言 → 权限图/IR」的降层损失**, 不是求解器指标。谁把 90.5% 当成"形式化内核准确率"就会答错问题。这也是本方案 §6 的头号风险。

**同赛道对标数字(已核实)**: Agent-C(arXiv 2512.23738) 时序合规 **100%** vs AgentSpec 82.27% / DynaGuard 73.8% / 无护栏 37.79%; Provably Secure Agent Guardrail(arXiv 2605.29251) 走 SMT + 隔离 TCB。⇒ 90.5% 不是天花板, 外部最强在受限(时序)子域已报 100% ⇒ **±5pp 是可达区间, 而非上限**。

**待确认(防上下文丢失, 实施前必须消解)**:
- **T1** DCR 精确公式与分母: 逐"决策"计数, 还是逐"轨迹"计数? 宏平均还是微平均?
- **T2** 弃权/超时/不可判 是否计入合规? (决定 §3 的整个不等式)
- **T3** 三个题集的规模、判定者(人工/脚本)、超参预算。
- **T4** "aggregate" 的合并方式(加权? 等权?)。

**对标规则**: T1–T4 任一未对齐 ⇒ ±5pp 的差值**不可解释**(可能只是分母不同)。故本方案给双口径: 先自证我方口径, 再谈对标。

## 2. 度量定义(可证伪, 不放任何弹性)

- **决策单元 `d`**: 一个节点决策 = (节点类型, 工具/动作选择, 参数绑定, 放行/阻断/弃权)。**分母 = 决策数, 不是轮数、不是轨迹数**(与 FAVA "Decision" 一致; T1 待确认)。
- **判定者**: 确定性检查器 —— agent.rover `check` 子命令 + 契约检查器 + 资源/权限约束。**零 token、零 shell、零外部进程、无 LLM 参与**。**不采信模型自评**。
- **判决域**: `Proved` → 放行; `Refuted` → 阻断 + 回注精确反例(最小冲突核); `Vacuous` → 前提空洞, 拒绝(不静默吞); `Unknown` → **弃权**(交还用户, 附机器可核理由码 `fragment_limit:*` / `int_gap` / `decision_unknown`)。
- **决策合规率** `DCR = (正确放行 + 正确阻断 + 正确弃权) / d`。
- **成对指标(防空转刷分, 必须同时报)**:
  - `coverage = (放行 + 阻断) / d`(非弃权率),
  - `错误的放行率 = 错误放行 / d`,
  - 弃权理由码分布(弃权必须**可解释**, 不可"因为不确定"了事)。
- **分层报账**: 按轨迹步长分桶(1–2 / 3–6 / 7–12 / 13–18 / 19–24 步)。**单看总均值会掩盖长轨迹崩塌**(见 §6 R2)。

## 3. 达标条件的数学(±5pp 翻译成工程约束)

若弃权计合规(FAVA 风格), 则 `DCR = 1 − 错误放行率`。于是:

| 目标 DCR | 等价约束: 错误的放行率 `E` | 且覆盖率 `C` 必须 ≥ |
|---|---|---|
| 85.5% (下界) | `E ≤ 14.5%` | `C_floor`(待定, 建议 ≥ 0.70) |
| 90.5% (基准) | `E ≤ 9.5%` | 同上 |
| 95.5% (上界) | `E ≤ 4.5%` | 同上 |

若"弃权"不被外部口径计合规(T2 为否), 则回到纯乘法链:

`DCR ≈ (判定侧正确率) × (语义降层忠实率)` —— 外部实测降层缺口高达 **29.0pct**(编译通过 89.5% vs 语义忠实 60.5%, 见报告 §裁决3), 那么 90.5% 必须靠**缩小断言语言覆盖的决策类**换取, 而不是靠求解器变强。**这就是 T2 为什么是决定性问题。**

**结论**: 本方案的靶点 = **错误的放行率 ≤ 4.5%, 覆盖率 ≥ 70–90%, 长轨迹(≥13 步)不出现断崖**。

## 5. 最合理的 agent 执行链(形式化验证为骨)

### 5.1 链形(5 段, 判定全在本地零 token)

```
① 意图 → 契约前置(静态前缀, 零 token)
      ├ 决策前提显式化: 目标/边界/可判定片段声明
      └ 减少澄清轮 ← 已在 R376/R379 验证
② 计划 → 节点化 + 逐节点断言(*.assert/契约)
      └ 判据集由契约层定义, 模型不得自选判据(防规范博弈)
③ 节点 → ★本地形式化闸门 agent.rover check(零 token/零 shell)
      ├ Proved   → 放行
      ├ Refuted  → 阻断 + 回注精确反例(最小冲突核) → 闭环重试 ≤1 次
      ├ Vacuous  → 拒绝(前提空洞, 不静默吞)
      └ Unknown  → 弃权 + 理由码 → 交还用户(计合规, 但受 coverage 下限约束)
④ 执行 → 出站网关(资源/权限/依赖约束) + 审计轨迹落盘
      └ 出站前再检一次(FAVA 同构: JIT 网关 + 单调图修复)
⑤ 收口 → 可离线重放(不再调 LLM) → 已验证结论缓存进稳定前缀
```

**嵌入点(既有锚点, 已核实文件存在)**: `src/agent.host/CliSession.cs`(入口) · `src/agent/intent/PlanResumeService.cs`(装载/续跑) · `src/agent.recovery/ExecutionCheckpoint.cs` · `src/agent/registry/{CapabilityPlugin.cs,SegmentKind.cs}` · `src/agent/extensions/ServiceCollectionExtensions.cs:145-152`。
**精确插入行号 = 待确认(依赖 recon 阶段级地图)**; 未拿到地图前不写接线代码。

### 5.2 为什么是"节点级"而不是"回复级"

- 逐节点 ⇒ 阻断粒度小、反例可定位、可回注 ⇒ 重试成本低(报告 §裁决2: 符号检索使昂贵编译-修复循环调用 **−26.6–29.8%**)。
- 回复级验证 ⇒ 只能整体重写 ⇒ 长轨迹下收益为负(§6 R2)。

### 5.3 闭环重试上限(硬约束)

**≤ 1 次**。外部实测: 1–2 步轨迹忠实率 81.3%, 19–24 步跌至 **12.0%** ⇒ "再多修几轮"是负收益区间。超阈值强制降级为弃权。
