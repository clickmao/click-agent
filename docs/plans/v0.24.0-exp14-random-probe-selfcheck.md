## 2. 设计（三条铁律，全部机检化）

1. **独立双路径**：每题期望答案由两条互相独立的实现算出；不一致 ⇒ **拒绝发题**（绝不发未验算的题）。
2. **公开/隐藏分离**：公开样例只用于题面；判分**只认隐藏用例**（隐藏用例的答案由生成期算好，不暴露给解法）。
3. **失败必须分类**：`no_code / syntax_error / runtime_error / timeout / wrong_output / partial / no_final / wrong_final`；只报通过率 = 空心指标。

**解法适配器契约**（语言无关，文本进文本出）：`oracle` / `file:<dir>` / `command:<shell>` / `agent`（真机走 AOT `agenthost -q`，py 插件落盘产物）。

## 4. 判据与门禁（不可自证）

- 生成器/判定器/编排器三者**各自**有 `--selftest`，且含**反向负控**（把判据打坏后必须转红）。
- `skills/**/SKILL.md`（`type: knowledge_hint`）由 `SkillGeneralizationTests` **全目录**体检：① 可被加载器加载 ② keywords/regex_patterns 非空（否则 skill 永不触发）③ **正文零语言特性**（语言细节一律外置到 `references/`）。
- 机检失败 = 门禁红，不许"注释掉测试"绕过。

## 5. 已产出的经验（证据 → 经验）

| 证据（真实运行） | 抽象出的语言无关经验 |
|---|---|
| 首轮真跑 `no_code` 实为**判定器要求围栏**、而产品交付是**裸回复区 + 落盘产物** | 判据必须按**交付物的真实形态**收集候选并取"可编译/可验证"者；假设形态 = 空心判定 |
| 硬编码公开样例的作弊解仍拿 22.2% 隐藏用例通过率 | 计分单位必须是"**整题全对**"，用例级通过率会给出作弊空间 |
| 差一错误解在两路径比对恒真时被判通过 | 判据被打坏后**必须**转红 ⇒ 反向负控是判据的一部分 |
| 全目录体检暴露 `image-gen` 零 regex_patterns、`critic-rules` 正文含语言 token | 单点门禁 = 覆盖面缺口；门禁必须**遍历全目录**，否则新条目无门禁 |
