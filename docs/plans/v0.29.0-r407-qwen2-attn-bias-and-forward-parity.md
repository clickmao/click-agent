## 2. 判定（预注册，跑之前定死）

- **H0（缺陷无害）**：各层 `attn_{q,k,v}.bias` 字节完全相同 ⇒ 复用 `blk.0` 与逐层读取数值等价。
- **H1（缺陷成立）**：存在层 `l` 使 `sha256(blk.l.*) != sha256(blk.0.*)` ⇒ 必然静默算错。

**实测（`scripts/r407_bias_alias_probe.py`，`eval/rover/r407/bias-alias-probe.json`）**：四路 bias
在 28 层上**各 28 个互异 sha256**；与 `blk.0` 的最大绝对差 `q=121.7 / k=407.1 / v=10.6`；
`attn_output.bias` 在本模型不存在 ⇒ H1 成立、`_oBias` 走 null 路。

## 3. 实施

1. **修复**：`MaybeLoadBiasPerLayer` 逐层物化（28×2048 f32 ≈ 229 KB，可忽略）；层间不一致抛
   `cfg_partial_bias`，形状不符抛 `cfg_shape_mismatch`（沿用「不静默降级」契约）。
2. **可机检端口**：`AttnBias(l, which)`；未知 `which`/越界 `l` 抛 `ArgumentOutOfRangeException`。
3. **回归测试**：`src/agent.tests/RoverAttnBiasParityTests.cs`（判据见 §4；测试工程按 Link 手工登记
   rover 源文件，本轮新增 `GgufMappedFile/GgufReader/ModelConfig/TensorResidency/KvCache/ForwardPass` 六个 Link）。
4. **对账设施**：`ForwardPass` 之外不动产品路径，只给 `GenerateCli` 加 `--dump-logits DIR`
   （`cli/GenerateCli.cs:22/371/453/710`），把每 step 采样所用的**原始 f32 logits 向量**落盘。

### 4.1 V5/V6 的关键因果（**别把 f16-KV 的差异算到引擎头上**）

同 prompt 同模板双 greedy，本引擎与 llama.cpp **默认臂**在第 15 个 token 分叉
（本引擎 ` start`，llama.cpp ` can`）。三步排除：

1. 关掉 llama.cpp 全部采样过滤（`--top-k 0 --top-p 1 --min-p 0 --repeat-penalty 1.0 --temp 0`）⇒ 仍 ` can`（**不是采样器**）；
2. 独立 numpy oracle 与我方**逐 token 相同**（24/24 id 一致、logits cos=1.0）⇒ **不是我方独有偏差**；
3. llama.cpp 换 `--cache-type-k/v f32 --flash-attn off`（默认 KV 是 **f16**，相对精度 ~1e-3）⇒ 输出变成
   ` start by breaking down…` = **与我方逐字相同** ⇒ 分叉源 = **llama.cpp 默认 f16 KV cache 在近并列处的翻档**。
