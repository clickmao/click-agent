# v0.83.0-R464 · 本地判别通道「配置错配」fail-closed（消灭静默回退默认权重）

状态: 已收口 (R464) · 判决 `eval/rover/r464/verdict-r464.json` · 报告 `docs/reports/r464-config-fail-closed.md`

## 1. 触发（R463 现场发现 + 全候选推进令）

R463 负控 BP 首跑 VOID，根因不是负控设计错，而是**产品代码静默替换了配置意图**：

```
src/agent/extensions/ServiceCollectionExtensions.cs:300
    ModelPath = lc.IsReady ? lc.ModelPath : baseOpts.ModelPath,
```

`lc.IsReady = 路径非空 ∧ File.Exists(路径)`。于是 `local.model_path` 指向**不存在**的文件时，三个互不相同
的世界被压成同一个读数：①配置可用 ②配置错配 ③配置未声明。产品在 ② 时**静默改用宿主默认权重**
（env `AGENTFRAMEWORK_LLM_MODEL` / 内置 `~/.agentframework/models/qwen2.5-3b-instruct-q4km.gguf`），
既不告警、也不在遥测留痕 ⇒ 任何以「权重档位」为单变量的测量在 ② 下**读数是错的且看不出来**（R463 BP 因此 VOID）。

这是「器具必须 fail-closed」的直接违反：**仪器 IO/配置异常必留告警**，且「宣称的配置」与「实际生效的配置」
必须可区分（承 R446「形态自证」、R463「cfg 只追加 delta 块」同族纪律）。

## 3. 设计（三态分离 + 绝不替换）

| 配置状态 | 生效路径 | 通道 | 告警 |
| --- | --- | --- | --- |
| 未声明 `local:` 段 | 宿主默认（env / 内置） | 按默认文件是否存在 | 默认文件缺失时告警（原为静默） |
| 声明且文件存在 | **配置路径** | 可用 | 无 |
| 声明但 `model_path` 为空 | `""`（不可用） | 不可用 | `R464 config_mismatch` |
| 声明但文件不存在 | **配置路径本身**（不可用） | 不可用 | `R464 config_mismatch`（含「未回退默认权重 X」字样） |

- **铁律**：`Declared == true` 时**任何情况都不把 fallback 写进 ModelPath**。错配 ⇒ 通道不可用 ⇒ 门走既有
  fail-open（Pass，远端兜底）——安全语义不变，但**配置意图不再被偷偷改写**。
- **宽度参数同源**：`ContextSize`/`Parallel` 只在 `Source==Configured` 时取配置值（原来按 `IsReady`，在错配时会
  把配置宽度丢掉、改用宿主宽度，同属静默替换）。
- **告警双通道**：`ILogger`（有 DI 时）+ `Console.Error`（headless/无 logger 的宿主机路径也必须可见），
  且告警串以 ASCII 标记开头（机检可 grep，不依赖中文控制台编码）。

## 4. 约束

- 零关键字补丁、零语言特定硬编码；解析器是纯函数（可单测，不依赖真实权重）。
- 单变量对照：同网格（R438 `task-p12.json`）/ 同桩 / 同 role / 同二进制，**仅换二进制**（R463 二进制 → R464 二进制）。
- 质量硬线不退化：残余带轮（6–9）+ 纠正轮（10–12）不得 Skip；12/12 轮 ok。
- 形式门禁：`VerificationFormTests` 全绿；AOT 0 IL 警告；`registry` 两行。
