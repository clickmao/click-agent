# v0.13.1 增强计划: 备选兜底校验 + RAG 相似问题粘性路由

> 状态: 设计中 (用户钦定 2026-09-08, 文档先行)。
> 用户定义 (逐字要点): ①当存在备选 LLM 时启用兜底校验, 可以通过 config 设置是否启用兜底服务,
> 逐个按照性价比 (与 auto 选择模式相同) 进行失败兜底, 并记录问题到 RAG 内;
> ②相似问题首先使用成功模型问询 — 实例即 C17 真败相: deepseek-v4-flash 兜底被断言脆性误判,
> 说明"哪个模型在什么问题上成功过"本身就是有价值的路由依据。
> 【注意】相似问题如何确立, 需要设计详细的开发计划和校验收敛和执行打点跑测得到数据后验证有效性。

## 一、功能设计
### 1.1 config 开关 (fallback.yaml 或 models.yaml 新段)
```yaml
fallback:
  enabled: true                  # 总开关 (用户钦定: config 设置是否启用兜底服务)
  order: cost_quality            # 性价比序 = auto 选择模式同序 (RankCandidates)
  per_request_max_fallbacks: 2   # 单请求最多切几个备选 (现行为: 重试2次+切备1个 → 可扩展)
  record_failures_to_rag: true   # 失败问题记 RAG (问题级路由记忆)
  similarity_threshold: 0.80     # 相似问题判定阈值 (v0.13.1 保守起步, 见 §2)
  sticky_ttl_hours: 72           # 粘性记录有效期
  verify_fallback_reply: true    # 兜底回复校验 (非空+非错误模板 — 兜底校验)
```

### 1.2 兜底链改造 (ModelQueueRouter.OnTransientFailureAsync)
- 现状: 重试1次 → 切备1个 (FirstOrDefault) → 失败返回。
- v0.13.1: 备选按**性价比序**逐个尝试 (per_request_max_fallbacks 个上限), 每个兜底回复过校验
  (非空/非错误模板/长度>min) — 校验失败继续下一个 (用户钦定"逐个...兜底")。
- 全部失败 → 如实返回失败 (不降级硬跑)。
- 打点: `fallback_attempt` (from, to, attempt_n, verify_ok, ms) — 现有 llm_failover 扩展。

### 1.3 问题级粘性路由 (RAG 记忆 — 用户钦定核心)
- **写**: 请求成功后记 `RouteRecord { question_emb (bge), question_head, model_id, outcome, ts }`
  → RAG 命名空间 `route-memory`; 失败请求同样记录 (outcome=fail, model_id=失败模型)。
- **读 (关键)**: 新请求进来, 先用问题 embedding 检索 route-memory:
  - 命中 (sim ≥ threshold) 且 outcome=success 且模型可用 → **首选该模型** (粘性),
    打点 `sticky_route_hit` (sim, model, from_record);
  - 命中 outcome=fail → 该模型**降权/跳过** (同类问题已知失败), 打点 `sticky_route_avoid`;
  - 未命中 → 走正常 auto 序。
- 与手动覆盖关系: 手动 /model 指定 > 粘性路由 > auto 序 (用户显式意图优先)。

## 二、相似问题如何确立 (用户【注意】点 — 设计核心, 需跑测验证)
### 2.1 候选机制与风险
| 机制 | 优点 | 风险 (跑测须验证) |
|---|---|---|
| A. bge embedding 余弦 ≥ 阈值 | 零成本, 语义级 | 小模型语义漂移: 不同问题同 embedding (假阳性); 阈值难定 |
| B. 意图+实体指纹 (IntentRecognizer + 关键实体 Jaccard) | 结构化, 可解释 | 同意图不同问题误粘 |
| C. LLM 判定 "是否同一问题" | 最准 | 每请求多一次 LLM 调用 (成本/延迟) |
### 2.2 v0.13.1 决策: A 为主, B 为护栏, C 留作高价值场景
- 双门: `sim ≥ threshold` **且** 意图一致 (IntentRecognizer 主意图相同) → 才粘性;
  两门都过仍错粘 → 记 negative route record (失败链路自纠)。
- 阈值确定法 (跑测数据驱动): 用 explore_cases 语义近对/远对各 20 组实测 bge 余弦分布,
  取分离点 (目标: 近对 ≥0.8, 远对 ≤0.6 — 实测后定, 不拍脑袋)。
### 2.3 有效性验收 (用户钦定: 打点跑测得数据后验证)
- **正向**: 同构题组 (N04 家族) 第2问 sticky_route_hit ≥1 且 首选模型=第1问成功模型;
- **反向 (假阳性防线)**: 形近意远题 (如"总结 https://a.com" vs "总结 https://b.com" — 不同 URL
  = 不同任务!) 不得粘 (指纹护栏: URL/路径差异 → 不算相似);
- **收敛**: 同题 3 次, 路由决策一致 (CV=0); 粘性命中率健康带 10-40% (全粘=阈值过低, 零粘=过高);
- **KPI**: 粘性路由请求的失败率 < 非粘性请求失败率 (真实对比 — route 打点分组统计)。

## 三、打点族 (ledger 新维度 route_stickiness_index)
| 打点 | 键 | 用途 |
|---|---|---|
| fallback_attempt | from/to/n/verify_ok/ms | 兜底链逐个尝试分布 |
| route_record_write | outcome/model | 成功/失败记录写入率 |
| sticky_route_hit | sim/model/意图一致 | 粘性命中 (阈值校准数据) |
| sticky_route_avoid | sim/model | 已知失败模型跳过 |
| sticky_route_fp | sim/意图 | 假阳性 (错粘) — 验收反向样本 |

## 四、实施里程碑
- F1: fallback config + 逐个兜底+校验 (Router 改造, 单测 mock 序列)。
- F2: RouteRecord 写入/读取 + 双门相似判定 (bge+意图) + 阈值实测校准 (20+20 对)。
- F3: 集成批测 (T-R01 同构粘性正样本 / T-R02 形近意远负样本 / T-R03 全败兜底链) + A/B 对比。
- F4: 数据分析报告 (命中率/假阳性率/失败率对比) → 判定有效性 → 用户汇报。

## 五、排除项
- 不做跨机共享路由记忆 (本机 RAG)。
- 不在兜底校验中跑 LLM 二次判定 (成本) — 校验是规则性的。
- 手动 /model 优先级不被粘性覆盖。
