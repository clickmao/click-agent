# v0.14.0 思考链迭代 — 输出后自审/自优化回路 (开发计划, R317 立项, 用户钦定主题)

## 问题定义 (用户实证)

LLM 输出代码中存在"初级程序员都能优化"的反模式, 例: `foreach (var input in new[] { g.N[id].In0, g.N[id].In1 })`
— 用堆分配 `new[]` 取两个栈上字段, 语义为"取值稳定"但引入 GC 增长; 正确写法是 `ref var` + 显式双操作数
(用户提供的真实案例)。此类缺陷无法简单回溯成因 (上下文/偏好/采样综合), 只能靠**输出后审查捕获**。
同样问题覆盖日常/学术等一切有逻辑性要求的输出。

## 现状代码事实 (v0.13.3, 带行号)

- 思考链 = **探索链** (`IndustrialAgentV2.RunThinkChainAsync` L108): URL/目录种子 → `ExplorationPlanner`
  → `HostExploreExecutor` 执行 (≤4 步/4s 预算) → digest 注入。**只有"事前探索", 没有"事后自审"。**
- LLM 返回后管线: `_segmentRouter.ProcessAsync` (L~852/L921) → L1/L3 牵引追加 → `AddToSessionAsync`。
  区段路由只做格式分节, 不做质量审查。
- 打点: `think_chain` / `thinking_end` (L835) — 无质量维度。
- 项目已有可复用资产: `InjectedInstructionClassifier` (规则分类器, AOT 安全) /
  `CompressionBreaker` (熔断模式) / 打点→批测→KPI 闭环 (5 KPI 钦定)。

## 工业方案对照 (调研结论)

| 方案 | 机制 | 适配判断 |
|---|---|---|
| Self-Refine (NeurIPS'23) | LLM 自审 → 自反馈 → 重写, 迭代至停 | 纯 LLM 自审, 无确定性锚, AOT 下 token 成本×2~3, **不单独采用** |
| Reflexion | 失败后反思入记忆, 下次生成时注入 | 需要明确失败信号; 与本项目 think-memory 兼容, **作二期** |
| Static-Analysis-as-Feedback (arXiv 2508.14419) | 编译器/linter/静态检查结果回灌 LLM 修复 | **确定性锚 + 零额外 LLM 自审**, 与 AOT/无模拟铁律最契合, **主线** |
| Generative Compilation (arXiv 2607.13921) | 生成时编译器实时反馈 | 需流式解码钩子, 当前管线不满足, **远期** |
| Agents4PLC / 测试反馈 | 生成→测试→修复闭环 | 测试资产不全的领域难复制, 作案例参考 |

**主线决策**: 反模式捕获靠**确定性规则检查器** (CompilePass 层思路的移植), 不靠 LLM 逼自己发现自己的问题 —
用户例中 `new[]` 双操作数模式, 一条 30 行的规则分析器 100% 可捕获且零 token; LLM 只负责"已知缺陷修法注入"
(把 R0071 类已转正修法作为少样本提示常驻), 这与"提示与核心主题衔接"的 L1 牵引同一哲学: 规则锚定, 不赌模型自觉。

## 失败定义 (用户纠正 2026-09-09 — 核心修正)

用户实证案例在编译器下**完全合法**, 不构成任何工具意义上的"失败"。因此 Reflexion 式"失败后反思"不能以
编译器/测试结果为锚。可用的失败信号只有三类, 强度递减:

1. **度量差 (最硬)**: 领域可度量维度上的负差 — 内存分配量/GC 频次/执行时间/token 成本/评测 rel 分。
   `new[]` 案例在 alloc 度量下可自动捕获 (合法但 alloc>0 且可零分配改写 → 记为"可改进")。
   适用边界: 只覆盖有度量的领域。
2. **评审反馈显式化 (最普适)**: 用户/评审人指出"这里不合理" → 该样本转正为 (反模式 → 修法) 对,
   入修法记忆。R0071 案例即此路径: 人发现 → 人给出修法 → 固化。这是**稀疏但零噪声**的信号,
   工业实践 (代码评审/Grammarly 式反馈) 均为此形态。
3. **规则外推 (最弱)**: 从已确认修法归纳出可静态检测的模式族 (T1 规则表), 检测器命中只提示、
   不定论为失败 — 命中≠错误, 是"已知改进点提醒"。

**结论**: "合法但次优"输出不存在全自动闭环 — 工业上成立的形态是 [人审标记 + 度量器] 双信号源喂
修法记忆, 生成时注入常驻少样本, 静态规则做低成本的泛化提醒。本计划按此修正 T2 为主线。

## 设计 (v0.14.0 档位, 修正后)

### T1 规则反模式扫描器 (新组件 `agent.critique/OutputCritic.cs`, AOT 纯静态)

- 触发: LLM 回复含代码块 (```) 时, 零额外 LLM 调用。
- 规则表 (R0 编号, 每条 = 检测 + 修法提示文案; **规则来源 = 评审反馈显式转正**, 见"失败定义"节):
  - R01 堆分配替代取值: `new[] {` / `new List<>{字面≤4项}` + 循环体内 → 建议 ref/局部变量
  - R02 字符串拼接进循环 (`+=` on string in loop) → StringBuilder
  - R03 async void (非事件处理器) → async Task
  - R04 `.Result` / `.Wait()` 混用 await → 全 async 链
  - R05 `catch (Exception) { }` 吞异常 → 至少日志/注释
  - R06 LINQ `Count() > 0` → `Any()`
  - R07 double 比较 `==` → 容差
  - R08 未使用 `using` 声明内 new 大对象 → using 包裹
  - 首批 8 条, 每条带**证据行号** (误报可审计)。
- 输出: 回复尾追加 (与 L1 同点位, SegmentRouter 后): `> ⚠ 自审: R01 new[] 堆分配 (行 N) — 建议 ref/显式变量, 见 R0071 修法`; 打点 `output_critic{rule, line}`。
- 开关: `AGENTFRAMEWORK_OUTPUT_CRITIC=0` 关闭; 默认**只提示不改写** (改写正确性风险高, 与 L1"不改答案本体"同哲学)。

### T2 修法知识注入 (主线, think-memory 复用)

- **信号源**: ①评审反馈 (用户/评审人指出次优点 + 修法 — 人给锚, 零噪声) ②领域度量器 (alloc/tok 差, 有度量域自动化)。
- 流转: 信号 → (反模式描述 + 修法代码) 对 → think-memory 写入 (现有 STJ 持久化, recall 0.9701);
  生成前 recall top-sim 修法作为少样本注入上下文 — 入记忆的是**已确认修法**, 不是 LLM 自产的"反思散文"。
- 这是 Reflexion 的确定性收窄版: 反思内容由人/度量器供给, LLM 只负责检索复用。

## 度量 (5 KPI 对齐)

- 命中率: 每批 quick-12 的 C 系回复 critic 命中数 (打点聚合)。
- 误报率: 抽样人工复核 (每 10 批 audit 制度复用)。
- 回归健康线: critic 上线后批 tok/case 增幅 ≤5% (纯静态扫描, 理论零 LLM 增量)。
- C20 新案 (T1 验收): 构造含 R01/R03 反模式的诱导题, 断言 critic 打点命中 (真断言, R149 标准)。
