## 现状代码事实 (RAGConfig.cs, commit 86a4f13 基线)

- `src/agent.rag/RAGConfig.cs:231-262` `PersistDocument(RAGDocument doc)`:
  - L250 `File.AppendAllText(path, line)` — 每文档 1 行 JSONL 追加;
  - L251-256 **每次 append 后无条件** `File.ReadAllLines(path)` 判 `lines.Length > 512`,
    超限 `File.WriteAllLines(path, lines[^512..])` (保留最新 512 行)。
- 调用点: L360 `IndexAsync` 末尾 (每用户消息/每文档一次, **热**; 对话库逐轮涨)。
- `LoadPersisted()` L184-211: 仅构造时整读一次恢复内存 `_documents`; 召回全走内存
  (L384 `_documents.Values`), **文件读回不是每消息开销** — 裁剪读才是。
- 裁剪语义: 文件 ≤512 行 (追加后即时裁剪), 保留**最新** 512。
- 锁: PersistDocument 无自身锁 (IndexAsync 的 `_lock` 在 L360 调用前已释放) — 既有竞态面,
  非本项引入, 保持最小改动不新增锁。

## 问题量化

- 文件 512 行 ≈ 数百 KB 级 (每行 ≤440ch+向量), 每次 IndexAsync 一次整读; 超过 512 后
  **每消息整读 + 整写** — 恒定但完全浪费的每消息 O(库大小) 文件 IO。
- 增长期 (1→512) 每 append O(n) 读 → 前 512 条消息累计 O(n²) 读。

## 设计 (裁剪摊销)

- 抽常量化: `RagPersistMaxLines = 512` (语义不变), `RagPruneInterval = 64`。
- 计数器: `int _persistAppendsSincePrune` (Interlocked, 无需 init — 首查在 64 次 append 后)。
- PersistDocument: append 后仅当 `Interlocked.Increment(ref _persistAppendsSincePrune) % 64 == 0`
  时执行一次裁剪检查 (整读 + 超限整写保留最新 512), 然后归零。
- 裁剪触发时机变更的语义影响: 文件可在两次裁剪间瞬时达 **512+63 行** (有界松弛);
  每次裁剪终态与逐次裁剪一致 (都保留最新 512) — 追加+保尾裁剪是单调操作, 检查频率只影响
  中间态长度, 不影响裁剪后内容集。重启落在这 63 行窗口内时最多多载 63 文档 (有界, 可接受)。
- 自愈: 文件被外部删除/重建 (eval R81 隔离每轮删 index.jsonl) 后, 计数器最多漂 64 次 append,
  下次裁剪检查整读实测归零/校准 — 无永久漂移。

## 关键约束

- 不改 append 格式与 LoadPersisted 读侧 — 落盘兼容, 老文件直接可读。
- 不新增锁 (避免改竞态面); 仅 Interlocked 计数器。
- 裁剪仍保留**最新** 512 (lines[^512..]) — 方向不变。
- 不动 dedup/分块/召回逻辑。
