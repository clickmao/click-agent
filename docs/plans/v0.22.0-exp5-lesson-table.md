### 1.2 工作目录（L3）**当前不存在显式判定** —— "无工作目录则略过" 这条**现在无法执行**

- `IWorkspace/Workspace.RootPath` 无生产赋值点，`InitializeAsync` 无生产调用 → `RootPath` 恒空，实际靠 cwd 兜底（`./data` 相对 cwd 解析 `[src/agent.host/Program.cs:241]`）。
- **无「是否在某项目内」的分支**（无 `.git`/项目根探测、无工作区白名单）。
- 结论：L3 必须先补一个**显式的工作目录判定器**（见 §3.1），否则"略过"永远不触发，教训表会写到进程 cwd（可能是 `/` 或临时目录）。

### 1.3 前端通知（L5）**目前不可能** —— 有信封、无通路

- `src/agent.frontendapi` 是**纯请求/响应**：accept 循环每连接一线程 `[src/agent.frontendapi/FrontendApiServer.cs:45-57]`，逐行 `resp + "\n"` `[:85-95]`；**无客户端注册表 / 无 Broadcast / 无 Subscribe**。

## 3. 推荐设计（探索结论）

### 3.1 工作目录判定器（先决条件，最小实现）

```
WorkspaceLocator.Resolve(cwd) → { Kind: Project|Bare, Root: string?, Marker: string? }
判定顺序: ① 显式配置 (--workspace / env AGENTFRAMEWORK_WORKSPACE) 
        ② 向上找 .git / *.sln / *.csproj 目录 (首个命中即项目根)
        ③ 均无 → Bare (无工作目录) → 教训表走"略过 + 内存态"
```
- 判定结论要**可观测**（telemetry 点 + `state.snapshot` 字段），否则又变成"隐式行为"。
- 用户"若无工作目录则略过"= 不落盘、不问询、只在内存/TTL 内使用。**必须显式实现，不许靠 cwd 兜底**。

### 3.2 教训表（L1）—— 以 `ExecutorLessonMemory` 为内核补一层统一面

- **不搬迁数据**：新建 `LessonsTable` 作为**统一读面 + 事件源**，三源（ExecutorLessonMemory / FailureClusters / GuardrailMemory）通过**适配器**投影为统一记录，避免大爆炸式迁移。
- 统一记录字段（最小）：
  `{ Id: 稳定指纹(FNV-1a, 复用 R365 算法), Kind: Execution|Failure|Guardrail|Correction, Pattern, Count, FirstSeen, LastSeen, Solution?, Source: 组件名, Scope: Project|Session }`
- 键稳定性铁律：指纹必须**跨进程/跨 locale 稳定**（FNV-1a + 序数排序，R365 已实证踩坑），禁用 `string.GetHashCode()`。
- 落盘：`data/lessons/lessons.json`（STJ 源生成，禁手写 StringBuilder）；写入走**原子写**（tmp+rename，同 `.rbin` 先例）。

### 3.3 API 读取面（L4）

| API | 语义 |
|---|---|
| `lessons.query { since?, kind?, scope?, limit? }` | 拉取（支持增量游标 = 版本号） |
| `lessons.detail { id }` | 单条详情 |
| 域登记 | `meta.info.domains` 增加 `lessons`（当前硬编码 3 域必须改） |
| `state.snapshot` | 增加 `lessons_version`（单调递增，供前端判断"有新教训"） |

### 3.4 前端通知（L5）—— 两条路，建议先做 B

- **方案 A（真推送，P2）**：frontendapi 增加客户端注册表 + `FormatEvent` 广播 + 订阅/游标。改动面大（连接生命周期/背压/断线重连），且与既有 P2 路线图一致。
- **方案 B（推荐先做，零协议破坏）**：复用 `state.snapshot` 的**拉取式**语义 —— 暴露 `lessons_version`，前端轮询到版本变化即拉 `lessons.query?since=`。这与现状架构完全兼容，且"新教训已到达"语义成立（版本号变化 = 到达事件）。
- **方案 C（与既有 `@cmd` 通道打通）**：`@cmd` 已是 agent→前端单向通道，但**不带 req_id/ack**，且未接 `CommandWriter`；可作为"轻提醒"（"有新教训"），细节仍走 query。
- 建议：B 先落地（可验收、低风险），A/C 记为后续（本文档 §8 待确认）。

### 3.5 L2（问询是否在本项目创建）

- 复用 `IUserPromptService` 加一问：`"是否允许在本项目创建教训表 (data/lessons/)? 记住此选择"`；
- 选择要**持久化**（`data/user-choices.json` 或复用既有偏好存储）+ 支持 `--lessons on/off` 覆盖；
- 与 staging 审批链的关系：**审批 = 单次动作授权**，本项 = **长期偏好**，两者不复用同一存储（避免语义混淆）。

## 4. 关键约束

1. **指纹稳定性**：FNV-1a + 序数排序（R365 教训，跨进程/跨 locale）。
2. **零反射 / AOT**：STJ 源生成；禁手写 JSON 拼接（既有 `ExecutorLessonMemory` 属技术债，若扩用需先修）。
3. **原子写**：教训表落盘 tmp+rename。
4. **诚实边界**：教训"命中"必须绑真实事件（真实失败/真实纠正），不许 LLM 自述"我学到了"就记一条。
5. **隐私**：`ContextTail` 类字段截断上限（既有 `count>=8` 才补 `[:37-38]` 的设计保留），且不外发原始对话。
6. **零 shell**：不涉及。

## 5. 验收标准

| # | 断言 |
|---|---|
| A1 | 同一 pattern 出现 3 次 → 表内 1 条记录 `Count=3`（去重成立），第 4 次命中 `Solution` 升级 |
| A2 | 进程重启后指纹不漂移（同 pattern 命中同一条）—— 跨进程用例锁死（R365 同类回归） |
| A3 | `LessonsTable` 写入成功 → `lessons_version` 自增，`lessons.query?since=` 能拉到增量 |
| A4 | 在 `Bare`（无工作目录）下：**不落盘、不问询**，且判定结论可在 telemetry/snapshot 看到 |
| A5 | 用户拒绝"在本项目创建"后，重启仍不复建（偏好持久化） |
| A6 | 前端侧：轮询 `state.snapshot.lessons_version` 变化 → `lessons.query` 得到新条目（端到端脚本证据） |
| A7 | 全量测试绿 + AOT 0 IL 警告 |
