## 4. 实现
- `SessionHistorySearch.cs:98`：`score += Idf(t) * TfSat(d.Tf.TryGetValue(t, out var tf) ? tf : 1);`
- `SessionHistorySearch.cs:219`：`internal static double TfSat(int tf) => 1.0 + Math.Log(tf < 1 ? 1 : tf);`
  - 因子 **≥1**（tf≥1）⇒ 每项不小于 R422 口径 ⇒ **分数符号不变 ⇒ 命中集合可证不变**（C1）；
  - 单调不减 + 对数饱和（相对增益递减，次线性）⇒ 高频不会无界碾压；
  - 可解析对账：单词元查询下 `分数(带频次)/分数(无频次) == 1+ln(tf)`（C3/C4 的闭式）。
- `SessionHistorySearch.cs:203`：`CountTokens`（词元→出现次数）；**单一真源**：`:75-76` 词元集合由计数键派生（`new HashSet<string>(tf.Keys)`）⇒ 集合与频次不可能口径分叉。
- 单测（`SessionHistorySearchTests.cs:359-485`，+5 条）：等长分档 + 闭式比值；**边界并列**（断言不可分，非缺陷）；命中集/极性成对不变量；饱和性质 + 计数单一真源；**冻结语料特征向量机检钉死**（真实存储 Load + BuildDocument + CountTokens）。
- 零参数、零配置、零 LLM、确定性排序不变（并列处仍退化为 sessionId Ordinal 序）。

## 6. 预测输入纠错（首跑 C4 红，已归档不复跑覆盖）
- 归档：`eval/capability/r423/verdict-r423-run1-predictor-error.json`（`verdict=FAIL`, `pre_registered_failures=[C4]`）。
- 红因：**预测输入错**，不是实现错——首版 `tf(存在)` 由**人工复算**得 2（只读了 `LongTermMemory` 段，漏了
  `GoalText`/`Milestones` 段，而 `BuildDocument` 会把它们拼进文档）⇒ 真值 4。
  独立佐证：首跑实测隐含 tf = `exp(0.1408/0.059 - 1) ≈ 4.000` ⇒ 实现符合闭式。
- 处置（判据结构未改、阈值未放宽）：① 预检数字改为**机检取得**（单测 `R423_FrozenCorpus_FeatureVector_IsMachinePinned_NotHandCounted`
  经真实存储 + 文档构建 + 真实分词器算出 90/4 并钉死）；② harness 的预测输入改为引用同组钉死值（`:53-59`）；
  ③ 新增 C4 的"实测隐含 tf == 钉死值"两源一致子判据。**人工复算在本轮被证明不可靠**（见 §8 教训）。

## 7. 语料目录污染事故（C0 的由来）
- 现象：`eval/capability/r422/fixture-sessions/` 内出现空子目录 `sessions/`（harness 首跑时 `IsADirectoryError` 暴露）。
- 根因：`src/agent/session/SessionMemoryStore.cs:19-20` 构造即 `Directory.CreateDirectory(Path.Combine(dataStoragePath,"sessions"))`
  ⇒ 某次以**冻结语料目录本身**为 `dataStoragePath` 构造存储的实现路径，就地建出 `sessions/` 子目录。
- 影响与处置：三份语料 **sha256 逐字节未变**（== R421 登记），污染仅为空目录 ⇒ `rmdir` 清除；
  harness 加固：`fixture_digest`/拷贝只取**文件**，并新增 **C0**（条目集纯净机检）。
- 诚实边界：该事故由**实现探索过程中的调用方式**造成（非产品缺陷），已按事故入档，不写进能力宣称。
