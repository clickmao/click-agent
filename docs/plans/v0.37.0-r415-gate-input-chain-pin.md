# v0.37.0 · R415 — 链级钉死「前置门入参 = 用户本轮原文」

**主题**: 把 R413 的「门入参」防线从**源码级**升级为**行为级、端到端**（外部真值）。

## 1. 为什么做

R413 的前置门（本地 r1 判真假 ⇒ 跳过无新增轮的主调用）实测 -33.3% 调用 / -58.5% tok。
但该增益曾经**归零**过一次，第三个空心根因是：门吃 `prompt.UserMessage`（已追加 role/知识块/回注块）
而不是 `message.Content`（用户本轮原文）⇒ 门恒 Pass。当时唯一的防线是 `G29`：**扫源码字面量**。
源码级钉死挡不住「换个变量 / 绕一层 helper / 中间寄存一次」的等价回退；且它无法证明**装配后**的门真的拿到了原文。

## 2. 做了什么（不改产品代码）

新增 harness `eval/rover/r415/`，把本地后端换成**确定性假实现**（`fake_llama.py` 模拟 llama-server 的
`/health /props /apply-template /tokenize /completion`：待判原文含「谢谢」⇒ S，否则 P），
链侧完全真实：真 `agenthost --frontend-api`、真 DI 装配、真 `ModelQueueRouter`、真 `LlamaCppLocalGenerationPort`、
真进程 + HTTP（零 P/Invoke）。判别力靠**知识提示型技能**注入哨兵：`skills/r415-gate-pin/SKILL.md`
（`type: knowledge_hint`，关键词 `收到/谢谢`）命中后其 body 会作为 `[技能知识参考]` 尾挂到 `prompt.UserMessage`
（`IndustrialAgentV2.cs:1200`）⇒ 该轮 `prompt.UserMessage != message.Content`，门若吃错变量立刻可辨。
