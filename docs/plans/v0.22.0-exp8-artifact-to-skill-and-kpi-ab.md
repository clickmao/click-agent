# v0.22.0 探索项 8：已验证产物 → skill 蒸馏 + skill 生命周期 + KPI A/B（tokens/轮数）

> 用户原话（R371，逐字）：「真跑 agent 产出的 artifact 自测 时记得将可复用的模块做成skill放在skills内，
> 并且可以允许对已有skill进行优化、删除、更名等操作（注意所有代码类型的必须为通用形式），
> 一切以KPI（tokens\用户回答频率不能高\回复质量，同一个问题优化前后需要多少tokens和多少轮）和通过上下文自检为要目的」

## 0. 拆解（4 个子能力 + 1 条铁律）

| # | 子能力 | 要点 |
|---|---|---|
| S1 | **产物 → skill 蒸馏** | 真跑（自测通过）的 artifact 中，**可复用的模块**沉淀为 `skills/` 内的 skill |
| S2 | **skill 生命周期** | 对已有 skill 支持 **优化 / 删除 / 更名**（不是只能加载） |
| S3 | **通用性铁律** | 「所有代码类型的必须为通用形式」—— 代码型 skill 不得写死某语言/工具/项目专名（复用 exp5 的通用化机检） |
| S4 | **KPI 驱动 + 上下文自检** | 同一问题**优化前后**的 tokens、**轮数**、用户回答频率（不得升高）、回复质量对比；并以"通过上下文自检"为目的 |

## 1. 现状代码事实

1. **skill 只读加载**：`src/agent.skills/SkillPackageLoader.cs` 只有加载/匹配；
   `skills/<id>/SKILL.md` 由人工/开发轮次写入 → **无 create/update/rename/delete API**。
2. **产物与 skill 完全脱节**：`PythonArtifactPlugin`（R368/R371）只做「落盘 + py_compile + 可选运行」，
   产物停在 `data/artifacts/`，**没有任何"抽取可复用模块 → skill"的通路**。
3. **KPI 有探针无 A/B 口径**：`eval/kpi/kpi_probe.py` 统计 token 成本/召回/规模，但**没有"同一问题优化前后 tokens/轮数"的对比机制**；
   `eval/results/*.json` 有 per-case token 字段可作数据源。
4. **通用化机检已存在可复用**：`src/agent.roles/LessonGeneralization.cs`（R370）—— 黑名单词表 + 词法边界；
   代码型 skill 的通用性判据可直接复用（**角色与技能共用同一判据，避免两套标准**）。
5. **上下文自检**：`docs/验证形式规范.md`（R370）已定义证据阶梯；skill 变更后的"自检"应产出 L2 机检 + L3 真跑证据。

## 2. 缺口清单

- G1 无 skill 写面（S2）→ 必须先有**受控写 API**，否则 S1 无从落地。
- G2 无"可复用性"判据（S1）→ 需要机检：通用形式 + 无项目/语言专名 + 自测通过 + 最小可用。
- G3 无 A/B KPI 口径（S4）→ 需要"同题对照"执行器 + 对比报告。
- G4 无 skill 变更审计/回滚（S2）→ 更名/删除必须可追溯（与 `.rbin` 原子写/版本先例一致）。

## 3. 推荐设计（待用户确认后开发）

### 3.1 skill 生命周期 API（S2，建议归属 skills 模块）

- `SkillRegistry.Create/Update/Rename/Delete(id, content?, newId?)`：
  - 落盘仅限 `skills/` 根（路径逃逸机检：拒绝 `..`、绝对路径、symlink）；
  - **原子写**（tmp + rename）+ `skills/.history/<id>/<rev>.md` 审计快照（可回滚）；
  - **禁止静默覆盖**：update 必须携带"变更理由 + 优化前后 KPI"（见 3.3）。
- 更名：目录 + frontmatter `name` 同步；旧名保留 1 个 rev 的转发索引（避免既有引用断链）。

### 3.2 artifact → skill 蒸馏（S1）

判据（全过才允许沉淀，缺一不可）：
1. 产物**真跑自测通过**（`Ran && ExitCode==0`；L3 证据）；
2. **通用性机检通过**（复用 `LessonGeneralization`：无语言/工具/扩展名专名；项目专名同样拒绝）；
3. **可复用性机检**：不含项目内路径/项目实体名；输入输出以参数/标准输入输出表达；
4. 幂等：以内容指纹（FNV-1a，与教训表同算法）去重，同指纹不重复建 skill。

产出形态：`skills/<id>/SKILL.md`（触发条件 + 用法 + 边界 + 验证方式）+（可选）`skills/<id>/templates/`。

### 3.3 KPI A/B 口径（S4，用户钦定）

| 指标 | 口径 | 数据源 |
|---|---|---|
| tokens/问题 | `prompt_tokens + completion_tokens`（同题同模型） | `data/telemetry/host.jsonl` |
| **轮数/问题** | 达成同一验收所需的 LLM 轮数（含重试；`llm_call` 计数） | 同上 |
| 用户回答频率 | `loop_turn.asked` 的比例（**不得升高**，优化不得靠"多问用户"换质量） | 同上 |
| 回复质量 | 机器可验代理：自测通过率 / 断言条数 / 编译通过率（L≥2 证据） | 产物台账 + 机检 |

- **同题对照**：同一提示词 + 同一模型 + 同一环境，优化前后各跑 N 次（N≥3），报告 `tokens 中位/轮数中位/asked 率/质量`；
- 结论纪律：**token 或轮数上升而质量无提升 = 优化失败**（回退，与"打分<上版即回退"同精神）。

### 3.4 上下文自检（S4 目的）

skill 每次变更后自动跑：
1. 加载校验（frontmatter/结构/触发词）；
2. 触发匹配回归（不应误触发到无关意图）；
3. KPI 回归（3.3 对照表）→ 附在变更记录里，作为"这次改动值不值"的判据。

## 4. 关键约束

1. AOT 0 IL 警告；STJ 源生成；禁反射；零 shell（`ArgumentList` 直连）。
2. **代码型 skill 必须通用形式**（复用通用化机检；项目专名、语言/工具专名一律拒绝）。
3. 凭据卫生：skill 内容不得含 token/key（机检扫描 + 复用 `scripts/check-token-residue.sh` 思路）。
4. 删除必须可回滚（历史快照）；不做不可逆操作。

## 5. 验收标准（机检草案）

| # | 断言 |
|---|---|
| A1 | `Create/Rename/Delete` 往返成功；路径逃逸用例被拒；历史快照可回滚 |
| A2 | 含语言/工具专名的产物**拒绝**沉淀为 skill（负向控制：通用形式用例通过） |
| A3 | 真跑失败（exit≠0）的产物**拒绝**沉淀 |
| A4 | 同内容二次沉淀幂等（1 个 skill，不重复建） |
| A5 | A/B 报告字段完整（tokens 中位/轮数中位/asked 率/质量），且**asked 率升高时判为失败** |
| A6 | 全量测试绿 + AOT 0 IL 警告 |

## 6. 排除项

- 不做"自动联网找 skill"；不做跨机同步；不做 skill 市场。
- 不把 artifact 本体直接塞进 skills（只沉淀**通用化后的模块**）。

## 7. 待确认（开发前回答）

1. skill 写 API 归属：`agent.skills` 模块内（推荐）还是 role 模块（教训表已归 role，skill 是全局能力 → 建议 skills 模块）。
2. "可复用模块"粒度：整文件级（推荐，先做）还是函数级（需 AST，成本高）。
3. A/B 的 N 与预算：本机 2 vCPU，N≥3 每轮约 3×2 次 LLM 调用（可接受）。
