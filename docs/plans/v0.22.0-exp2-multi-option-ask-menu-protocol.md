## 3. 协议缺口分级（P0 = 不做则功能不可能成立）

### P0（menu 功能的前提）
1. **前端 ask 通路整体未接线**：无 `ask.reply` / `ask.cancel` 路由（[src/agent.host/Program.cs:274-306]、[src/agent.frontendapi/FrontendApiServer.cs:162-175]、[src/agent.frontendapi/FrontendApiChatRouter.cs:23-55]）；无 `IUserPromptService` 前端替换（DI 恒 Console [ServiceCollectionExtensions.cs:158]）；`FrontendPromptService` 无构造点、`emitEvent` 无提供者 [FrontendPromptService.cs:16,29]。
2. **`ask` 不成信封**：`{ev,ask_id,service,purpose,questions[]}` 缺 `v`（协议版本）、`type:"event"`、事件名、`req_id` [FrontendPromptService.cs:51-61 vs FrontendApiContract.cs:70-84] ⇒ 前端无法复用既有解析器、协议无法版本化演进。
3. **选项与数据类型在通道中丢失**：`CredentialItem` 缺 `Choices/DataType/MultiSelect/Default*` [PromptOrigin.cs:105-118]；`ask` 事件缺 `options[]` [FrontendPromptService.cs:57-60] ⇒ **前端无法渲染菜单**。

### P1（可用性/正确性硬缺口）
4. **无超时字段与超时上报**：deadline 固定 300s 且前端不可知 [FrontendPromptService.cs:29]；无 `timed_out` 事件/错误码。
5. **无显式取消协议**：只能靠 `answers=null` 隐式表达 [FrontendPromptService.cs:90-100]。
6. **无幂等/重放**：覆盖式丢弃 [FrontendPromptService.cs:26,46]；客户端重连/重发无定义 [FrontendApiServer.cs:131-150]。
7. **选择约束缺失**：`min_select/max_select`、默认勾选、`multi` 标志全无 [PromptDataType.cs:123-136]。

### P2（规范性/可观测）
8. **错误码不全**：`conflict` 只在注释 [FrontendApiContract.cs:12,20-23]；`busy` 硬编码 [FrontendApiServer.cs:83-84]；缺 `ask_not_found` / `cancelled`。
9. **数据模型双轨未统一**：栈 A 与栈 B 并存（§1）。
10. **关联不闭环**：ask 层无 `req_id` 贯通审计 [PromptAuditEntry.cs:6-24]。
11. **文档-实现不符（须同步）**：
    - `docs/api.md` §24（[:1027-1035]）三条与 [PromptPersistence.cs:145-159] 不一致：代码只判 `!Items.Any(Sensitive)`、**完全不查 Authority**；`CredentialItem` 无 Authority 字段 [PromptOrigin.cs:105-118]；`ClarificationItem.Authority` 打包时被丢弃 [ClarificationBatch.cs:65-84] ⇒ 文档所写「MainAgentAllowed 问询」**在实现里不可表达**。
    - `SilentInterAgent` **无任何赋值点**（无 env / 无 config / `data/` 无 silent 项）[PromptOrigin.cs:229]、[PromptPersistence.cs:116]、[FrontendPromptService.cs:37] ⇒ 文档示例开关**运行中不可达**。

    - 静默 = 回空串 [:149] → 批量校验「输入为空」→ **重问到耗尽（实为 3 次重问后放弃）** [ClarificationBatch.cs:106-136]，文档未提。

## 4. 推荐设计

### 4.1 信封统一（P0-2）
`ask` 事件改为复用既有信封：`{v:1, type:"event", event:"ask_reach", req_id, ask_id, service, purpose, deadline_ms, questions:[...]}`。**不新造解析器**，直接复用 [FrontendApiContract.cs:70-84]。

### 4.2 menu 载荷（P0-3）
```
questions:[{ key, display, data_type:"choice|multi_choice|text",
             required, sensitive, default_value, suggested_values[],
             multi, min_select, max_select,
             options:[{ id, label, description, recommended }] }]
```
字段来源全部是**已存在但被传输层丢弃**的模型字段（§2），不是新概念。

### 4.3 路由与回填（P0-1 / M3）
- 新增 `ask.reply{ask_id, answers[], idempotency_key}` → `FrontendPromptService.TryComplete` [:91-100]；`ask.cancel{ask_id, reason}` → `PromptAnswerSource.Denied`。
- DI 增加前端实现切换（与 `--frontend-api` 启动开关同源；[ServiceCollectionExtensions.cs:158] 目前恒 Console）。
- **选择回填后继续**：`ClarificationBatch` 保持现有「批量打包 → 逐个校验 → 耗尽重问」结构 [ClarificationBatch.cs:106-136]，仅在传输层补全字段与状态码；**不改主链语义**。

### 4.4 超时/取消/幂等（P1）
- 请求侧 `deadline_ms`，事件侧 `status:"timeout"`；`PromptAnswerSource.Timeout` 补产生点 [PromptOrigin.cs:59]。
- `ask_id` 已答缓存（内存 LRU，容量与淘汰照抄 `SkillLifecycle` [src/agent.skills/SkillLifecycle.cs:39,184-195]）→ 重放返回同一结果。
- 单槽 `pending` → **按 `ask_id` 索引的字典**（现状单槽会静默丢弃并发问询 [FrontendPromptService.cs:26]）。

### 4.5 触发判定（M1）
现状已有可用触发源：`EvidenceGate` 已产出 Choice 问询 [src/agent/registry/EvidenceGate.cs:134-156]、`ClarificationService` 已做打包。**建议不新增 LLM 侧「我要问」协议**，而是在现有证据门/澄清批上补一个「≥2 个等价候选方案且置信度差 < ε → 升级为 Choice 问询」规则（0 额外 token 的 L1 判定），**待确认**（§8-Q2）。

### 4.6 文档同步（P2-11）
本项落地时必须同批修正 `docs/api.md` §24 与 `docs/plans/v0.19.0-frontend-api-plan.md` 的形状差异（3 处），否则重演「文档过度承诺」。

## 5. 关键约束

1. **协议向后兼容**：新增字段可缺省；`v` 字段必须首个可用版本就位（否则日后无法演进）。
2. **AOT**：事件与 DTO 全部 STJ Source Generator；无反射序列化。
3. **主链不改语义**：问询仍是「批量打包 + 校验 + 重问耗尽」；本项只补传输层字段与路由。
4. **前端 DEMO 必须真机验证**（先例：`samples/FrontendApi.WinForms`，R367），不接受「单测通过即宣称可用」。
5. **凭据类问询永不走菜单化静默**（`Sensitive` 恒问真人）——与 §24 的意图一致，但实现需补 Authority 判定（P2-11）。
