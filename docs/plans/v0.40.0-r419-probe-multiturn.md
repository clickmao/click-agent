# R419 计划 · 探针多轮化：把「轮数 / 首次通过率」从恒等判据变成可分化判据

状态: 已立案（待执行；下一步 = §2 的决定性微实验）

> 恢复指针。R418 已收口（`v0.39.0-r418-process-kpi.md`，HEAD `1f44c8b`）。

## 1. 目标（为什么）

R418 已把「过程/成本」维度落成仪器（`eval/probe/process_metrics.py`），但**探针只有单轮**：
`solve_agent`（`eval/probe/run_probe.py:430`）每题只跑一次 `agenthost -q <prompt>`，
判分单元也只有一次提交 ⇒ 「轮数恒为 1」「首次通过率 ≡ 整题全对率」（R418 诚实边界②）。
用户 KPI 口径是「每题 tokens / **轮数** / **首次通过率**」⇒ 必须先让**轮数**能分化。

## 2. 侦察事实（已验证，勿凭印象改）

- `eval/probe/run_probe.py:430-447`：`solve_agent` 一次性调用，命令 =
  `agenthost -q <prompt> --output-mode text --session-id probe-<ts>-<tid>`；**每题独立进程**。
- 探针归档回复（`data/probe/replies/agents<seed>-*.txt`）是 CLI 转录，含
  `── 执行中 (turn 1) ──` + `prompt 构建完成: ~N tokens` ⇒ 现有提取器能读 turn 与 prompt 侧 token。
- `eval/rover/r413/drive_task.py`（95 行）**已经在做多轮**：TCP `{"v":1,"type":"req","api":"chat.send"}`
  逐轮发 `TASK["turns"]`（`eval/rover/r413/task.json` 为 8 轮脚本），逐轮落 `turns-*.jsonl`
  （`turn/text/reply/ok/secs/events`）；远端调用数取自桩侧 `calls-*.jsonl`（外部真值）。
- 该多轮 harness 的 `ok` 是**传输层**成功（桩恒应答 ⇒ 恒 true）⇒ **不能**当质量/首次通过率用。
  质量必须来自**判定器**（`eval/probe/grade.py`）。

## 3. 待确认（下一步第一步，决定性微实验）

**Q：同一 `--session-id` 跨两次进程调用，链是否续上下文？**

- 做法：连跑两次 `agenthost -q`（同 sid）：①「记住数字 4271」②「我刚才让你记住什么？」
  判据：②的回复出现 `4271` ⇒ 续上下文成立；否则不成立。
- 若成立 ⇒ 多轮探针可用「两进程同 sid」实现（改动最小，复用现有 harness）。
- 若不成立 ⇒ 改走 `eval/rover/r413/drive_task.py` 的 TCP 路径驱动探针题（多轮在同连接内），
  并把回复转录落到 `data/probe/replies/`（沿用 R418 命名空间 `agents<seed>-<tid>-t<N>.txt`）。

## 4. 设计（待 §3 结论后定形）

1. **多轮题面**：给每个 `json_mini`/`topo_min` 题加一条**修正轮**（turn 2），文案取自该题的
   `tight_gen` 隐藏用例（例：「用例 X 你判错了，只重发修正后的完整程序」）。
2. **判分单元不变**：仍是**整题全对**；turn 1 全对 ⇒ 首次通过；turn 2 才全对 ⇒ 记「修复成功」。
3. **KPI 三元组**（对齐用户口径）：
   - `tokens/题` = Σ(每轮 `prompt 构建完成: ~N tokens`)（prompt 侧，链不落 completion 侧）；
   - `轮数` = 实际发送轮数（`turn N` 最大值，缺记 `n/a`）；
   - `首次通过率` = `turn1 整题全对` / 题数；另列 `修复率` = `turn2 修复成功` / `turn1 未过题数`。
4. **仪器扩展**：`eval/probe/process_metrics.py` 增 `--multiturn`：
   逐 `-t<N>.txt` 归档聚合（同一 `reply_ns` 前缀 = 同一题的多轮），缺轮/歧义照旧记 `n/a` 不猜。
5. **成对负控（必做）**：① 注入「turn 2 也故意不回修正」的缺陷解 ⇒ `修复率` 必须为 0；
   ② 正控：oracle 多轮满分 ⇒ 修复率 1.0。无正控时仪器错与「题太难」不可区分（R415 教训）。

判据（预注册）：多轮后在**同一题集**上必须出现 `轮数=2` 且 `首次通过率 < 整题全对率(两轮合并)`；
若两值仍恒等（例：所有题 turn1 就全对）⇒ 判「题集对本轮目标仍饱和」，记入诚实边界并换更紧的题。

## 6. 约束与铁律（继承）

- 质量只取**判定器产物**；过程只取**归档原文**；外部真值优先于被测代码自报计数器。
- `n/a ≠ 0`；`n/a` 剔除均值分母；歧义不猜（R418 归属铁律）。
- 免问询令生效；推送暂停令生效（只本地提交）。
- 测量期间不做吃 CPU 的活；长跑用 `background=true` + `notify=true`。
