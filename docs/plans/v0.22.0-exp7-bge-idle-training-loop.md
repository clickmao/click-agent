# exp7 — bge-small-zh-v1.5 闲时训练闭环（确定性召回率驱动）

- 状态：探索中（设计成稿，R370）
- 载体：`eval/bge/`（数据/训练/评测）+ `scripts/bge_idle_train.sh`（闲时调度）
- 目标函数：**确定性召回率**（冻结语料 + 冻结查询 + 冻结指标，逐版本可比）
- 上位约束：不换基座（用户钦定 bge-small-zh-v1.5）；AOT 形态不变；零 shell；CPU-only（2 vCPU / 3.6 GiB）

---

## 1. 为什么需要"确定性召回率"

R369 之前用 10 条 query 的硬集定选型 → 1 条 query = 0.1 分辨率，属**噪声内**，不足以支撑选择，更不能支撑"版本择优"。
任何"训练→择优"闭环都必须有一个**不随版本漂移的裁判**，否则择优退化为自我欺骗。

**目标函数定义（冻结件）**

| 冻结项 | 内容 | 位置 |
|---|---|---|
| 语料 | 1299 块（src/**/*.cs 908 + docs/**/*.md 391），384 个不同文件，块长 ~480 字符 | `/tmp/embbench/recall/corpus.jsonl` → 归档 `eval/bge/fixtures/corpus.jsonl` |
| 查询 | 120 条中文自然提问，LLM 出题，**禁止复述标识符**（防词法捷径），金标准块已知 | `eval/bge/fixtures/queries.jsonl` |
| 指标 | recall@1 / @5 / @10 / @20 / MRR@10 / 中位排名 / 平均排名 | `eval/bge/eval_recall.py` |
| 基线 | 字符二元组 Jaccard 词法基线（证明语义模型是否真赢词法） | 同上 |
| 分辨率 | 1 条 query = 0.83pt；≥3 条（2.5pt）才称"提升"，≥6 条（5pt）才称"显著" | 本文件 §5 判据 |

**确定性三要素**：语料文件固定、查询文件固定、评测脚本固定 —— 同一模型权重（含 adapter）任意次重跑必须得到同一分数（浮点容差 1e-6）。任何对冻结件的修改都要**新建版本号**（`corpus_version`），旧分保留。

## 2. 数据来源与采集（真实数据优先）

| 源 | 现状实测 | 采集方式 | 可扩展性 |
|---|---|---|---|
| A. LLM 出题（块→问） | 已验证：1299 块语料可无限出题 | `collect_pairs.py --gen`：对**与评测金标准不相交**的块出题 | 高（受 LLM 配额限制） |
| B. 运行期真实查询 | 514 轮 × 4406 case → **唯一 query 仅 59 条** | 收割 `eval/results/*.json` 的 `input` | 低（套件复用） |
| C. 运行期真实检索文本 | **拿不到**：`snippets` 只记数量、`sources_recall` 只记 `源:Nsnip/tok/rel` 摘要 | ← 需新增落盘（§2.1） | 高（这是长期主源） |
| D. RAG 会话记忆 | `data/rag/index.jsonl` 仅 4 行 | 直接读 | 中（随使用增长） |
| E. 自挖掘伪正例 | 未启用 | 当前模型 top1 + LLM 复核（闲时做） | 高，但含噪（须 LLM 复核才入库） |

### 2.1 长期主源（本轮提出，需用户裁定后实施）
在检索路径落盘 `data/bge/retrieval_log.jsonl`：
`{ts, query_sha8, query, source, snippet_id, snippet_sha8, rank, score, used_in_prompt}` —— 文本落盘仅限本地（产品本就本地）；`used_in_prompt=true` 且其后回复通过验收 → 自动成为**弱正例**。这是把"真实使用"变成训练数据的唯一诚实通道。

### 2.2 训练/评测隔离（防作弊）
- 评测金标准块集合 `G_eval`（120 块）**永久排除**在训练正例之外；
- 训练正例来自剩余块池，负例从全语料挖掘（含 `G_eval` 块——负例用评测块无害，且更接近真实干扰）；
- `collect_pairs.py` 强制机检：`assert not (train_gold ∩ G_eval)`。

## 3. 训练阶梯（本机可行度分档）

| 阶段 | 方法 | 本机可行性 | 产出物 | 状态 |
|---|---|---|---|---|
| T1 | **后处理适配器**：均值中心化 + PCA 白化（无监督），可选监督低秩映射 `W = argmin‖WQ−P‖²+λ‖W‖²`（岭回归，闭式解） | ✅ 秒级~分钟级（d=512，纯 CPU，无 numpy/torch） | `data/bge/versions/vN/adapter.bin` | **本轮实施** |
| T2 | 部分微调：冻结 3 层，仅训练最后 1 层 + 池化层（需自研 BERT 反向传播） | ⚠️ 重（自研难度大，2 vCPU 每步 ~百 ms） | `vN/layer4.delta` | 待定（工作量评估后立案） |
| T3 | 全参微调（12→4 层 24M 参数） | ❌ 本机无 torch/GPU，不做 | — | 仅文档记录 |

**诚实边界**：T1 是**合法但有限**的优化（不改变基座权重，只改"表示空间"）。它能带来确定性召回提升就采纳；不能提升就如实记"vN 回退"。T2/T3 不夸大。

## 4. 闲时调度（用户钦定：本机无任务才跑）

`scripts/bge_idle_train.sh` 判定"闲时"（全部满足才启动）：
1. `/proc/loadavg` 1 分钟负载 < **1.0**（2 vCPU 的一半）；
2. 无 `run_round|round_autopilot|dotnet build|llama-server|run_recall|gen_queries` 进程；
3. `MemAvailable` ≥ **1200 MB**；
4. 无 `data/bge/.train.lock`（flock 防重入）。

闲时动作序：`collect_pairs.py --gen --budget 300s` → 若新增训练对 ≥ **32** → `train_adapter.py` → 过 §5 闸门 → 写版本 + 小报；否则仅落数据、静默退出（cron 无输出=不发消息，watchdog 形态）。

## 5. 择优闸门（硬判据，不过即回退）

| 判据 | 阈值 | 说明 |
|---|---|---|
| G1 主判据 | `recall@10` 提升 ≥ **2.5pt**（≥3 条） | 即"训练确实带来收益" |
| G2 防倒退 | `recall@1` 不低于基线 **−0.83pt**（−1 条） | 防"堆 recall@10 但首位变差" |
| G3 成本 | 每块嵌入延迟增幅 ≤ **15%**，RSS 增幅 ≤ **15%** | 适配器仅矩阵乘，超此即实现有问题 |
| G4 过拟合 | 训练集与评测集分数差 ≤ **15pt** | 差距过大说明适配器在背评测集（须隔离复核） |
| G5 确定性 | 同权重重跑分数一致 | 不一致即判实现缺陷 |

不满足 G1..G5 任意一条 → **拒绝采纳**，小报记 `verdict=rolled_back` + 失败原因（负样本诚实铁律）。
