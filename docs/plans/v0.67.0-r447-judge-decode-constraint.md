# v0.67.0 · R447 — 判官解码侧约束（单字母 GBNF）的等价性与收益预注册

轮次：R447（承 R446）｜形态：**真机探针（不改产品代码）**｜预注册时间见 `eval/rover/r447/prereg.json` 落盘 mtime

## 1. 为什么做这个（因果链，全部有前轮读数背书）

- R443/R444 已把「本地 r1 真值」钉在 `tokens_evaluated / prompt_n / gen`（不再是 chars/2），并实测：M20 单轮本地真值 7841 tok，主调用 KPI 降幅 33.32%（含本地真值）。
- R446 机制结论（`eval/rover/r446/run-BRJ-M20-s2/data/telemetry/host.jsonl`）：

  | 通道 | 本地调用数 | 本地 token | 其中 gen | 其中 prompt |
  |---|---|---|---|---|
  | 前置门 `local_turn_gate` | 7 | 3103 | 913 | 2190 |
  | 关系判官 `correction_judge` | 13 | 4738 | **1974** | 2764 |
  | 合计 | 20 | 7842 | **2887 (37%)** | 4954 |

  ⇒ 本地成本里 **37% 是生成（推理链）**，而判官通道的生成占 25%（1974/7841）。判官每次调用 gen 92–194 tok
  （`n_predict` 实为 512，未被预算截断），**全是「思考」token，随后才吐一个字母**。
- R435 已证：该判官本地化曾 1/7 成功（thin 模板导致截断），修好后 H2 判决 = f(msg, prev) 且**同输入⇒同字母**（R446 真机 26 样本）。

**问题**：判官要的只是一个字母（3 值），却付 92–194 tok 的生成费。**能否用解码侧约束（GBNF 单字母）把
gen 压到 ≤2 tok，同时判决等价？** 这直接打在「降 30% 总 token」的承重项上（判官 + 门 = 全本地生成）。

## 2. 被测对象（唯一变量 = 解码约束）

产品实发形状（逐字复制，出处 `src/agent.llamacpp/LlamaCppClient.cs:121`）：

```
turns  = [ {system: CorrectionJudgeSystem('只输出一个字母。')},
           {user:   BuildJudgePromptVerbose(prev, user)} ]
POST /apply-template {messages: turns, add_generation_prompt: true}  → prompt
POST /completion {prompt, n_predict, temperature: 0.0, samplers:["temperature"],
                  cache_prompt: false, stream:false, return_tokens:true, seed:0, [grammar]}
```

| 臂 | grammar | n_predict | 语义 |
|---|---|---|---|
| **J0** 基线 | 无 | 512 | 现网口径（先思考，再吐字母） |
| **J1** 语法单字母 | `root ::= "A" \| "C" \| "N"` | 8 | 只允许输出一个字母 ⇒ 无思考空间 |
| **J2** 短预算无语法 | 无 | 8 | 只砍预算（预期：think 未闭合/无字母 ⇒ 反证必须语法） |
| **NC1** 错配 prev | 无 | 512 | 把样本 i 的 prev 换成 (i+1) 的 prev ⇒ 器具非空心负控 |
| **NC2** 平凡结算器 | — | — | 恒输出 `N`，不调模型 ⇒ 指标判别力负控 |

语料 `eval/rover/r447/corpus.json`：**18 条真实 (msg, prev) 对**，三通道机械对齐（禁手打）：
① prompt 模板由 `CorrectionDetector.cs` 字面量派生（派生器 `eval/rover/r444/channel_marks.py`），并对
`eval/rover/r435/judge-prompt-golden-v2.jsonl` 9 条**产品实发 prompt** 做逐字校验（硬闸，须 9/9）；
② msg ← 网格 `turns[]` 原文，以遥测 `msg_head` 前 18 字符锚定；
③ prev ← 归档候选常量，用遥测 `prompt_len` 解方程定位；
④ 另含 6 条 R435 golden 真值对（含**真实** prev 26 字符 + C 类样本），补 prev/字母多样性。

## 3. 预注册判据（先落盘，再执行；机检，不解释）

- **C1 非空心**：每臂「可解析字母」比例 ≥ 0.90；且 J0 的字母种类 ≥ 2。
- **C2 生成降幅**：`mean(gen|J1) ≤ 0.20 × mean(gen|J0)` 且 `max(gen|J1) ≤ 8`。
- **C3 等价（承重）**：`agree(J1, J0) ≥ 0.90`（逐样本字母相同）。
- **C4 负控判别力**：(a) `agree(NC1,J0) ≤ agree(J1,J0) − 0.15`；(b) NC2 与 J0 一致率 < 0.90；
  (c) J0 与**归档字母**一致率 ≥ 0.85（第三通道·器具漂移告警，不 fail-closed）。
- **C5 记账自洽**：每请求 `tokens_evaluated == prompt_n + cache_n`；且 J0/J1 **逐样本 prompt_n 相等**。
- **C6 形态自证**：argv 直取含 `-np 1 / --cache-type-k f32 / --cache-type-v f32 / --flash-attn off / -c 4608 / --jinja`；
  `/props` 采样档 = 仅 temperature（R429/R430 口径）。

**判定规则（预注册）**：C1–C6 全绿 ⇒ 结论「解码侧约束可作 R448 产品化候选（开关默认关 + M20 三臂真机 A/B 复验）」；
任一红 ⇒ **负结论**归档（不得启用），并把该臂的失败机制写进证据 README。
