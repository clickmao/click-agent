## T-A P1/P2 async 化 (热路径双阻塞消除)

### 现状 (代码事实)
- **P2** IndustrialAgentV2.cs:622 `GetContextBiasAsync(...).GetAwaiter().GetResult()` — 每用户消息一次,
  OnProcessAsync 内 (本可 await)。
- **P1** agent/tendency/TendencyData.cs:347+380 `AnalyzeUserTendencyAsync(...).GetAwaiter().GetResult()` ×2 —
  GetContextBiasAsync 内部 (文件 IO + 全量历史扫描); **L347 与 L380 双算同一画像** (结果未复用)。
- 调用链: V2 L622 (阻塞) → GetContextBiasAsync → TendencyData L347 (阻塞) + L380 (再阻塞) = 每消息 2 次线程池占死 + 双倍文件扫描。

### 修法 (由内向外)
1. **T-A1** TendencyData 内部: AnalyzeUserTendencyAsync 的两个 GetResult 调用点改 async/await
   (方法签名 async 化), L347 结果复用于 L380 (消除双算)。
2. **T-A2** TendencyAnalyzer.GetContextBiasAsync: 去 GetResult 包装, 真透传 await (签名已是 Async)。
3. **T-A3** V2 L622: `GetAwaiter().GetResult()` → `await` (OnProcessAsync 已是 async 方法)。
4. **注意**: TendencyData 内若有同步方法签名调用点 (非 async 上下文), 保持 API 兼容
   (提供 async 主路径 + 同步壳标注 legacy, 或调用点全量 async 化 — 按 grep 调用链定)。

- [ ] TendencyData 双算消除 (L347/L380 合一)

## T-B R-3 bge 双加载消除 (真内存重复, 数百 MB 级)

### 现状 (代码事实)
- **链 A**: agent/llamalocal/BgeEmbedder.cs (ITextEmbedder) — DI 注入 ContextGradientCompressor (压缩漂移校验) + TriggerMatcher (skill 触发)。
- **链 B**: agent.vectormemory/BgeEmbeddingProvider.cs (RAG EmbeddingFunction) — 经 EmbeddingRouter 注入 RAGConfig。
- 两链各自 `new LLamaEmbedder(...)` 加载同一 bge-q8.gguf → 进程内**两份模型驻留** (R129 修过"每次调用 new", 实例级双驻留仍在)。
- 另: HashEmbeddingProvider 双实现 (dim 384 vs 256, 各走各的向量空间)。

### 修法 (共享单例 + 双接口适配)
1. **T-B1** 新共享单例: `SharedEmbedder` (DI singleton) — 持有唯一 LLamaEmbedder 实例。
2. **T-B2** ITextEmbedder 适配器 (包装 SharedEmbedder) → 注入 ContextGradientCompressor/TriggerMatcher (替换 BgeEmbedder 直持有)。
3. **T-B3** IEmbeddingProvider 适配器 (包装 SharedEmbedder) → 注入 RAGConfig (替换 BgeEmbeddingProvider)。
4. **T-B4** HashEmbeddingProvider 双实现统一到 vectormemory 一份 (dim 统一 384; llamalocal 的 256 版随链 B 退役)。
5. **风险**: 两链的嵌入语义/维度必须一致才可共享 — 先验证 BgeEmbedder 与 BgeEmbeddingProvider 的
   模型参数 (n_ctx/池化/维度) 完全一致, 不一致则参数归一后再共享。
