## 1. 统一契约设计 — AgentFrontendApi (能力全集 → 接口面)

### 1.0 原则
- **一个契约、全能力** — 上表 15 域全部进 v1 契约 (域多则 api 多, 但每个 api 形状统一: 信封 + 事件)。
- **简单明了** = 三类消息 (请求/响应/事件) 统一信封 + 能力域前缀分组 + snapshot 一次拉全。
- 传输可插拔 (SocketChannel 既有 / WS 适配器 P3) — 契约与传输解耦 (v0.19 不只 IO 的意思: IO 只是信封怎么走, 契约覆盖的是全能力)。

### 1.1 信封 (JSON Lines, 与既有行协议共存)
```
请求:   {"v":1,"type":"req","req_id":"r1","api":"<domain>.<action>","payload":{...}}
响应:   {"v":1,"type":"resp","req_id":"r1","ok":true|false,"payload":{...},"error":{code,msg}?}
事件:   {"v":1,"type":"event","event":"<domain>_<event>","payload":{...}}
```
- 长任务 (chat.send/script.submit): 先 `resp{accepted:true}` → 事件流 → 终态事件。
- 全 api 错误结构化: error.code ∈ {unknown_api, bad_payload, busy, conflict, not_found, internal}。

### 1.2 API 面 (15 域全映射)
- **chat**: send / history / cancel / thinking (事件: chat_delta, chat_done, chat_thinking)
- **ask**: (事件: ask_reach {ask_id, prompt, options[]}) / reply {ask_id, text} / cancel
- **script**: submit {name, code 或 path, task} / list / cancel / (事件: script_validated, script_progress {pct,msg}, script_heartbeat, script_done {outputs}, script_error)
- **staged**: list / diff {batch} / approve {batch|all} / reject {batch} / cleanup / (事件: staged_new {batch}, staged_conflict {batch, files})
- **activity**: list / (事件: activity_change {joined|left|status})
- **skills**: list / filter {only|exclude} / (事件: skill_hit {skill, confidence} — KnowledgeHint 命中)
- **model**: info / switch {id} / list / (事件: model_changed, balance_low)
- **memory**: search {q} / view {scope} / clear {scope} (谨慎域 — 默认 read-only, clear 需 confirm)
- **charter**: current / milestone {id} / (事件: charter_phase {status})
- **guardrail**: (事件: guardrail_triggered {rule, scope}) / lessons {pattern?}
- **eval**: summary / recent {n} / case {id} / (事件: batch_done {round, passed, cases})
- **files**: recent_changes / diff {path} (视图层, 写走 staged)
- **render**: (事件: artifact_ready {path, kind, preview}) — 像素画风产物等
- **trace**: turn_tools {session, turn} — 工具轨迹
- **telemetry**: (事件: route_break, executor_lesson) — 内部故障可观测
- **state**: snapshot / subscribe {events[]} / unsubscribe

### 1.3 UnifiedStateSnapshot v1 (state.snapshot — 前端渲染基线, 一次全量)
```json
{"v":1,"ts":...,"agent":{"name","status","model","balance","cwd"},
 "turn":{"active":false,"phase":null,"last_thinking":null},
 "ask":null | {"ask_id","prompt","options":[]},
 "charter":null | {"id","status","goal","milestones":[],"pending_inputs":[]},
 "staged":{"pending":[{"id","files":[],"created"}],"conflicts":[]},
 "activity":[{"pid","win","job","agent","status","task"}],
 "skills":{"active":["..."],"filter":null},
 "scripts":{"running":[{"name","since","last_event"}]},
 "eval":{"last_round":null|{"round","passed","cases"},"kpi_summary":null},
 "lessons":[{"pattern","count","summary"}],
 "trace":{"last_tools":[]}}
```
- 前端连接 hello → snapshot; 之后靠订阅事件增量; 掉线重连 → snapshot 恢复。

### 1.4 实现分层 (src/agent.frontendapi/ 新项目或 agent 内 — 待定, 倾向新项目引用 agent)
```
FrontendApiContract (STJ source-gen DTO) 
  → FrontendApiServer (传输适配: SocketChannel 行协议; P3 WS 适配器) 
  → Router (api 表 → 域 handler) 
  → DomainAdapters: ChatAdapter(V2 CallAsync/cancel/thinking 事件出口), AskAdapter(V2 clarify 触发点插桩), ScriptAdapter(ScriptPluginRunner + 事件转发), StagedAdapter(ApprovalController + 变更事件), ActivityAdapter(ActivityService 轮询/事件), SkillsAdapter, ModelAdapter(ModelQueueRouter), EvalAdapter(轮 JSON 读), SnapshotBuilder(组装 1.3)
  → EventBus (进程内 ring; 多连接广播 P2)
```
- 问询插桩: V2 clarify/隔离问询现有文本提示处 → 同步发 ask_reach (事件出口, 不改变 CLI 行为)。
- chat 流式: V2/chatbox 现有 thinking/output 事件适配为 chat_delta。
- AOT: 全 STJ source-gen, 零反射; 单测同现有模式。

## 2. 验收标准
1. 契约单测: 信封/响应配对/未知 api 错误/快照字段完整/事件顺序 (总线 ring)。
2. E2E (真 socket 47810): hello→snapshot→chat.send→chat_done; clarify 触发 ask_reach→reply; staged 批次→staged_new→approve; script.submit→progress→done; eval 摘要。
3. 全量单测绿 + AOT 0 IL 警告 + quick-13 零回归 (chat 主链仅插桩)。

## 3. 分期
- P1 (R342): 契约 + Server + Router + Snapshot + chat/ask/staged/state 四域 — 最小真实前端可用闭环 (覆盖用户点名 2 项: 问询到达 + 脚本? 脚本 P1 半: submit+事件).
- P2: script 全 + activity/skills/model/eval/memory(只读)/guardrail/trace/render 事件。
- P3: **无头浏览器域实现** (browser.navigate/click/eval/screenshot/artifact 预览 — Playwright py 内核经 v0.17.2-b 脚本插件事件流; 供 agent 网页自动化与 web 产物真机验证) + WS 适配器 (外部前端浏览器直连) + py 示例客户端 (示范外部前端如何对接)。
- **生态接入边界 (用户裁定 2026-09-10, 二次更正)**: ①无头浏览器 = **本项目实现** (agent 内部能力: 网页自动化/真机验证, Playwright py 内核经脚本插件协议) ②IDE/前端 = **外部实现, 本项目只负责对接接口** (FrontendApi v1 契约 + 传输; 不实现 IDE/编辑器/网页前端本身) ③MCP/其它不再扩展。

## 4. 待确认
- 新项目 vs agent 内: agent 主链依赖方向 (frontendapi 引用 agent; agent 不引用它 → 问询插桩靠事件出口接口注入, 避免反向依赖) — 设计为: agent 定义 IFrontendEvents (事件出口接口, 空实现默认), frontendapi 实现之。
- eval 数据接口权限: 迭代数据是否对真实用户开放 (产品形态决定) — 默认开放只读摘要。
- 记忆 clear: 默认需二次 confirm (防误删)。
