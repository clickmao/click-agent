## 4. 开关设计（最小面，默认档零产品变更）

## 6. 外部真值通道（本轮真正要解决的事：脱离自证闭环）

**通道 A · 真实用户行为标签（现成、零模型）**
从真实会话日志抽三元组 `(用户消息, 上一轮回复, 用户下一条消息)`，用**下一条消息**作标签：认可 / 纠正 / 换题。
⇒ 把 r1 门判与判官的判决打到**真实流量**上，得到 `外部一致率_A`；对照 `内部一致率`（自家归档）。

**通道 B · 证据标签（需先修 D-TM2/3）**
修好后写入必带 `Refs`（URL/文件/命令）与 `Outcome{positive|negative}` ⇒ 「主张 ↔ 依据 ↔ 结论」三元组即系统外的核实记录。
⇒ 用 `Outcome=negative` 的样本测"门是否该拦"、用 `positive` 测"是否误拦"，得 `外部一致率_B`。

**通道 A0 可行性实测（零测量，已跑；★ 用户裁定后重做）**：用户纠正了我的框定 ——
「我给你发任务, 你给我反馈, 这个过程**本就是真实流量**」。真实语料在 `~/.hermes/state.db`
（**790 MB / 142 会话 / 119,117 消息**）⇒ 收割 **1,542 条真实用户轮**（排除注入/空 659），其中 **862 条带上一轮反馈**可构成外部三元组。
用户并点名 **「有效性得筛选，因为大部分时候我的回复仅是让你执行下一轮」** ⇒ 语料分三类（规则先落盘）：
**D** 迭代驱动 361 条(23.4%，**不作采纳/纠正标签**) / **O** 运维质询 43 条 / **S** 实质反馈 **1,138 条(73.8%，才带真值标签)**。
反证：不筛则 D 类会贡献 **193 条假"采纳"**。

**★ 外部效度裁决（`verdict-r449.json` = `EXTERNAL_VALIDITY_GAP_CONFIRMED`）**：
机械门不变量 `¬Ack ⇒ Pass`（`IndustrialAgentV2.cs:1496`）；真实流量 **ack = 0/1542 (0.0%)**（独立复算纯认可族 = 0；Ack 族字面量由源码正则派生），

## 8. 诚实边界（先写清楚）

1. 1,342 条库里 **0 条可作真值**（T1–T4 全 FAIL）⇒ 通道 B 的**产量在本轮可能为 0**，只报"修好了没有 + 未来产量"，不得宣称"已验真"。
2. 通道 A 依赖真实流量样本量；若样本 < 30 条 ⇒ 只报分布，不报一致率（避免小样本假结论）。
3. `hits=0` 的两种解释（**召回没命中** vs **命中了没采纳**）本轮靠 C3 计数器区分，未区分前不得归因阈值。
4. 单模型档（r1-distill-1.5b-q4km + bge-q8 384 维）；M20X 是我构造的诱发网格，结论不外推到真实长会话。
5. 开关 `off` 的效果**不代表** think-memory 无价值，只代表"当前实现下不进入决策"; 机制缺陷修好前，消融结论只在当前形态成立。
