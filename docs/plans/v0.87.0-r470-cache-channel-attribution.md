## 1 问题
用户的 KPI 是「一轮任务总 token 下降 ≥30%（主因：不必要的远端 LLM 请求变少）」。要证明「前缀被复用、新算 token 变少」，唯一指标是 K2b 有效命中率。但它对**真实流量**是否可测？

机检（预检，43 条真实远端调用）：`effective_hit_rate` **43/43 = -1（100% 不适用）** —— 因为 43/43 都没有同会话前驱（29 个会话、28 个只调用一次）。与此同时供应商侧**确实在命中**：32/43（74.4%）`cache_hit_tokens > 0`，命中量 2,048（×19）/ 2,176（×7）/ 2,304（×2），按 64-token 单元对齐。

⇒ 真实缓存收益客观存在（3k prompt 上命中占比 0.66~0.71；5.4k prompt 上 0.34~0.42），但**当前唯一 KPI 通道看不见它** ⇒ 优化既无度量也无驱动信号。本轮不猜机制，先把**归因通道**补出来，并把它机检钉在真实遥测上。

## 2 口径（预注册，先落盘后跑复算）
- 通道归因（本轮**只增不改**）：设 `last = last_prompt_tokens`（同会话上一轮已发 prompt；无记录 = 0）：

| `cache_channel` | 条件 | 语义 |
|---|---|---|
| `same_session` | `last > 0` | 命中可归因到**会话内前缀复用**（R380 既定口径区间） |
| `shared_prefix` | `last == 0 ∧ prompt > 0` | 无同会话前驱 ⇒ 命中只可能来自**跨会话共享前缀**（含供应商侧同文本缓存；因果界见 §5） |
| `unknown` | `prompt == 0` | 无数据 |

- `shared_prefix_hit_tokens` = `hit`（仅 `shared_prefix` 通道；其余通道 **-1**，禁双计）。
- `shared_prefix_hit_rate` = `hit / (hit + miss)`（仅该通道；无分母/未上报 ⇒ -1，不得冒充 0）。
- **判定口径一字不改**：`cacheable_tokens` / `effective_hit_rate` 及红线阈值（97%）保持原样 ⇒ 新旧分通道并存，不构成口径回退。

## 3 预注册判据
- **C1** 真实流计数：`llm_call` = 43 条；逐行 `utf-8-sig` 读取（首行 BOM 不得吞行 —— 预检已踩：`utf-8` 会静默少一行）。
- **C2** 归因守恒：`shared_prefix + same_session + unknown == 43`；实测 **shared_prefix = 43, same_session = 0, unknown = 0**。
- **C3** 通道非空：`shared_prefix` 通道内 `hit > 0` 的调用 ≥ 30（实测 32），且命中直方图 = `{0:11, 127:2, 256:2, 2048:19, 2176:7, 2304:2}`。
- **C4** 对齐例外必须逐条列出：`hit > 0 ∧ hit % 64 != 0` ⇒ 明细落盘（实测 2 条：hit=127 / prompt=261），不得静默过滤。
- **C5** K2b 可测性裁定：同会话多轮样本 = 0 ⇒「K2b 有效命中率对真实流量 100% 不适用（43/43 = -1）」必须作为机检结论落盘，不得口头声明。
- **C6** 负控（必须红）：
  - (a) `last > 0` ⇒ `shared_prefix_hit_tokens == -1 ∧ shared_prefix_hit_rate == -1`（**禁双计**）；
  - (b) `hit` 未上报（null/-1）⇒ `shared_prefix_hit_tokens == -1`（**不得 0**）；
  - (c) `prompt == 0` ⇒ channel = `unknown` 且两个 shared 字段 = -1；
  - (d) 熔断：把归因条件反写（`last > 0` 才算 `shared_prefix`）⇒ C2 / C6a 必须变红。
- **C7** 接线：三处 data-carrying `llm_call` 打点都必须铺 `chanKv[0..2]`（源码按打点块配对扫描，防「算了不铺」空心）。
