## §7 实测基线（R413-A，2026-09-14 真机跑通后追加）

**链已跑通**（此前 §6 的"未建成"状态解除）：`eval/rover/r413/run_arm.sh A` ⇒ **4/4 轮 ok、13 事件、2 次 ask、0 错误**；桩侧真值 7 次远端调用 / 11,025 est tokens。证据：`eval/rover/r413/{calls-A.jsonl,turns-A.jsonl,baseline-breakdown.json,host-A.log}`。

| 调用类 | 次数 | tokens_est | 占比 | 单次区间 |
|---|---|---|---|---|
| **主回答**（"搜索专家" system + SessionMemory + 下轮预估 + 参考上下文） | 4 | 10,865 | **98.55%** | 2,376 / 2,599 / 2,876 / **3,014** |
| 纠正判别（"只输出一个字母"微 prompt） | 3 | 160 | **1.45%** | 51 / 56 / 53 |

**实测结论（推翻单点方案，判据 C1–C6 不变）**：
> 把「纠正/真假判别」整体搬到本地，**最多只省 1.45%** ⇒ 单点端口化**结构上不可能**达到 30%。
> 30% 的杠杆在**整轮远端主调用**：每轮固定发一条 ~2,400–3,000 tok 的主调用，**连 `"好，按这个来。"`（9 字符、零新信息）也触发 3,014 tok**。

**方案修订（§4.2 追加第 5 项，判据不回改）**：
- **5. 本轮前置门（本地真假判别 → 免发整轮远端主调用）**：每轮用户消息先经 `ILocalGenerationPort` 由 **r1** 判别「这条消息是否携带**新诉求/新信息**」（真/假），判别时挂 role 额外数据（`ActiveRole.ProfileSeed` + `GrowthLedger` 计数）；判"假"（纯确认/寒暄/重复）⇒ **本地消化，不发起远端主调用**（省掉该轮 ~3,000 tok）；判"真"⇒ 照常远端。默认 **OFF**（零回归），role 缺失自动失效。
- 判据换算（不改阈值）：C1 分母 7 次 ⇒ 臂 B 需 ≤4 次调用（−42.9%）；C2 分母 11,025 tok ⇒ 臂 B 需 ≤7,717 tok。因主调用占 98.55%，C1 达标基本蕴含 C2 达标。
- 反空心（防"用脚本刷比率"）：任务脚本固定且**两类消息都含**（实质请求 + 纯确认），并额外报告**分类分解**（实质轮 / 非实质轮各自省了多少），禁止只报总比率。
- 反"没测到"：C6 负控必须含**假阴性**用例（把有信息量的消息判成"假"⇒ 必须被逮住，不许静默跳过）。

### §7.3 前置门 v2 实现（2026-09-14，跑臂 B v3 之前写定 ⇒ 非事后回改）

   - 结构化实体（`` ` ``·`/`·`\`·数字）与长文本（≥24 字符）
   只有**无任何机械信号的短消息**（示例：「好，知道了。」「嗯。」「收到，谢谢。」「好，按这个来。」）才交给 r1。
2. **被跳过轮的回复改非 LLM 模板**（`ModelQueueRouter.LocalSkipFallback`，**不再调本地 r1 生成**）：
   纯确认轮没有新信息可加，生成只会引入幻觉；模板串同时是「有回复」不变式的机检锚点。
