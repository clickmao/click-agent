# v0.13.0 任务3: 思考链收敛 + RAG 联想记忆 详细开发文档

> 状态: 详细设计 (用户钦定 2026-09-08, 文档先行)。
> 用户定义 (逐字要点): ①判断当前任务是否为复杂问题 ②是否需要展开思考链收集数据依据 ③是否需要内部自动逐步探索链接查找深层依据 ④有限时间内评估依据置信度 (多信息源对比, 不能只看一家) ⑤**是否将此次思考记录在 RAG 内 (非常重要) 作为下次思考类似问题的依据 (类似问题=联想能力; 思考链查链接过多时, 凭 RAG 记录的偏好优先阅览历史相关高置信度链接, 并稍微提升其置信度)**。
> 用户新增要求 (逐字): 必须设计详细开发文档 + 回归收敛跑测重点观察数据 + 收集大量有效负样本/正常样本 + 独立跑测程序 + 执行后探查记录真实对比判断 KPI 是否提升。

## 一、功能设计
### 1.1 复杂度判定 (ComplexityGate)
- 输入: 用户消息 + IntentRecognizer 结果 + 子任务数。
- 判据 (可打点): 子任务数 ≥2 / 意图 ∈ {research, coding, planning} / 消息含 URL 或目录引用 / 消息长度 > 200ch。
- 输出: `ComplexityVerdict { is_complex, score, triggers[] }` → 复杂 → 启动思考链+探索; 简单 → 直接回答 (省 token)。
- 打点: `complexity_gate` (score, triggers, is_complex) — KPI: 触发率、误判率 (简单题展开=浪费, 复杂题直答=质量降)。

### 1.2 依据收集 + 多源置信度 (EvidenceScorer)
- 每个依据 (探索到的 URL/文件/RAG 片段) 打分: `confidence = w1*源历史置信 + w2*内容相关性 (bge 相似度) + w3*多源一致性`。
- **多源对比 (用户钦定"不能只看一家")**: 同一论断至少 2 个独立来源 (不同域名/不同文件) 才能达 high 档; 单来源封顶 medium。
- 有限时间: 全局思考预算 (秒) — `think_deadline_ms` (config, 默认 60s); 超时 → 用现有依据收敛作答, 打点 `think_timeout`。

### 1.3 RAG 联想记忆 (ThinkMemory — 核心)
- **写入**: 思考链收敛后, 若本次思考有高质量依据 (confidence ≥ 0.7), 记录 ThinkRecord:
  `{question_emb (bge), urls[], files[], avg_confidence, outcome, ts}` → 独立 RAG 命名空间 `think-memory`。
- **读取 (联想)**: 新思考链展开时, 用当前问题 embedding 检索 think-memory top-k (相似度 ≥ 0.75);
  命中 → **优先阅览历史高置信度链接** (队列前置), 并在其被引用后 **稍微提升其置信度 (+0.05, 上限 1.0)** — 用户钦定。
- **遗忘/降权**: 历史记录 30 天未被命中引用 → 置信度衰减 (-0.1); < 0.3 归档。
- 防污染: 负样本思考 (幻觉/错误答案被回测证伪) → 记录 outcome=negative, 检索时降权。

### 1.4 收敛判据 (ThinkConvergence)
- 满足任一 → 收敛: ①主论断多源一致 (≥2 high 置信源) ②思考预算/步数耗尽 ③探索无新发现 (2 步无新增源) ④LLM 自评"依据充分"。
- 打点: `think_converge` (reason, steps, sources_used, avg_confidence, wall_ms)。

## 二、跑测观察数据 (回归收敛重点 — 用户钦定)
### 2.1 新打点族 (登记 test-dimensions-ledger.md 新维度 `think_chain_index`)
| 打点 | 键 | 观察什么 |
|---|---|---|
| complexity_gate | score/triggers/is_complex | 触发率 20-40% 健康带 (全触发=门失效, 零触发=门死) |
| explore_step | step_n/budget_left/ok | 步数分布 (均值≤8), 预算耗尽率 <15% |
| evidence_score | confidence/source_n | 多源率 (≥2 源占比), 置信度分布 |
| think_converge | reason/steps/wall_ms | 收敛原因分布, wall_ms 均值 ≤ deadline |
| think_memory_write | question_emb_dim/urls_n | 写入率 (高质量思考占比) |
| think_memory_hit | sim/hit_url_conf_boost | 命中率, 置信提升生效数 |

### 2.2 KPI 提升判据 (真实对比 — 用户钦定"探查和记录真实对比性")
- **A/B 双口径**: 同一 19 用例集 × {探索关 (基线), 探索开} × 3 批 → 对比:
  ① reply_rel (相关性) 开 > 关 +0.05 显著 ② EvidenceGate 通过率 ③ tok/case 上行幅度 (成本, 记录不设硬带, 新开维度观察) ④ 幻觉负样本触发率 (负样本集) 开 < 关。
- 判定: ①③④ 改善且 ② 不降 → KPI 提升 ✓; 仅 tok 降其他平 → 无效回退。

### 2.3 收敛性回归 (防漂移)
- 同一问题 3 次独立跑: 收敛步数 CV < 30%; 答案关键断言一致 (must_contain 同断言)。
- 波动治理线: CV ≥ 30% 连续 2 轮 → 收敛判据回退检查。

## 四、独立跑测程序 (eval/run_explore_round.py)
- 复用 run_round.py 骨架 (轮号唯一/打点消费/-u/PATH fail-fast/per-case 容错 — 全部继承), 新增:
  - `--suite explore` 读 explore_cases.json; `--ab {on,off}` 探索开关 (env AGENTFRAMEWORK_EXPLORATION=0/1)。
  - 输出 `data/logs/eval/rounds/explore_<round>.json` + **对比报告**: 自动拉同用例基线 (off) vs 实验 (on) 的 reply_rel/EvidenceGate/tok/explore_step → 逐用例 Δ 表 + 总判定 (§2.2 规则)。
  - 真实对比落地: 对比表写 `eval/reports/explore-ab-<round>.md`, 并由程序从轮 JSON 原始数据计算 (不从内存/推断 — 用户钦定"探查和记录真实对比性")。
- 跑测命令模板 (继承批测纪律: -u / AGENTFRAMEWORK_LOCAL_DISABLED=1 / 后台 Popen):
  `python3 -u eval/run_explore_round.py exp_mass_1 "T3 ab=off baseline" --suite explore --ab off`

## 五、实施里程碑 (过自审查三问后逐个进)
- M-A: ComplexityGate + EvidenceScorer (纯逻辑+单测) — 依据: §1.1/1.2 判据全可静态复现; 前提: 纯 C# 无反射 ✓; 验收: 门触发率健康带 + 单测 ≥8。
- M-B: ThinkMemory (RAG 联想写入/检索/置信升降/衰减) — 依据: 现有 bge+RAG 基建; 前提: embedding 检索 AOT 链已稳; 验收: 联想单测 + TC-N04 真机。
- M-C: 思考链集成 (LLM 步进协议 + 收敛判据) — 验收: TC-N02..N05/F01..F06 全绿 + 收敛 CV < 30%。
- M-D: A/B 独立跑测 + 对比报告 + KPI 判定 → 用户汇报。

## 六、风险与诚实边界
- bge 检索质量是联想上限 (小模型语义漂移) — 用 sim 阈值保守 0.75。
- URL 抓取网络波动 — 负样本 F01 已覆盖, 探索失败不阻塞主回答。
- think-memory 污染 — outcome 负样本降权 + 30 天衰减。
- 成本: 探索开 tok/case 预计 +30-60% — 记录不设硬带 (新功能观察期), 用户 KPI 判定以质量为主。
