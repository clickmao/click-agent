## 2. 设计（含实施后的口径更正）

### 2.1 分词器（`src/agent.rover/token/`，纯 BCL / 零反射 / 无 NuGet）

1. `ByteUnicode.cs` — GPT-2 字节↔unicode 映射（256 项双射；可打印区间保留原字符，其余映射 `U+0100+`）。自检 `SelfCheck` 断言双射。
2. `Pretokenizer.cs` — 5 条 Split + Digits(逐位) + ByteLevel 的**标量扫描器**（`Split:88`、`SplitStages:108`、`SplitDigits:129`）。
   - **实施更正 ①**：计划原写「正则常量内嵌」——实测发现 .NET `Regex` 按 **UTF-16 码元**解析字符类，对增补平面区间
     （`𐐀-𐑏` 等）会拆成孤立代理项 + 反向区间 ⇒ **静默过量匹配**。故改为：生成器把正则**机器解析成标量区间表**
     （`TokenizerAssets.g.cs`，含 5 条正则原文 + `sha256` + 5 张区间表 + 规范化摘要 `RangesDigest`），C# 侧用标量扫描器消费。
   - **实施更正 ②**：区间表必须**归一化（排序 + 合并）**后才可二分查找。CJK 正则原文顺序为 `一-龥` `ࠀ-一` `가-퟿`（非升序），
     首版直接透传导致 `中/文` 漏判（实测现象：`中अआ文` 被切成 3 片）。根因与修法已固化为自检项
     （`Pretokenizer.SelfCheck:17` 断言「区间严格升序互不重叠」，失败即红）。
   - **实施更正 ③**：`\s?[类]+` 的**可选前缀需要回溯**。贪婪吞掉一个空白后若其后不是类字符，必须退回「不吞空白」，
     让该空白字符本身作为类成员被匹配（实测：U+3000 同时在空白集与标点/CJK 类内，`：\u3000””\u3000` 的尾片依赖此语义）。
     落点 `Pretokenizer.MatchClassRun:237`。
   - **谓词探测口径更正 ④**：判定谓词必须**逐阶段隔离探测**，不能用整条流水线探测单条谓词——后续阶段会二次切分，
     导致把 Zs 类空白误判为「非 `\s`」。正确读数（`scripts/rover_probe_oracle_predicates.py`，全 BMP 穷举 + 增补候选）：
     `\s` = **25 码点 = Unicode White_Space 全集**（含 U+3000 / U+2000-U+200A / U+2028-2029 / U+202F / U+205F / U+1680 / U+0085 / U+00A0）；
     Digits = `{Nd,Nl,No}` 全集（候选 1831 命中 1831，负控 3920 例 **0 违规**）。
3. `BpeTokenizer.cs` — 从 GGUF 装载 `tokens/merges/token_type`：编码 = **切分集优先切分 → 预分词 → 逐片最低 rank 合并**
   （`Encode:165`、`BpeEncode:240`）；解码 = `id→token` → 反字节映射 → **UTF-8 跨 token 字节缓冲后一次性解码**（`Decode:200`）。
   - **实施更正 ⑤**：切分集 = `added_tokens` **全体 18 个**（实测：与 `special=true` 标志无关，18/18 均在编码前被切分）；
     `special=true` 的 **3 个**只影响 `decode(skip_special_tokens=true)`。两套集合分别入表（`SplitTokens`/`SpecialTokens` + 各自 sha256）。
   - 整片命中词表 ⇒ 直接取 id（HF 快路径）；缺表/计数不符 ⇒ **拒绝装载**（不静默降级）。
4. **显式拒绝而非猜测**: ① 词表缺口（含 13 个不可映射字节）⇒ 抛异常；② chat template 未支持构造 ⇒ 抛 `NotSupportedException`；
   ③ 表快照 sha256/计数与登记不符 ⇒ 拒绝装载（防「换了模型还看起来能跑」）。

### 2.2 采样器（`src/agent.rover/infer/Sampler.cs`）

- SplitMix64 确定性 PRNG（`NextU64:160`；参考向量由**独立 Python 实现**给出，逐位对账）。
- 支持 `greedy`（`temp≤0`）/ `temperature` / `top-k` / `top-p`；并列按 id 升序（全序 ⇒ 与排序稳定性无关，跨平台确定）。
- **范围更正**：**未做**重复/存在惩罚（计划原列，已移入 §6 排除项）。
- 边界语义显式: `temp≤0` ⇒ 贪心（不消耗随机数）；`top-k≤0 或 >词表` ⇒ 视为不裁剪；`top-p≥1` ⇒ 全支撑。
- **负控抓到真 bug**：首版 `NextU64` 把状态拷进局部再 `ref`，导致随机源**永不前进**（退化采样）——
  由「平坦分布必须出现多个 id」的反向控制捕获，已修（`Sampler.cs:160`），并保留该控制为常驻测试。

### 2.3 解码环 & CLI（`src/agent.rover/cli/GenerateCli.cs`，`RoverCli` 分派）

- `tokenize <gguf|--tables DIR> --selftest | --fixtures | --neg-control | --text …`：
  自检（资产摘要/双射/升序/chat golden）/ 四组夹具逐条对账 / 负控读数 / 单文本诊断（分片 + ids + 往返 + 原始解码）。
- `generate <gguf> --prompt P [--chat [--system S]] [--max-tokens N] [--temperature T] [--top-k K] [--top-p P] [--seed S]
  [--ctx N] [--max-seconds S] [--budget-mb N] [--out-text F] [--json F]`：
  一次 prefill + N 次单 token decode（复用 `ForwardPass`，KV 自然累积）→ 采样 → 解码 → 文本 + 逐步墙钟/`tok/s`/峰值 RSS/流式字节数。
- chat 渲染: 支持 `system/user/assistant` 三类消息 + `add_generation_prompt`（DeepSeek 版式，系统前缀分隔 = `\n\n`）；
  其它构造（工具调用、`continue_final_message` 等）⇒ 显式拒绝（R403 补齐）。
- 离线复跑面：`--tables DIR` 走**表快照**（`TableSnapshot.cs:15/28`），无需 4.2 GB 模型即可跑全部对账。

### 2.4 对账与负控（跨实现铁律）

- **正控**（oracle = HF `tokenizers` 0.23.2，独立实现，非本仓代码）:
  199 条 encode 夹具 + 199 条预分词夹具 + **2000 条压力夹具**（确定性随机、对抗字符集混合、含增补平面/空白/特殊符号）+ **405 条解码夹具**（含跨 token 多字节与特殊符号跳过），全部逐条对账。
- **负控（必须红，且已量化判别力）**:
  | 变体 | 依赖合并样本 | 被检出 | 下界断言 |
  |---|---|---|---|
  | `merges` 乱序 | 1814 | 753（41.5%） | ≥30% |
  | `merges` 逆序 | 1814 | 1032（56.9%） | ≥40% |
  | `merges` 清空 | 1814 | 1728（95.3%） | ≥90% |
  | 空切分集 | — | 特殊符号文本必被打散（3→15 id） | 必红 |
  | 朴素整片预分词 | — | 判别 137/199 | ≥100 |
  统计口径：只在**依赖合并表的样本**（至少一个片段被切成 ≥2 token）上统计——整片命中词表的文本与合并表无关，计入会稀释判别力。
