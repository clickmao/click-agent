## 2. 设计（新族判据 = 公开样例推不出隐藏判据）

| 族 | 规格要点 | 隐藏判据 |
|---|---|---|
| `topo_min` | 有向图（0 起编号，可含自环/重边/环） | **字典序最小**拓扑序；有环 ⇒ `-1` |
| `vm_run` | 微型栈机（PUSH/POP/ADD/SUB/MUL/DUP/SWAP/PRINT/JNZ/HALT，`k` 条指令） | 跳转语义；栈空/操作数不足/地址越界/超 10000 步/执行流越界 ⇒ `ERR` |
| `json_mini` | 严格 JSON 子集（整数无前导零、仅 6 种转义、uXXXX 解码且码点≥0x20、重复键后者覆盖、对象键按码点升序、输出无空白） | 非法输入 ⇒ `ERR`；**合 JSON 但不合本规格**（浮点/NaN/低码点 uXXXX/裸控制字符）也必须 `ERR` |

**双路径验算**（既有铁律）：每族 `ref`/`check` 两条**独立实现**（如 `topo_min` = 最小堆 Kahn vs 线性扫描；`vm_run` = list 栈 vs 预分配数组+指针；`json_mini` = 字符级递归下降 vs 手写词法+token 递归下降），
不一致 ⇒ `RefuseToEmit`（拒发题）。本轮实测：`json_mini` 609 例、`topo_min`+`vm_run` 813 例，**分歧 0**。

## 3. 约束（守）

- 打分单元一律 **整题全对**（全部隐藏用例通过）；用例级率只作旁读（本轮负控 B 正是反例：用例级 75%、整题全对 0）。
- 只认**隐藏用例**；公开样例仅进题面。
- 判别力必须**成对自证**：正控（oracle 必须满分）∧ 负控（缺陷注入必须整题全对 0）。
- 真机读数取**真实链**（AOT `agenthost`），不取被测量代码自报。
- 所有输入文本用 `chr()`/`_nl()` 构造，**禁止转义字面量**（R413 教训：写入工具会污染特定字符序列）。

## 4. 验收（命令 + 判据）

```bash
python3 eval/probe/tasks.py --selftest            # 45/45（含各族"浅解零通过"负控 + 对抗输入覆盖）
python3 eval/probe/run_probe.py --selftest        # 18/18
python3 eval/probe/run_probe.py --kind program --families topo_min,vm_run --n 4 --seed 20260914 --solver oracle
python3 eval/probe/run_probe.py --kind program --families topo_min --n 4 --seed 20260914 --solver mutation:topo_dfs
python3 eval/probe/run_probe.py --kind program --families vm_run  --n 4 --seed 20260914 --solver mutation:vm_noerr
python3 eval/probe/run_probe.py --kind program --families json_mini --n 2 --seed 20260915 --solver oracle
python3 eval/probe/run_probe.py --kind program --families json_mini --n 4 --seed 20260915 --solver mutation:json_loose
python3 eval/probe/run_probe.py --kind both --n 3 --seed 20260913 --solver agent   # 同题复跑（对比 2026-09-13 基线）
```

**判据**：① 正控 oracle 三族均 **整题全对 2/2 或 4/4**；② 负控三族均 **整题全对 0**；③ 同题复跑（seed 20260913）与基线**逐族一致**；④ 真机新族读数作为 §5 质量分数的**首个非饱和**读数（若仍饱和，如实登记为下一步候选依据）。

### 5.1 `json_mini` 真机读数（**首个非饱和质量分数**）

| 口径 | 用例级 | 整题全对 | 备注 |
|---|---|---|---|
| 记录口径（缺陷仪器，`probe-r417-json-agent.json`） | 27/54 = 0.5000 | **0/3** | p001 `wrong_output 0/18`（提取残片）、p002 `runtime_error 10/18`（退出码顶掉） |
| **修正口径**（`probe-r417-json-regrade.json`，同一批归档回复离线复判） | **47/54 = 0.8704** | **1/3 = 0.3333** | p001 12/18、p002 **18/18（满分）**、p003 17/18 |

- **用例级 87% 与整题全对 33% 的落差 = 判分单元必须是"整题全对"的实证**。
- p003 唯一失分用例 = **`tight_gen` 强制的"裸 TAB 在字符串内"**（规格要求 `ERR`，其解法接受了它并回写 `["a\tb"]`）⇒ 紧用例机制**确定性地**否掉了 17/18 的解法拿到整题全对。
- p001 的 7 处失分全是**输出侧漏引号**（`{z:-72}` / `[A]` 之类）⇒ 能力缺陷，非仪器问题。
- 提取/分类的**两处仪器真缺陷**（长回复下"首个可编译前缀"退化 + 非 0 退出码顶掉正确 stdout）已修：`eval/probe/grade.py` 提取器分两轮且前缀 ≥64 字符、分类按 stdout 优先（`exit_nonzero_ok` 计数），`--selftest` 25→**29**。

## 6. 诚实边界

- **两个口径都给**：`json_mini` 记录口径 0.5000 用例级 / 0 整题全对（缺陷仪器）与修正口径 0.8704 / 1/3，不选择性汇报。
- **修正口径来自同一批归档回复的离线复判**（`file:<dir>` 适配器读 `data/probe/replies/` 原文）⇒ 判定器升级后对**同一外部证据**复判，**没有新跑 LLM**、没有换题。
- **单调性论证（不重跑即可判定旧读数是否仍然成立）**：两处仪器缺陷都只会**低估**（提取残片 ⇒ 分数降低；`exit!=0` 判失败 ⇒ 正确 stdout 被顶掉），修后口径恒 ≥ 旧口径。故 `topo_min`+`vm_run` 记录口径已满分（74/74、6/6）⇒ 修正口径下**必然仍满分**，无需重判。
- **证据卫生缺陷（本轮暴露）**：`data/probe/replies/` 按 `<solver>-<tid>.txt` 命名、**不带轮次/臂命名空间** ⇒ 后一臂覆盖前一臂（本轮 topo/vm 臂的 p001–p003 回复已被 json_mini 臂覆盖）⇒ 下轮应改为 `<tag>-pNNN.txt`。
- **饱和 ≠ 仪器坏**：负控仍 0 整题全对；饱和指被测对象到顶。
- **未打破天花板**：`topo_min`/`vm_run` 两族 agent 仍满分 ⇒ 说明"加难族"这条路本轮**未奏效**；质量分数仍缺连续量。
- 真机读数 **n 小（3～6 题）**、单机单次；只作方向性证据。
- `tight_gen` 机制使 `json_mini` 每题多一条**人为设定**的紧用例 ⇒ 它度量的是"是否按本规格实现"，不是"是否会用 JSON 库"这一泛化能力。
- 本轮**未**改动产品代码 ⇒ 无需重发 AOT（沿用 R414 产物 `/tmp/pub_r414/agenthost`）。
