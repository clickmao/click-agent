## 2. 机制事实（源码为准，决定题集边界）
`LocalGenerationPort.MechanicalPass`（零 token、确定性、**根本不问 r1**）在下列任一成立时结构
性 Pass：`?？` / QuestionSignals / RequestSignals / CorrectionSignals / 反引号·斜杠 / 含数字 /

因此 P 族（假信息/纠错）在本题集的定义 = **残余带内的真假诉求判别**：机械表已覆盖的纠错
（`不对/不准确/重新…`）由机械表结构性 Pass，不进 r1，故不进本题集（否则是测机械表，不是测 r1）。

## 10. Phase 2 (少样本修) 被实测证伪

假设: 门判 few-shot 的两个 P 例 (`另外，测试命令是什么？` / `不对，你上一轮不准确，请重新确认。`) 全带机械信号 ⇒ 生产里根本进不到本门 ⇒ 残余带内 r1 只见 S 例 ⇒ 学成「短消息 ⇒ S」。

修: 补两条**残余带原生 P 例**(`再说一遍。` / `展开说说。`)。机检: `gate_prompt_len` 425/424/426 → **453/452/454** (+28, 与新增两行逐字节相符) ⇒ 改动确实进了实发 prompt。

实测 (同题集, 同 AOT 重发布 `/tmp/pub_r434b`, IL 0):
- 臂 B: 判定**逐位不变**(Skip 6 / Pass 1, 总 tok 4958 完全相同) ⇒ 1.5B 对该少样本**零敏感**。
- 臂 B0: acc **0.625 → 0.875** (假阴性 [3,7]→[9], 假阳性 [2]→[]) ⇒ 示例修在无挂载臂有效、在挂载臂完全无效。

⇒ 结论: 少样本路线**不能作为质量硬线的修法**(不稳定, 且与挂载块相互压制)。改走 Phase 3 结构修。

## 11. Phase 3 (双条件结构修) — 实现与复测

```text
Skip 生效 = MechanicalPass=false ∧ r1 判 Skip ∧ MechanicalAck(message.Content)=true
            (结构上确认为「认可族」↑)          否则 ⇒ 降级 Pass (gate:skip_rejected_nonack)
```
- 方向性: 白名单(承认哪些可省) 而非黑名单 ⇒ 未知一律保守走远端 (与 MechanicalPass 同向)。
- 反空心: 结构确认不过 = 不省这次调用 ⇒ **任何误判只可能多花 token, 不可能让真诉求变空话**。
- 可观测: `local_turn_gate_reject` 事件 + `TurnGateCounters.SkipRejected`。
- 机器不变量 (测试 G30/G31/G32): ① 每个 tag 至少一条**带内**示例 (否则该 tag 对 r1 不可见);
  ② 认可族判定表 (正向 5 / 反向 8, 含「再讲一遍。」族); ③ 链侧必须接线 (`MechanicalAck(message.Content)`)。
