## 2. 判官语义（源码事实，非推测）
`src/agent.roles/CorrectionDetector.cs`:
- L1 规则层（0 token，`:51 RuleJudge`）：强纠正标记（`:30 CorrectMarkers`）/ 强采纳标记（`:36 AdoptMarkers`）
  命中即结算（`marker:<词>`），**未命中返回 null ⇒ 进 L2**。
- 结构性短路（`:128`）：`previousReply` 空 ⇒ `Neutral / signal=no_prev_reply / TokensUsed=0`（不调模型）。
- L2（`:115 JudgeAsync`）：单一 prompt 构造点 `:96 BuildJudgePrompt`，模型输出 C/A/N 字母；
  `:155` 按 `StartsWith("C")/StartsWith("A")` 归类，否则 **Neutral**（`:161`，Signal=`llm:<raw head>`）。
- 下游语义：Kind ∈ {Neutral, Adopt, Correct} = {不罚不赏, 赏, 罚}（`:27`）。
  ⇒ **若可机检地断言「LLM 必答 N」，则跳过调用与实调一次在 Kind 上逐位等价**（Confidence/Signal/Tokens 不同，
  但赏罚链只吃 Kind）。这就是门侧 `¬Ack ⇒ Pass` 的同构命题。
