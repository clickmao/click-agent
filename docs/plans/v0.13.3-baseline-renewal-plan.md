> 背景 (用户定义): 现有 396 用例实测 prompt 100% <2k — **用例太小, 不符合实际使用,
> 不利于开发校验**; 长任务多轮会不断触发上下文压缩, 达到阈值才触发微步骤隔离 —
> **这个从来没跑过**。要求: 更换 baseline, 往期数据作为不同覆盖面纳入, 收集其他覆盖面数据与负样本。

## 二、L3/L4 用例设计 (真实"大"从哪来)
### L3 大上下文注入
- XL-01: 3k tok 合同文本 (内嵌 ground-truth 数字/日期/签署方) 问答 — 压缩必触发
- XL-02: 5k tok 多文档对比 (2 篇 × 2.5k) — 检验跨文档关键信息
- XL-03: 8k tok 代码库摘要任务 (真实仓库文件喂入) — RuleCompress 档实战
- XL-04: 10+ 轮 repl 长对话 (脚本驱动, 每轮注入新材料) — history 累积 → 压缩多轮
### L4 微步骤隔离触发链
- MS-X01: 长任务 (5+ 子任务 × 多依赖) + 每子任务注入 1.5k 材料 → 步骤间 est 累计过阈值 → context_gate mode=isolated_micro 断言
- MS-X02: 触发后 skill 调用不丢 (微上下文 skill 按需注入断言)
- MS-X03: 触发后主记忆零污染 (subagent 销毁断言)
### L5 负样本
- XL-F01: 8k tok + 无关话题注入 → isolated_true 且主记忆零污染 (A5 语义)
- XL-F02: 压缩后关键数字问询 (audit ground-truth 复用 — 答"不在上下文中" vs 幻觉编造)
- XL-F03: 20k tok 超预算 (超 hard_threshold) → 诚实拒绝/丢弃策略, 不硬跑
## 三、阈值联动 (更正2 语义)
- WARN_THRESHOLD=6000 / HARD=9000 (config); L3/L4 用例设计 est 恰好跨 6k (触发) 与 <6k (不触发, 防抖对照)。
- L4 断言绑定 context_gate 打点 (est_tokens, mode) — 打点已有 (本计划新增 gate 消费)。
## 四、成本与节奏
- L3/L4 单次 ≈ 4-8 用例 × 3-8k tok → 单次跑测 ~30-60k tok (vs quick-11 ~11k) — 每周节奏可控;
- 首跑 = 校准跑 (不计 KPI 带, 收集 est_tokens 实测分布校准阈值), 之后入带。
