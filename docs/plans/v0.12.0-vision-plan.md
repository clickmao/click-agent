## 1. 官方事实核实 (2026-09-08, docs.bigmodel.cn)

- **glm-5.3-flash 无视觉能力** (coding 文本端点)。图像理解需接 **GLM-4.5V** (MOE 106B/12B 激活, 图像+视频+文件+GUI 任务) 或免费 **GLM-4V-Flash** (16K)。
- 端点: `https://open.bigmodel.cn/api/paas/v4/chat/completions` (标准端点, 非 coding 子域)。
- 请求格式: OpenAI 兼容; `messages[].content` 为**多段数组**: `{"type":"image_url","image_url":{"url":...}}` / `{"type":"video_url",...}` / `{"type":"file",...}` + `{"type":"text",...}`; 支持 base64 data URL。
- `thinking: {"type":"enabled"}` 开关。
- **待确认**: 4.5V 价格与 context_window (官网页未在抓取片段内, 开工时核实); 4.5V 是否支持 xlsx (文档理解列了 pdf/文档, xlsx 待验)。

## 3. 视觉调用链 (src/agent)

1. `LlmClient` (现有) 增加 `content parts` 序列化: 文本 string → 多段数组 (向后兼容: 无图时保持 string)。
2. `VisionRequest` 支持 local file → base64 data URL (image/png|jpeg, 上限待定 4MB)。
3. 意图路由: 新意图 `vision_qa` (输入含图片路径/截图引用时触发)。
4. 打点: `vision_call` 点位 (kv: model, image_bytes, image_format, ms, ok) + harness 消费键同步 init (缺陷58/60 教训)。

## 4. 无头浏览器插件服务 (能力增强计划)

- 插件契约: `IHeadlessBrowserPlugin` (Open(url) → ScreenshotBytes(png, width, height))。
- 默认实现: GitHub 开源 chrome headless (puppeteer/playwright 镜像之一, 开工时选型核实网络可达性)。
- 截图缩放: max width 1280 (可配), png → jpeg q85 (体积/上传成本)。
- 服务形态: 独立插件目录 `plugins/headless-browser/`, 注册进 DI, 用户可替换实现。
- 待确认: 部署机网络能否拉 chromium 二进制 (RST 阻塞名单核查)。

## 5. 图像理解 Skill (skills/vision-check/)

- 触发: 输入含截图/图片路径 + 校验类问题。
- 流程: 读图 → (若 URL) 无头浏览器渲染截图 → 缩放 → vision 模型问答 → 结构化结论 (PASS/FAIL + 证据描述)。
- 例: 「帮我开发一个页面, 左上角应该有 icon, 右侧一个 table…」→ 生成后启动无头浏览器截图 → vision 模型核对 icon/table → 输出校验报告。
