# v0.17.3 文件与执行层时序撞车检测 (R340 立项 — 用户钦定 2026-09-10)

> 用户指令: "新增v0.17.3增强：文件与执行层 时序撞车 检测" — 起因实证: AOT E2E 在 dotnet publish
> background 未完成时启动 → 跑了正在被覆盖的旧二进制 → /git 落 LLM 幻觉假输出 (表象), 真因是
> **发布/写入与执行撞车**。同族: R110 telemetry 竞争 / R257 轮号撞号 / 双进程写文件 (v0.17.0 已锁)。

## 0. 现状与缺口 (证据)

- 文件写已加固 (v0.17.0 FileLock/AtomicFileWriter) — **但只锁"写-写"互斥**; "写者 vs 读/执行者"无检测:
  执行者启动一个程序/读一个文件时, 另一进程可能正在原子替换它 (AtomicFileWriter tmp→Move) — 执行者拿到
  旧版或读到半程, 无感知 (AOT publish 覆盖 agenthost 时被并发执行 = 本事故)。
- 进程/产物时序无观测: 无"产物文件 mtime/版本 vs 启动时间"校验; 无执行前产物新鲜度检查。
- 撞号铁律 (R257) 只覆盖 eval 轮号; 泛化到任何"生产-消费同名文件"场景缺失。

## 1. 设计 (执行层时序撞车检测 = TTC, Time-To-Collision)

### T1 执行前产物校验 (ProcessRunner 层)
- 新 `ArtifactGuard`: 执行外部程序/脚本前, 若目标可执行文件路径存在:
  ①记录其 (size, mtime, sha256?) → ②进程启动后 100ms 复查 — 若 mtime/size 变了 → **撞车检测**: 输出
  警告 "⚠ 执行目标 {path} 正在被并发写入 (mtime 变化) — 可能运行旧版/半程产物" + 打点 artifact_collision
  + ExecutorLessonMemory.Record (频率加权) + 可选 --retry-after-settle (等 500ms 稳定再执行)。
- 适用: ScriptPluginRunner / SkillExecutor / GitOperations (git 二进制本身不会变, 但 cwd 仓库状态会 — git
  操作前 status 快照可比对)。

### T2 产物版本水印 (发布/写入侧)
- AtomicFileWriter 写后原子伴写 `<path>.meta.json`: {sha256, writtenUtc, writerPid, writerDesc} — 读方
  可校验自己读到的内容版本 (写-读撞车时 meta 与内容同 Move 原子成对, 读方先读 meta 后读内容, 若内容
  sha != meta.sha → 撞车中, 重读)。
- 适用高竞争产物: AOT publish 输出 agenthost、批测 JSON、RAG index。

### T3 时序撞车检测 API + 指令
- `CollisionDetector.IsSettling(path, minStableMs=500)`: 连续两次采样 (间隔 minStableMs/2) 的
  (size, mtime) 相同 → stable; 不同 → settling (写入中)。
- 指令 `/collision <path>`: 检测路径是否在稳定 (连续写中判定)。
- E2E 事故路径复验: 起 publish background → 立即 /git status → 若旧二进制被检测到覆盖中 → 警告而非幻觉。

## 2. 验收

1. 单测 ArtifactGuardTests: 写者线程持续改写目标文件 → 执行前校验检出 settling; 停写后 stable 通过;
   meta 水印成对 (sha 不符重读)。
2. E2E: publish 覆盖期间启动 agenthost → 检测到撞车 → 明确警告 (不再静默跑旧版); 稳定后正常。
3. 全量单测绿 + AOT 0 IL 警告 + quick-13 零回归。

## 3. 排除项
- 不做锁升级 (写-读加共享锁会阻塞 AtomicFileWriter 语义 — 检测+警告+重试足够);
- 不跟踪非本框架写入 (VS Code 等外部写由 v0.17.1 基线比对覆盖)。
