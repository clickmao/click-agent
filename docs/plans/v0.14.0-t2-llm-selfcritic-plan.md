# v0.14.0 T2 修订 — LLM 自审 (评审人角色) 方案 (R319, 用户钦定方向)

> 修订关系: 本文档取代 v0.14.0-thinkchain-self-critique-plan.md 中"排除 Self-Refine"的决策。
> 用户论点 (R319): LLM 可以承担评审人角色 — 其数据来源即【人类经验】, 对"这样写不好"的判断
> 本身是人类经验的检索与压缩。该论点成立, 且正好补上评审反馈显式化的最大短板: **评审人稀疏**。

## 1. 论点分析 — 为什么用户是对的, 以及边界在哪

### 成立的部分
- 常见反模式 (new[] 堆分配、async void、循环串拼接) 位于训练分布的**高密度区** — LLM 对这些的
  "这不好"判断不是瞎猜, 是数百万代码评审/StackOverflow 答案/风格指南的压缩检索, 可靠性与人类
  初级评审员相当甚至更高 (LLM-as-Judge 研究共识: 明确 rubric 下 good/binary 判断一致性高)。
- 评审反馈显式化的瓶颈从来不是"信号质量"而是**信号量** — 人少、懒、不覆盖长尾。LLM 自审把
  评审带宽从 O(人时) 放大到 O(token), 这是数量级差异。

### 边界 (设计必须处理的三类失效)
| 失效模式 | 表现 | 对策 |
|---|---|---|
| **过度批评** (假阳性) | 把惯用法/合理权衡报为缺陷, 噪声淹没信号 | 校准层: 与已有修法库/静态规则交叉验证, 无锚的降级为"观察"不入记忆 |
| **幻觉批评** | 引用不存在的"最佳实践"、错误断言行号 | 锚定要求: 每条批评必须含可复述的机制解释 (为何伤 GC/并发) — 无机制解释的丢弃 |
| **分布外瞎编** | 冷门领域陷阱, 训练密度低, 判断=编造 | 领域门控: 批测 rel 分差的领域 (有度量) 优先信任度量; LLM 自审只出"候选" |

**结论**: LLM 自审可以承担评审人, 但它的产出定位是**候选反馈** (candidate feedback), 不是已确认修法 —
需要过滤/标定层。这与人类评审员完全同构: 人类评审也会误报, 依赖被评审人判断与仲裁。差别只在
LLM 的误报率更高、且可无限供给 — 所以仲裁机制必须自动化。

## 2. 方案 — 三级过滤的 LLM 自审管线 ( Critic → Anchor → Memory )

```
LLM 输出
  │
  ▼
[一级] SelfCritic (LLM, 单次追加调用)
  输入: 输出原文 + 领域提示 (C#/日常/学术) + 反模式 checklist (OutputCritic R01-R08 的**概念**版)
  输出格式 (强制): {quote: 原文片段, mechanism: 机制解释, severity: high|low, fix_hint: 修法}
  约束: quote 必须是原文逐字子串 (防幻觉锚点) — 后处理校验, 不匹配即丢弃
  │
  ▼
[二级] Anchor 校验 (确定性, 零 LLM)
  a. 修法库查重: think-memory recall(quote+mechanism) top_sim ≥ 阈值 → 已知修法, 直接入库升级
  b. 静态规则交叉: OutputCritic 同点命中 → 强锚 (LLM 与规则独立同判, 双重证据)
  c. 度量器可用域 (代码: 编译通过性; 评测: rel 分差): 度量佐证 → 强锚
  → 强锚 = candidate_confirmed (自动入库 think-memory, 标 source=llm_self)
  → 弱锚 (仅 LLM 单源) = candidate_observed (打点观察, 不入生成上下文)
  │
  ▼
[三级] 标定回路 (批测自动化 + 人工抽查)
  - candidate_observed 累积 ≥N 次同机制命中 → 自动升级 confirmed (多次独立同判近似交叉验证)
  - 每 10 批 audit: 抽样 confirmed 修法人工复核 (既有制度复用), 误报→回滚并记录 critic 误报模式
  - 打点: self_critic{stage:emit|anchor|promote|reject, rule, sim}
```

### 与 R318 版的差异 (诚实对照)
| 维度 | R318 版 (排除 LLM 自审) | 本版 |
|---|---|---|
| 评审人 | 仅人 | 人 + LLM (LLM 供量, 人供标定) |
| 失败信号 | 度量/评审/规则三档 | 不变, 但 LLM 自审作为**第 0 级候选源**加入 |
| 成本 | 0 | +1 次 LLM 调用/含代码回复 (max_tokens 受限, 预算 ~600 tok) |
| 风险 | 漏报 (评审稀疏) | 噪声 (靠二三级过滤压) |
| Memory 污染 | 无 | 有防护: 逐字子串校验 + anchor 门 + 标定回滚 |

## 3. 落地拆解 (增量, 每步可验证)

1. **T2a SelfCritic 调用器** (`agent.critique/SelfCritic.cs`): 输入输出契约 + 逐字子串校验;
   开关 `AGENTFRAMEWORK_SELF_CRITIC=0` 默认关 (上线灰度: 先批测开)。
2. **T2b Anchor 校验器**: think-memory recall + OutputCritic 交叉 + (代码域) 编译探测。
3. **T2c Memory 写入流**: confirmed → think-memory 写 (source 标记) + 生成前 recall 注入
   (复用现有 R302 EnableAllSources 隔离机制, 防自审记忆污染主上下文)。
4. **T2d 标定**: 批测打点聚合 + audit 抽查制度扩展。

## 4. 度量 (5 KPI 对齐)

- **覆盖**: 含代码回复的 critic 调用率 (目标 100%) 与候选产出率 (≥1 条/回复)。
- **精度**: confirmed 修法的人工复核误报率 (audit, 目标 <20% — 人类评审同数量级)。
- **实效**: 注入修法后, 同类反模式在后续批次的复发率下降 (批间对比, 真断言)。
- **成本**: critic 调用增量 tok (目标 ≤ 批均 8%, 预算上限触发自动降级为仅静态规则)。
- **健康线**: 无 (新维度, 前 10 批只观察不定线)。

## 5. 验收标准

- [ ] SelfCritic 契约单测 (逐字校验/格式坏例/开关) ≥6 例
- [ ] Anchor 门单测 (修法库命中/静态交叉/无锚降级) ≥4 例
- [ ] 真机 E2E: 含 new[] 反模式的诱导题 → 自审命中 → anchor 确认 → think-memory 写入 → 下轮 recall 注入
- [ ] 批测 10 批观察期数据 (候选率/锚定率/误报抽样)
- [ ] AOT 重发布 0 IL 警告

## 6. 排除项

- 不做无预算上限的自审循环 (多轮 refine) — 单次 critic 调用, 重写仍由主生成承担。
- 不做无锚直入库 (LLM 单源自评不直接进生成上下文)。

## 6.1 任务主题锚定 (R319 用户纠正 — 替代"领域白名单门控")

> 原排除项"日常/学术域待标定数据"是错的: 系统不需要**领域标定**才critic — 会话本身携带
> **任务主题锚** (GoalText / intent / 画像 coreTopic / forecast), critic 的 checklist 应
> 按主题动态组装, 直接覆盖任何当前任务领域。

**主题信号链 (现成资产, 全部已在 OnProcessAsync 作用域)**:
| 信号 | 来源 | 用途 |
|---|---|---|
| `intent` | IntentDecomposer (L515) | 一级路由: code/creative/qa/... |
| `coreTopic` | 画像 GetContextBiasAsync top-1 (L535) | 会话核心主题词 (Web API/菜谱/...) |
| `goal.GoalText` | SessionMemory 锚定 | 当前任务全文 (最细粒度领域描述) |
| FixMemory.Recall | 修法记忆 pattern 匹配 | 该主题已知修法 → 直接成为 checklist 条目 |

**checklist 组装规则 (SelfCritic.BuildPrompt 已留 domain 参数, 补全)**:
1. 基础层: 通用经验 checklist (逻辑自洽/事实核查/结构完整 — 全域适用)
2. 代码层: intent 含代码 或 回复含 ``` → R01-R08 概念条目
3. **主题层: FixMemory.Recall(goalText + coreTopic) 命中修法 → "检查是否重蹈: {pattern}" 条目**
   — 该主题历史上被指出过什么, critic 就优先看什么 (会话内自我改进闭环, 无需预标定)
4. 领域词面: coreTopic 进 prompt ("领域: Web API 项目") — LLM 经验检索按主题定向

**效果**: 新领域 (日常/学术/任何) 无需先标定 — 第一条批评来自 LLM 通用经验 (分布内即有效),
经 Anchor 过滤后入 FixMemory, 第二轮起主题层 checklist 自动带上该修法。**标定是累积产物, 不是前置门槛。**
