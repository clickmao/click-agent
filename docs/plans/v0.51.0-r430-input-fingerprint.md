# v0.51.0 · R430 —— 判定输入指纹（P5c 残余来源判定）

状态: 已完成 (PASS; 证据 eval/rover/r430/README-evidence.md)（T0 预注册；本文件在读取本轮任何读数**之前**写入，器具代码与判据同批冻结）

## 1. 为什么有这一轮（机制，不引记忆）

R429（`14b6156`）钉死决策路径缓存：门判/关系判官显式 `CacheReuse=false`。收口时留下两条**未过**的预注册判据：

- **P4 未过**：传输级 20 次 cache-on 门判全为 P，未观测到判定翻转 ⇒ 只证「判定**输入**不可复现」（弱宣称）。
- **P5c 证伪**：钉死后同一批同文消息的 4 次门判，生成文本 `raw_len` 仍取 4 种值（`113/105/102/100`；重复轮 `128/108/111/113`）⇒ **文本级逐位复现未达成**。

「逐位不同」有一个绕不过去的前提问题：**我并不知道这 4 次调用送进引擎的输入是否逐位相同**。若输入本身就不同（prompt 文本或请求字段被改动），那么「引擎不确定」这个结论**根本无从谈起**；反之若输入逐位相同而输出仍不同，则不确定**必在引擎侧**，且是可复现的强结论。

R429 的读数只含 `raw_len/cache_n/pinned`，**缺输入侧锚点** ⇒ 这一轮先把锚点做出来，再用它判。

## 2. 假设（互斥，二选一必须落地）

- **H1 输入侧漂移**：同一批同文消息，门判构造出的 prompt 或请求字段逐轮不同。
  - 子假设 H1a：角色种子漂移（`ActiveRole.Id|Clip(ProfileSeed,80)`）。
  - 子假设 H1b：请求字段漂移（`n_predict` / `samplers` / `cache_prompt` / `seed` 等）。
- **H2 引擎侧不确定**：输入逐位相同（prompt 与请求体指纹均恒定），生成文本仍逐位不同 ⇒ 不确定在 llama.cpp 侧（数值/调度）。

## 3. 器具（纯观测，不改生成与判定）

- `agent.modelqueue.LocalInputFingerprint`：`Sha16(text)` = SHA-256 前 8 字节 → 16 小写 hex（**无随机盐、无时钟、无 Guid**）；`Describe(...)` = 请求关键字段摘要（`np/t/sp/cp/seed/tk/tp/mp/rp`）。
- `LlamaCppClient.CompleteAsync`：对**送达服务端的渲染后 prompt**（`CompletionOptions.Prompt`）与**请求体 JSON**（`JsonSerializer.Serialize` 源生成器）各取指纹；把 `PromptSha16/RequestSha16/RequestFields` 放进 `CompletionResult`。
- 贯通四层：`LlamaCppTextGenerator`（`LastPromptSha16/LastRequestSha16/LastRequestFields`）→ `LlamaCppLocalGenerationPort`（`LocalGenerationOutcome` 三字段）→ `ModelQueueRouter`（`TurnGate.LastPromptSha/LastRequestSha/LastRequestFields` + `RecordRoleSeed` → `LastRoleSeedSha`）→ `IndustrialAgentV2` 门判遥测 `prompt_sha/request_sha/req_fields/role_seed_sha`。
- 缺失语义：后端不上报 ⇒ 空串，**缺失 ≠ 错误**（负控 F6）。
- 服务端精度档（先核实，非假设）：`LlamaServerOptions.CacheTypeK/V` 默认 **f32/f32** 且 `FlashAttention=false` ⇒ 产品运行档与 R429 传输级探针（f32、cache 关、15/15 逐位相同）**同档** ⇒ KV 精度不是本轮变量。

## 6. 诚实边界（先声明）

- 指纹 = SHA-256 前 8 字节（16 hex）。碰撞概率量级 2⁻⁶⁴，非零 ⇒ 结论以「16 hex 相同」为等价类，不宣称逐字节相同。
- 指纹覆盖 prompt 文本与请求体**字段值**，但不覆盖服务端**未显式传入的默认值**（如 llama.cpp 内部默认采样链），故 H2 成立时的归因止步于「引擎侧」，不细分内核。
- 幂等性：指纹只观测；判定结论仍以 R429 已钉死的缓存关闭为前提。

## §3 结论（读数后追加；判据见 §1，未改判据）

**判定路径逐位可复现 = 达成。**

| 判据 | 读数（机检） | 判定 |
|---|---|---|
| P1 输入指纹恒定 | 真机 4 次门判 `prompt_sha` 1 种 / `request_sha` 1 种 / `role_seed_sha` 1 种 | PASS |
| P2 漂移在引擎侧（H2） | 输入恒定而输出 raw 逐字节 sha16 **4 种**（raw_len 122/129/113/111）；H1（输入漂移）证伪 | PASS |
| P3 机制 = 并发在途 ⇒ 批组合 | 默认 `n_slots = 4`（启动日志）+ 并发在途 ⇒ 同一 prompt 2 种 token 序列（105/105/108）；串行基线 75 | PASS |
| P4 修法 = 显式 `-np 1` | 并发下强制 `-np 1` ⇒ 3/3 逐位相同；真机同文 4 次门判 raw 逐字节同一（sha16 ×4 相同） | PASS |
| P5 判定/KPI 不退化 | 判定仍 `Skip×4`、cache_n 恒 0、pinned 1..4；远端 2→1、token 2053→1996；全量 1242/1242、AOT IL 0 | PASS |

**机制落点（承重）**：本仓库 llama.cpp 构建的 `-np` **默认 = 4**（未显式声明时）；4 个槽可在同一批里并行处理
不同序列 ⇒ 每个序列的批形状/分块取决于**同时到达的其它请求** ⇒ 浮点归约顺序变 ⇒ 同一 prompt + 同一请求体
（cache_prompt=false、greedy、temp=0）走出不同轨迹。**只关缓存不够，必须总槽位 = 1（真串行）**。

**修法（已落产品代码）**：`LlamaServerHost.BuildArgumentList`（纯函数，可测）**无条件**追加 `-np <Parallel>`，
`Parallel` 默认 1（`LlamaServerOptions` / `LlamaCppGeneratorOptions` / `LlamaCppEmbedderOptions` /
`ModelCatalog local.parallel` / DI 接线），非正值夹到 1。

**诚实边界**：① 未测修法后判定/回复**质量**变化（本轮只测可复现性与 KPI 计数）；② `-np 1` 的代价是本地通道
真串行（判官本地调用与门判互相排队），墙钟增量未量化上限；③ G3（`-np 2` + `id_slot`）本次亦 3/3 相同，但依赖
**每次调用钉槽位** ⇒ 仅作备选记录，不作为能力宣称；④ 探针 v1 有「渲染早于起服务」与末段取值 bug（v2 已修并
增量落盘）；⑤ 单机单次读数，P2/P4 的**变体个数**不构成判据（机制结论不依赖具体个数）。
