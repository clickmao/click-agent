## 0. 目的（先定目标函数，防"为编排而编排"）

**唯一目的 = 三 KPI**（不达标即回退此计划）：

| 指标 | 现状 | 目标 |
|---|---|---|
| ① tokens | 一切（含本地可完成的工作）都走一次 LLM 单轮 | 本地可完成的节点 **零 LLM 调用 / 零 token** |
| ② 端到端耗时 | 远程生成期间本地空等（全串行） | 无依赖的本地下游节点在远程 in-flight 期间**先跑**（真并行） |
| ③ 前端可见性 | 前端 API 无步骤/计划通道，用户只见最终回复 | 每节点 **location(本地/远程)/state/依赖/产物/耗时/tokens** 可推送可查 |

**反向约束（用户钦定）**: 新增结构若不能在上述三项上被测量到改善，即视为"编排表演"，不得合入。

## 2. 根因（按失败模式表归类）

| # | 类别 | 说明 |
|---|---|---|
| R1 | **断链**（头号失败模式） | 组件（拆解/计划/引擎/本地执行体）全部存在且单测绿，**调用方没接**：主链注入哑执行体 → "策略永不触发" |
| R2 | **缺维度** | 本地/远程路由不是实现遗漏，而是**从未建模**（模型无字段、Builder 无判定）→ 前端即使想画也无数据 |
| R3 | **归属错位** | 本地执行能力挂在"LLM 单轮输出**之后**的产物闸门"，没有挂到"计划节点**之前/之中**"→ 结构上不可能"先本地做" |
| R4 | **通道缺失** | 前端 API 只有 ask/reply + 通用 envelope；计划/节点状态无事件 |
| R5 | **KPI 盲区** | `loop_turn`（`IndustrialAgentV2.cs:1555-1558`）不带计划/产物结论 → 本地省了多少 token、并行省了多少秒，一律不可测 |

## 3. 设计（最小真闭环；每项都必须能被 KPI 或前端观察到）

### D1 计划节点增执行位置（数据模型）
`PlanNode` 新增（AOT 纯数据字段，走 `TaskPlanJsonContext` source-gen）：
- `ExecutionLocation Location` ∈ `{ Local, Remote, Hybrid }`
- `string? LocalExecutorId`（如 `python.run` / `skill.script` / `isolate.task` / `text.process`）
- `string? LocalHint`（判定依据短句，供前端显示"为什么这步可以本地跑"）

### D2 判定规则 = **确定性表**，不是 LLM（关键：不得让 LLM 拍脑袋分类）
来源 = 既有能力事实：
1. 本地有能力执行器（`LocalExecutorRegistry`，登记 `python.run`/`skill.script`/`isolate.task`/`text.process`/`file.op`…），且
2. 任务类型映射命中（代码产物/文本处理/文件操作/状态反核 = 可本地；纯推理/创作/信息检索 = 远程），且
3. 节点参数齐备（`IsExecutable`）且无敏感/凭据依赖
→ 三条全真 = `Local`；需要生成新内容 = `Remote`；两者兼有 = `Hybrid`（远程生成 → 本地跑/验，正是用户原话场景）。
**负向控制**：映射未命中或本地执行器缺失 → 必须落 `Remote`（不得乐观判 Local）。

### D3 真执行体注入（替换哑体）
主链注入真 `nodeRunner`：
- `Local` → 本地执行器（`PythonRunVerifier`/`ScriptPluginRunner`/`IsolatedTaskRunner`），**零 LLM 调用**，产物落 `data/artifacts/` 并复用现有台账/闸门
- `Remote` → `ModelQueueRouter`（token/缓存 KPI 复用现有打点）
- `Hybrid` → Remote 生成 → 立即本地执行/校验（复用 `ArtifactRepairLoop` 语义，但**由节点驱动**而非整轮驱动）
- 关闭开关：env `AGENTFRAMEWORK_PLAN_EXEC`（默认开；=0 回退哑体，保留旧行为可比对）

### D4 本地先行（真并行，用户的"等待期先跑起来"）
- 已有 `TaskPlan.ExecutableNodeIds` + `MaxParallelism` 作为调度入口
- 规则：远程节点发起后**不阻塞**，同层（`ParallelGroup` 相同 / `Level` 相同）无依赖的 `Local` 节点**立即执行**；本地完成后若命中远程节点的前序产出依赖才阻塞等待
- 并发上限：`MaxParallelism`（默认 4）+ 本机 2 vCPU 实际钳制（`Environment.ProcessorCount`），防 CPU 打满拖慢远程回程解析

### D5 前端可见（用户原话的"给到前端API显示"）
- `FrontendEventHub` 增事件（复用 `EmitAsync` envelope，AOT source-gen 序列化）：
  `plan.created`（节点树：id/text/intent/location/executorId/dependsOn/level/parallelGroup）
  `plan.node`（state: Pending→Running→Completed/Failed/Skipped；耗时 ms；tokens；产物路径）
  `plan.finished`（总耗时、本地节点数、远程节点数、**本地节省 token 估算**）
- `/plan` 保留（拉取式兼容）；事件为推送式，前端可只订阅

### D6 KPI 打点（否则无法证明不是编排表演）
- 新点位 `plan`（节点数/本地数/远程数/并行组数）+ `plan_node`（id/location/executor/state/ms/tokens/artifact）
- 验收对照：**同题**（PY 开发小游戏）优化前后 —— ① LLM 调用次数 ② tokens ③ 端到端 ms ④ 前端可见节点数

## 4. 约束（违反即返工）
1. **不为编排而编排**：每项改动必须能落到 D6 的四项对照数字上。
2. **零反射 / AOT 可用**：计划与事件序列化走 source-gen（`TaskPlanJsonContext` 同族）；不引入动态类型。
3. **跨平台零 shell**：本地执行一律 `ProcessStartInfo.ArgumentList` 直连（沿用 `PythonRunVerifier` 既有做法）；tmux/真机按键属**探针层**，不进产品路径。
4. **确定性判据**：D2 判定为纯函数，可单测；与提示词注入（`SessionBaseline`）**同源**，防"提示词与闸门漂移"。
5. **诚实边界**：本地执行失败不得静默降级成"远程重做"来掩盖；节点失败如实标 `Failed` 并保留产物。
6. **门禁**：新增能力必须有"消费方断言"测试（防再现 R1 断链）；无消费方 = 不合并。

## 5. 验收（真机）
1. **单测**：D2 判定矩阵（Local/Remote/Hybrid 各正例 + 负向控制）；D3 执行体注入后"哑体不再被使用"的反向断言；D4 并行序（本地节点在远程节点完成前已 Running/Completed）。
2. **真机 A（PY 开发小游戏，同题对照）**：`plan.created` 事件含 `location` 字段；`plan_node` 里出现**至少一个 Local 节点在 Remote 节点之前/并行完成**；tokens 与 LLM 调用数 **不高于**优化前同题。
3. **真机 B（文本处理类）**：远程生成 → 本地立即跑（`script_run` 出现在远程调用之后但**不新增 LLM 调用**）。
4. **前端**：订阅事件可见节点树（location 标注"本地/远程"），节点状态实时变化。
5. **AOT**：发布 tag 轮校验 0 IL 警告（登记口径 `aot_check_policy=release_tag_only`）。

## 6. 排除项（本轮不做）
- 不做分布式/多机调度（本机单机场景）。
- 不做"计划可视化 UI"（前端实现方负责，本仓库只暴露事件与字段）。
- 不做 MCP / 外部生态接入（既有立场不变）。
- 不重写 `IntentDecomposer` 拆解质量（本轮只做"路由 + 真实执行 + 可见性"）。

| 抢跑入口 | `PlanRunner.StartLocalFirst(plan, ctx, ct)` | 在**计划构建时**（模型调用前）启动；无此类节点 → 返回 `null` + 打点 `plan_local_first state=skip`（**不许假装先行**） |
| 结果复用 | `RunAsync(..., localFirst, remoteWindow)` | 先 `await` 批次、把 `Results/Outcomes` 灌进主跑；节点命中缓存**直接返回** ⇒ 绝不双跑（`plan.node` 事件数 = 节点数 是断言） |

### 9.5 诚实边界（本轮新增，必须写下来）

1. **`remote_tokens` 记 0**：LLM token 只在 `llm_call` 点位按**会话**计，尚未归因到计划节点 ⇒ `plan.finished.remote_tokens` 目前无意义（本地 tokens=0 是真的，远程=0 是**缺归因**，不是省了）。
2. **重复计算（新发现）**：拆解器把"且统计我这段需求描述的字数"单独拆成一个 `general` 远程节点 → **LLM 也算了字数**（模型报 118，本地确定性统计 117）。本地节点确实零 token 先跑，但**同样的活被远程又干了一遍** ⇒ 省 token 的收益被拆解粒度吃掉。修法（下一轮 D4b）：源文本动作命中时，从**远程节点文本**里剔除该动作 / 或在拆解阶段就把它标为 `text_processing`（属 §6 排除的拆解器改造）。
3. **`Wired=false` 仍不路由**：`realmachine.replay`/`command.local` 未接线（D3b）。
4. **`AGENTFRAMEWORK_PY_RUN` 默认关**（T4 未决）：默认配置下 `python.selftest` 记 `Skipped`。
5. **本地先行只覆盖"无依赖"节点**：与远程产物有依赖的本地节点（如自测）必须等产物，谈不上并行 —— 这是定义使然，不是缺陷。
