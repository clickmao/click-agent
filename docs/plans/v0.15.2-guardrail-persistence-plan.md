# v0.15.2 警告/铁律持久化与违规联想抑制 (设计文档, R324 立项 — 用户钦定)

## 需求原文 (用户钦定, 语义保真)

"用户多次警告/违规 RAG 持久化（之前有做过联想，类似联想能力，最终目的: 相似的违规操作不再轻易发生，
但一定要注意，违规操作所在主题覆盖领域）。检视语言逻辑学与心理学并设计【用户主动提醒违规/警告/
铁律等重要信息的持久化方案】并实施工程。完成后增加结果确定性的多领域样本和负样本并进行循环跑测优化。"

## 1. 需求拆解 (前提先行)

| 前提 | 语义 | 设计映射 |
|---|---|---|
| 用户多次警告 | 警告是**重复出现**的信号 — 一次性错误 ≠ 铁律 | 持久化条目带 confirmations (复用 FixMemory 来源秩/合并模式) |
| 违规操作 | agent 的输出/行为曾被用户判定为违规 | 违规记录 = (触发模式, 违规内容特征, 领域, 铁律文案) |
| 类似联想 | 相似情境下**主动联想**到历史警告 | Recall 触发: 新输出/新输入与已记录模式匹配 → 注入警告 |
| 不再轻易发生 | 度量 = 同类违规**复发率下降** | 批测复发率对比 (真断言, R149) |
| 主题覆盖领域 | 违规有领域性 — 铁律只在相关领域生效, 不跨域泛扰 | 条目带 domain (来自会话主题锚 S1-S4); recall 按 domain+pattern 双键 |
| 语言逻辑学 | 违规表述的逻辑形态 (条件/例外/量词) — 铁律文案需保留**逻辑结构** | 条目存"逻辑形态"字段: 全称/条件/例外 (如"除非X否则不做Y") |
| 心理学 | 行为修正机制: 提醒时机 (前置>后置)、重复效应、具体>抽象 | 前置注入 (生成前) 而非事后批评; 具体案例随铁律注入 |

## 2. 语言学/心理学检视 (设计依据)

### 2.1 语言逻辑学 (铁律的逻辑结构)
- **全称禁令** ("永远不要X"): 过宽 — 用户警告常带隐含条件/范围。
- **条件规则** ("在Y情境下不要X"): 正确形态 — 存储时保留触发条件。
- **例外保留** ("除非Z"): 必须存 exceptions 字段 — 否则联想抑制会误伤合法操作。
- 设计: 铁律条目 = `condition(情境) + prohibition(禁令) + exception(例外)` 三元组, 注入文案按三元组渲染
  ("在{condition}时, {prohibition}{exception}") — 保留用户的逻辑限定, 不做无界泛化。

### 2.2 心理学 (行为修正有效性)
- **前置提醒优于事后纠正** (proactive > reactive): 警告在**生成前**注入 (ContextAssembler 源),
  而非违规后再批评 — 与 L1/L3 牵引同点位哲学。
- **具体案例 > 抽象规则** (concrete > abstract): 铁律附原始违规案例片段 (脱敏), 少样本效应。
- **重复与间隔** (spaced repetition): 相似情境每次命中都注入 (重复强化), 但**同会话内去重**
  (同会话反复注入同一警告 = 噪声, 心理学 habituation 习惯化反而弱化响应)。
- **负样本价值**: "什么不违规" 也要记录 (被用户认可的类似操作) — 防止过度抑制 (chilling effect)。

## 3. 工程 — GuardrailMemory (复用 v0.14 骨架)

```
GuardrailEntry {
  id, domain,              // 领域 (会话主题锚: goalText+coreTopic 归一)
  pattern,                 // 触发模式 (关键词/形态 — recall 键)
  condition, prohibition, exception,   // 逻辑三元组
  origin_case,             // 原始违规片段 (脱敏, 少样本)
  source,                  // human_warning (用户主动) | review | metric
  confirmations,           // 多次警告合并
  created_utc
}
持久化: data/guardrails.json (STJ source-gen, FixMemory 同款)
```

### 注入链 (生成前, ContextAssembler 新源 Guardrail → DataSourceType.GuardrailMemory)
1. 触发: Recall(用户消息 + goalText + coreTopic) — domain 匹配 + pattern 匹配双键。
2. 渲染: "⚠ 铁律 (历史警告): 在{condition}时{prohibition}{exception}。案例: {origin_case}"
3. 同会话去重: 会话级 _injectedGuardrails 集合 (habituation 防护)。
4. K1 隔离对齐: FULL_ISOLATION 下剔除 (R302 教训, FixMemory 同款)。

### 写入链 (两个信号源)
- 用户主动警告: 用户消息含警告语义 ("不要/禁止/以后别/警告你/记住了") + 负面指向 → 提取三元组
  (LLM 辅助解析, 结构化校验后入 entries, source=human_warning, 最高秩)。
- 批测违规: C 系负样本 FAIL 模式转正 (metric 信号)。

## 6. 排除项

- 不做违规内容自动判定 (是否"违规"由用户/评审判定 — LLM 自判危险高, 与 R318 失败定义一致)。
- 不做跨域泛化 (领域门控是特性不是缺陷)。
- 不做自动惩罚/输出拦截 (只注入提醒; 硬拦截待度量表成熟后评估)。
