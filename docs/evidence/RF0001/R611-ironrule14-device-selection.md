## 5 外部器件查证（**R613 起仅作否决理由库/备查；本仓不采用**）

**Laya**（`github.com/NandhaKishorM/laya`，Apache-2.0，`pip install laya`；发行方 convaiinnovations）—— 用户已令**不用**
- 形态 = 开源 System1 决策器；原语 `choice` / `score` / `noul`；**单次前向出校准概率**。
- 官方口径 32.8 ms（单 GPU 中位），与用户「32ms」吻合；对照 Jev 官方 236–276 ms。
- 官方自陈四条坑（**随条文保留**）：① 开箱 ≈0.35（近随机）⇒ **须域内微调**（微调后 0.995）；② 选项 >20 显著退化（Banking77 0.425 vs Jev 0.870）；③ **非拉丁脚本高置信错判**（Khmer 0% 准确率却报 95.2% 置信度）；④ 仅 Python ⇒ **入 NativeAOT 栈必须先 ONNX 化**（PyPI 件不可直接引用）。
- **另注（避免误导）**：XGBoost 与 Laya 不可并列 —— 树模型是 CPU 微秒级、零依赖、可导成纯 C# 打分器（天然过 AOT）；Laya 是 421M 双向编码器（ModernBERT-large）、32.8 ms 为单 GPU 读数。

**实测口径出处**：「延迟降低 95%，成本降低 85-91%，任务成功率不变」= **外部出处**（TabAgent，arXiv **2602.16429**，AppWorld / CUGA 设定；摘要逐字 `reducing latency (by ~95%) and inference cost (by 85–91%)`）。TabAgent 把 GPT-4.1 生成式决策头换成 ~50M 分类器（2.682 ms / $2.0e-7 per read vs GPT-4.1 的 7.50 s / $0.052）；同篇把 LLM 当决策头 1B/3B/8B = 100.48/198.12/378.42 s per read ⇒ 方向支持「NLP 当决策主体」，反对「本地 LLM 当决策头」。**R613 起该组数字定位为「终局目标口径」。**
**本仓未复现该量级**（本机 3B 判别位 17.2 s/例，差四个数量级）⇒ **方向可搬、量级不可搬**，禁直引为本仓结论。本仓可对照口径：prompt 9,576 vs 12,925（省 26%）· 缓存命中 0.9477 vs 0.9315 · 质量轴 R602–R606 多为未达标 · R612（判别位真实流量 42 次门判全为机械族/守卫、真问本地 0、台账决策率 11.93%）。
