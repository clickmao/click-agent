## 3 设计 (本轮实现)
- **新件 `src/agent/intent/NodeScopeFile.cs`**: 范围文件 DSL `nodeId | 路径[,路径]` (行内 `#` 注释; 尾部 `/` = 目录前缀, 含 `*` = 字面前缀通配)。
  - `ParseText/Load` fail-closed: 字段数不足 / 节点 id 空 / 重复声明 / 空范围 / 越界路径 (绝对路径、`..`) ⇒ Problems 非空且 Scopes=null。
  - `InScope(scope, relPath)`: 精确 / 目录前缀 / 前缀通配三态; 边界 `out` 不匹配 `out2/x` (段边界判定)。
  - `Overlaps(a,b)`: 前缀关系判定 (空前缀视为全覆盖 ⇒ 保守拦)。
  - `Validate(plan, scopes)`: ① 范围指向未知节点 ⇒ 红 ② **同层 (会并发) 两个已声明节点范围重叠 ⇒ 红** (跨层串行允许)。
  - `Undeclared(plan, scopes)`: 未声明节点 id 列表 (诚实面: 未声明 = 不参与重叠判定, 报告单列)。
- **`src/agent/intent/TaskOrchestrator.cs`**:
  - `Options` 新增 `WorkspaceRoot` / `NodeScopes` / `RequireScopedArtifacts`(默认 true)。
  - 节点执行前后做工作区快照 (`Snapshot`/`Diff`, 跳过 `.orchestrator*` 等内部目录) ⇒ `NodeArtifacts` 逐节点归属 (替代宿主侧实现, 单一权威源)。
  - `EnforceScope`: 仅对 `Completed` 且已声明范围的节点生效 —— 越界 ⇒ 改判 `Failed`; 无范围内增改 ⇒ 改判 `Failed`(假绿防护)。
  - `ScopeViolations` / `ValidateScopes` (静态门面) 公开; `NodeTelemetry` 增 `Scope` / `Artifacts` 两个 init 属性 (位置参数不变 ⇒ 既有构造不破)。
- **`src/agent.host/OrchestrateCommand.cs`**:
  - 新增 `--scope <范围文件>`; **在读配置/建 agent 之前** load+Validate ⇒ 违规直接 `rc=2` (零 token, 零 adapter 请求)。

  - 报告新增 `scope_file` / `scope_undeclared` / `scope_violations` / `requires_scoped_artifact`, 每节点新增 `scope`。
