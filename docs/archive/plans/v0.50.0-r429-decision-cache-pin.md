## 1. 问题（因果链）
KPI = 一轮总 token 显著下降 ≥30%（主因 = 不必要的远端请求少了）。
R425 已证前置门能砍掉主调用；R426 把关系判官本地化后再降一档，但 **k8 格 token 反高 2420**（相对 R425 臂 B）。
唯一可见原因 = **门判翻转**：臂 B 6×Skip → 臂 C 5×Skip+1×Pass ⇒ 多出 1 次主链调用（≈2524 tok），远超判官省下的量级。
R426 记「归因未定（同一 r1 端口被门与判官争用下的缓存态差异）」。本轮先钉死机制，再修。

## 3. 假设
H1 同一门判 prompt 在 `cache_prompt=true` 下，**命中**与**未命中**两种缓存态产出不同 token 序列。
H2 H1 的漂移足以让 S/P 判定翻转（把漂移与 R426 观察到的翻转接上）。
H3 `cache_prompt=false`（决策路径钉死缓存态）下，同一 prompt 任意交错均逐位相同。
H4 产品级：PRE 二进制 k8 臂 C 复现翻转；POST（决策 cache 关）门判序列 == 臂 B，且 token 不高于 PRE 臂 C。
