# v0.58.0 R438 — 本地消化轮不得把「从未发出的」内联块带进会话历史（缺陷修复）

> 立档：R438（2026-09-15）。承重 KPI 不变：**用户一轮任务总远端 API token 降幅 ≥30%**（R413 令）。
> 本轮类型：**产品缺陷修复**（非新功能、非调参）—— 一次性消除一类「白付账」token。

**缺陷**：本地消化轮（无远端发送）的内联块经 F2+F4+F5 落进会话历史，被此后**每一次**远端调用逐字回放。
从未发往任何 provider 的字节 ⇒ 不构成任何 provider 缓存前缀的一部分 ⇒ **纯白付账**，且随会话长度超线性增长
（每个跳过轮的块会被"剩余所有远端轮"各回放一次）。

**实测规模（R436 归档 calls-BRJ-p12.jsonl，逐字节重放）**：p12 有 4 个跳过轮（turns 2–5，由 `verdict-BRJ-p12.json`
的 `per_turn[].actual==skip` 程序化派生），其块在 6 次远端调用里被回放，合计 **2238 token = 分母的 8.09 pt**。

## 2. 前提拆解（改之前必须先证明「安全」）

- **缓存红线不受影响的前提**：R379 前缀不变量的约束对象是**已发送字节**。provider 的缓存前缀 = 上一次远端调用的
  完整 prompt；跳过轮的条目前缀于该点**之后**，且该轮**没有任何发送** ⇒ 剥离跳过轮条目中的块，**不改变**
  任何已缓存前缀区间内的字节。形式化判据见 C5（相邻远端调用「前一次请求 = 后一次请求的前缀」机检）。
- **信息不丢的前提**：会话记忆/预估块由**会话台账**逐轮重建（不是从历史消息里读块）。R436 实测证据：turn3 的块
  已列出 `【已完成】…把构建命令写成一行。; 谢谢，收到。; 好的，明白。` ⇒ 累积信息在**本轮新块**里重建一次，
  与历史里是否留着旧块无关。RAG/预估同理（各自独立存储）。
- **用户可见行为不变的前提**：本地回复的生成仍使用**含块**的 `prompt.UserMessage`（`1541` 行传参不变）⇒
  跳过轮的回复文本逐字不变；只有**历史里存什么字节**变了。

## 3. 修复（最小 diff）

在跳过分支（`IndustrialAgentV2.cs:1538`）内，落定 `message.SentContent = outboundText;`
（= 用户轮原文，扣掉框架自做子请求；**不含**本轮内联块，与首轮同形——首轮无块可挂）。
