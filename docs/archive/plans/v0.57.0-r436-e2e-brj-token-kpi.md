## 2. 待验证的主断言（本轮唯一承重）

> **A ≥30%**：在**同一 12 轮题集**（`tree task-p12`，R434 §14 预注册，**不改一个字符**）、**同一 AOT 二进制**下，
> 臂 **BRJ**（`turn_gate=true ∧ relation_judge=true ∧ role=growth(域3)`）的**远端 API token 总量**
> 相对 臂 **A**（`turn_gate=false`：全远端分母）下降 **≥30%**，
> 且下降的**主因**可归因到「不必要的远端 LLM API 请求变少」（远端 J 判官调用数）。

R434 同题集读数（旧二进制，J 全远端）：A=27670 / B=19990（**27.8%，未达 30%**）。
R435 单组件读数（探针层，非端到端）：本地可解析 1/6 → 5/6，**远端判官调用 6 → 1（投影，非实测）**。
⇒ 本轮要回答的正是：**这个探针层增益在产品端到端链上是否兑现，并足以把 27.8% 推到 ≥30%**。

## 4. 器具（本轮已发现并修的两处仪器缺陷）

1. **结算条件竞态（真缺陷）**：判官在 `Task.Run`（`IndustrialAgentV2.cs:1665`），R434 器具 `run_arm.sh:91` 只 `sleep 25` 就结算 ⇒ 远端 J 快（<1s）时侥幸不漏；**J 改本地后单次 15–32 s**，8 次要 2–4 分钟 ⇒ `sleep 25` 必然**少计**后期的 J 调用与 token。⇒ R436 器具改为**静默收敛等待**（`correction_judge` 事件数与桩 calls 行数在 **70 s** 内不再增长，或达到 700 s 上限），并把「等待秒数/最终事件数」落盘。
2. **通道标记手打风险**：`settle_r434.py` 把 `J_SYS="只输出一个字母"` 与锚点写死在脚本里；R435 已改 prompt 形状 ⇒ 本轮新增 `channel_marks.py` 从**源码**派生全部标记（解码 C# 转义 + 断言：无 U+200B/U+200C/U+200D/U+FEFF、长度、结构），并**先在 R434 磁盘档案上做复现性负控**（分类器重算旧档案须复现已登记的 G/J 计数，否则 fail-closed）。
