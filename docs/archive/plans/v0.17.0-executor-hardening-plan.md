## 1. 设计

### T1 跨进程文件安全写基建 (src/agent.io/FileLocking.cs — netstandard2.1 零依赖 AOT 兼容)
- `FileLock` : 跨进程 advisory 锁 — 锁文件 `<path>.lock` 以 FileMode.OpenOrCreate + FileShare.None 持有 (或目标文件直接 FileShare.None 探测); TryAcquire(timeout, 退避 50ms×3 级) / Release / IDisposable。
- `AtomicFileWriter` : 写 `<path>.tmp-<pid>-<rand>` → Flush(true) → File.Move(tmp, path, overwrite) — 读者永不见半写文件。
- `LockedFileSession` (用户点名场景): Acquire 失败 → **占用者检测** (T2) → 持续等待观察 (指数退避 ≤N 秒) → 拿锁后读现文件 → 与预期内容**比较差异** → 由调用方给合并策略 (覆盖/并入/放弃) → 原子写回 → 成功或超时返回失败原因 (结构化)。
- 锁文件自清: Release/Dispose 删除; 崩溃残留: 锁文件含 pid, 检测 pid 存活 (kill -0) 否则判定 stale 接管 (R257 同款 mtime 协议)。

### T2 占用者检测 (Linux /proc 系, FileLocking 内)
- 读 `/proc/locks` (POSIX/OFD 锁记录: 文件 inode) + `/proc/<pid>/comm` + `lsof` 不可用降级 → 占用者 = pid + comm ("文件被 PID 2576161 (agenthost) 占用"); 非 Linux 降级 "未知占用者 (平台不支持 /proc/locks)"。
- FileLock 的 lock 文件含 pid → 冲突时立即给出占用者 (无需 lsof)。

### T3 失败教训临时记忆 (src/agent/executor/ExecutorLessonMemory.cs)
- 执行层失败事件 (IO 冲突/超时/占用) → 记录 {pattern 键 (错误类型+文件/操作域), count, 首现/最近时间, 解决方案 (重试/合并/等待), 触发上下文 (最后 1 行)}。
- **频率加权增长** (用户钦定: 随教训频率提高记忆越长): 同 pattern count 1 → 摘要 1 行 (注入时 ~40 词); count≥3 → 补解决方案; count≥8 → 补触发上下文+统计 (教训升级); 每次注入前整体衰减 (TTL: 24h 无命中降级 count, 7d 无命中移除)。
- 注入点: 执行层尝试 (写文件/起进程) 前, 命中 pattern → 注入 system 侧提示 (FixMemory 同款但瞬时执行域, 不进 RAG)。
- 持久化: data/executor-lessons.json 原子写 (经 T1)。

## 2. 关键约束

- netstandard2.1 (agent.io) 无 Process → /proc 读取用 File; FileShare.None/File.Move 均可用。
- 禁反射/禁 Console.WriteLine (agent 本体; agent.io 现无 Console 依赖保持)。
- AOT 验收 (发布形态铁律): T1-T4 全链 AOT publish 0 IL 警告 + AOT 实机双进程竞争测试。
- 与 R332 的关系: run_round 每 case 前清 sessions 是**评测隔离** (单 agent 顺序), v0.17.0 是**真多 agent 并发** (sibling/双实例), 不冲突不重复。

2. ExecutorLessonMemoryTests: 同 pattern 3 次 → 方案注入; 8 次 → 上下文注入; 24h 无命中衰减/移除 (时钟注入); 持久化往返。
3. T4 接入点回归: TaskCharter/Guardrail 既有单测全绿 (546+ 全量)。
4. 批测 quick-13 13/13 零回归。
5. AOT publish 0 IL 警告 + 双实例真机竞争 smoke (两 agenthost 同时写 guardrails.json, 双方均成功无半写)。
