## 1. 调研结论

### 1.1 trae SOLO 模式 (官方文档)
- 核心: 自然语言需求 → Agent 自主**规划 (plan 先行, 用户确认后执行) → 逐步执行 → 预览/验证**;
  任务管理面板支持多任务并行; 工具面板 (编辑器/浏览器) 支撑执行。
- 关键语义: "一句话" = 需求级输入; SOLO 负责**分解 + 执行 + 验证 + 交付**全链。

### 1.2 长任务验收 (SWE-Marathon / LongHorizon 系)
- 长任务 (项目级) **resist single-test verification** — 单测不足以验收, 需要 multi-channel verifier:
  可见反馈面 (agent 可自用) + **hidden checks** (最终评分, 防 reward hacking)。
- 完成率悬崖 (completion cliff): 无显式边界/验收标准的长任务, agent 完成率骤降 —
  **边界与验收先行**是长任务的第一设计原则。
- 防 reward hacking: agent 会找捷径 (硬编码/绕过测试) — 验收不能只有 agent 自己声明 done。

## 2. 核心设计 — 任务生命周期 (Task Lifecycle)

```
一句话需求
   │
   ▼
[Phase P0] 需求理解 → 任务章程 (TaskCharter) 生成
   ├─ 目标陈述 (从需求提取, GoalText 锚定复用)
   ├─ 验收标准 (acceptance criteria, 可执行优先: 测试/命令/度量)
   ├─ 边界 (scope bounds: 做什么/不做什么 — 防 scope creep)
   └─ 里程碑分解 (milestones, 每个里程碑自带 mini 验收)
   │  ◄─ 用户确认点 (trae 语义: plan 确认后执行; 本项目可配置 auto-confirm)
   ▼
[Phase P1] 逐里程碑执行 (现有执行链/子任务/隔离机制复用)
   │   每里程碑结束 → mini 验收 (可执行验收标准运行)
   │   失败 → 修复循环 (预算上限, 超限上报)
   ▼
[Phase P2] 任务结束验收 (Task Acceptance)
   ├─ 可见验收: agent 自跑 (测试/构建/命令) — feedback surface
   ├─ 隐藏验收: 独立验证器 (与执行链隔离的 checker — 防 reward hacking)
   ├─ 输出物清单核对 (文件/接口/文档 vs 章程承诺)
   └─ 验收报告 (evidence list: 每条标准的通过证据)
   │
   ▼
[Phase P3] 交付/复盘 → FixMemory 沉淀 (v0.14 修法记忆复用)
```

## 3. v0.15.1 任务进行中新输入路由 (用户钦定, 先行落地 — 判定器全复用)

```
任务进行中 (TaskCharter 激活) 用户新输入到达
   │
   ▼
TopicRelevanceEvaluator.Evaluate(新输入, goalEntities=章程实体, goalIntent=章程目标, ...)
   │
   ├─ 相关 (Normal / 补充语义) → 【主题补充】写会话 pendingContext (下次循环注入为依据)
   │       打点 task_input{route:supplement}
   ├─ Isolate (无关任务) → 【隔离任务】IsolatedTaskRunner (既有链, R313 已恢复)
   │       打点 task_input{route:isolate}
   └─ 新目标语义 (用户换任务/放弃) → pivot 重锚 (既有 pivotRequested 机制)
           打点 task_input{route:pivot}
```
- pendingContext 生命周期: 仅任务存续期间, 任务结束即清 (防污染下一任务)。
- 与 D1-D4 牵引的关系: 牵引处理"闲聊漂移"; v0.15.1 处理"任务进行中的新输入" —
  判定器同一, 消费路由不同 (牵引=提示, v0.15.1=入上下文或隔离)。

## 4. TaskCharter schema (草案)

```
TaskCharter {
  id, goal_text,            // 一句话需求原文 + 提炼
  acceptance: [             // 可执行验收标准
    {kind: test|command|metric|file_exists, spec, must_pass}
  ],
  scope_in: [...], scope_out: [...],
  milestones: [{id, desc, mini_acceptance}],
  status: planning|running|accepting|done|failed,
  pending_inputs: [...],    // v0.15.1 主题补充暂存
  created_utc, deadline_utc
}
```
- 持久化: data/task-charters/{id}.json (STJ source-gen, AOT 同款约束)
- 隐藏验收器: 独立于执行进程的检查 (如: 重跑构建/测试; 文件存在性; 输出 diff) —
  防 agent 自己声明 done (SWE-Marathon reward-hacking 教训)。
