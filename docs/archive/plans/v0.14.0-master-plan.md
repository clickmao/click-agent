## 1. 既有牵引体系盘点 (代码事实, v0.13.3)

### 1.1 主题从哪来 (上游)
| # | 机制 | 位置 | 语义 |
|---|---|---|---|
| S1 | GoalText 锚定 | V2 `IsGoalWorthy` (L324) → SessionMemory.Goal | 用户显式任务锚 ("我在做 Web API 项目") |
| S2 | 用户画像 coreTopic | `_tendencyAnalyzer.GetContextBiasAsync` top-1 (L535) | 跨会话统计主题 (Web API=0.80) |
| S3 | intent | IntentDecomposer.PrimaryIntent (L515) | 单轮意图 (code/qa/search/...) |
| S4 | forecast | NextTurnForecast.Save (L949) | 下轮预估 (补充检索/深入某结果) |

### 1.2 主题怎么用 (中游 — 生成前)
| # | 机制 | 位置 | 消费方式 |
|---|---|---|---|
| M1 | ContextAssembler 多源装配 | src/agent/contextassembler (Memory/Session/WebSearch/UserTendency/WorkspaceFiles/ToolOutput/SessionMemory) | 按 EnabledSources 注入 |
| M2 | TopicRelevanceEvaluator 三态 | agent/intent (R308 合并) | Isolate→subagent 隔离 (L556) / 供牵引判定 |
| M3 | think-memory recall | exploration, V2 L754 | 历史思考依据 (URL/文件) 注入, top_sim 0.97 |
| M4 | LinkRegistry 激活 | exploration, L786 | URL 三信号激活 → 探索链 |
| M5 | RunThinkChainAsync 探索链 | V2 L108 (种子→执行→digest, ≤4 步/4s) | 事前上下文增强 |
| M6 | prompt_build 打点 | L675 | 装配末点观测 |

### 1.3 主题怎么守 (下游 — 生成后)
| # | 机制 | 位置 | 行为 |
|---|---|---|---|
| D1 | drift 检测 + 计数 | V2 L713 (topic_relevance verdict) | 连续偏题计数 |
| D2 | L1 陈述提示 (≥2) | L943 追加 (ProcessAsync 后) | "偏离核心主题, 随时说一声" |
| D3 | L3 问句澄清 (≥4) | 同点 (R314) | "回到核心 or 继续当前?" |
| D4 | 拉回率度量 | topic_clarify{pulled_back} (R315) | C19 案常态化 (quick-12) |

### 1.4 盘点结论 (结构性发现)
既有体系的牵引方向是**单向的**: 主题 → 生成前注入 (M1-M5) → 生成后提示用户 (D1-D4)。
**缺口: 生成输出本身从未被主题/质量审视** — 输出质量信息不回流, 修法经验无沉淀层。
- L1/L3 问用户"要不要回主题"; 却从不问自己"这段输出对主题/质量合格吗"。
- think-memory 存"思考依据" (URL), 不存"输出缺陷→修法"。
- 上下文装配 (M1) 的源都是**输入侧**经验; 输出侧经验为零。

## 2. v0.14.0 设计 — 输出侧经验闭环 (复用既有骨架, 不建新体系)

### 2.1 架构定位: 第四环 (生成后自审), 挂在既有骨架上

```
S1-S4 主题锚 ──► M1-M5 生成前注入 ──► LLM 生成 ──► [D1-D4 用户侧牵引]  (既有)
                                        │
                                        └─► [T: 输出侧自审] (v0.14.0 新增, 生成后闭环)
                                              T1 静态规则 (OutputCritic, 已落 R318)
                                              T2 LLM 自审 (SelfCritic, 已落 R319 契约)
                                              T3 Anchor 过滤 (修法库/静态交叉/度量)
                                              T4 FixMemory 沉淀 (已落 R319) → 回注 M1/M3
```

**关键复用决策 (不新造的清单)**:
| 需求 | 复用 | 不新造 |
|---|---|---|
| 自审的主题锚 | S1-S4 直接传参 (BuildPrompt 的 domain = goalText+coreTopic+intent 拼装) | 不建独立领域分类器 |
| 自审的已知修法 | FixMemory.Recall(pattern) → checklist 条目 (T2b, R319 已落) | 不做领域标定白名单 |
| 自审记忆的检索 | Recall 同款 pattern 匹配 (零 embedding 依赖, 规则检索) | 不动 ThinkMemory (语义不同, 独立 FixMemory 已立) |
| 自审产出的注入点 | M1 ContextAssembler 源枚举 **加一个 DataSourceType.FixMemory** (与 SessionMemory 同模式) | 不做旁路注入 |
| 观测 | 打点 5-KPI 闭环 / audit 制度 | 不建独立评测脚本 |

### 2.2 数据流 (全链)

1. **生成后**: 回复含代码块 → OutputCritic 静态扫描 (R01-R08) + SelfCritic LLM 单次调用
   (checklist = 通用条目 + FixMemory.Recall(goalText+coreTopic) 主题条目 + R01-R08 概念版)。
2. **锚定过滤**: quote 逐字校验 (防幻觉, 已落) → OutputCritic 交叉命中 = 强锚 /
   FixMemory 已有同 pattern = 已知修法 (confirmations++) → 单源自审 = 观察态。
3. **沉淀**: 强锚条目 → FixMemory.Write (来源标记 human_review / llm_self_confirmed / metric_delta,
   来源秩: human > metric > llm, 已落)。
4. **回注**: 下次生成前 ContextAssembler 拉取 FixMemory.Recall(goalText+coreTopic) 注入少样本
   ("历史确认修法: 避免循环内 new[] 堆分配, 用 ref 局部变量") — **输出侧经验的第一次回流**。
5. **度量**: self_critic{stage, rule, sim} / fix_memory{recall_hits} / 批测 C 系命中复发率对比。

### 2.3 与既有机制的一致性约束

- **隔离语义对齐 (R302 教训)**: FixMemory 作为新 DataSourceType 进 ContextAssembler 时,
  必须同时纳入 EnabledSources 隔离体系 (K1 实验全源隔离要能剔除它) — 防自审记忆污染对照实验。
- **追加点位对齐 (R307 教训)**: T1/T2 提示在 SegmentRouter.ProcessAsync **之后**追加 (L943 同点)。
- **打点契约对齐 (R142/R151/R309 教训)**: 新打点 (self_critic/fix_memory) 的 summarize init 键
  与消费分支同 commit 落地。
- **预算护栏**: SelfCritic 调用 max_tokens 受限 (~600); 批均增量 >8% 自动降级为仅静态规则
  (熔断模式, 复用 CompressionBreaker 形态)。

### 2.4 主题锚定 (用户 R319 纠正的落地)

评审/自审**不需要领域预标定** — 会话主题锚 (S1-S4) 即领域标识:
- checklist 第 3 层 = FixMemory.Recall(goalText + coreTopic) — "该主题历史上被指出过什么, 就优先看什么"。
- 第一条批评来自 LLM 通用经验 (分布内即有效), 过锚后入 FixMemory; 第二轮起主题层自动带上该修法。
- **标定是累积产物, 不是前置门槛** — 与 L1/L3 的主题牵引同构: 先用画像/目标锚定方向, 经验随交互累积。

## 4. 验收标准

- [ ] 5-KPI: 回答准确性 (C 系零回归) / token (增量 ≤8%, 超限自动降级) / SKILL 调用 (零影响)
- [ ] 复发率: 注入修法后同类反模式复发下降 (批间对比, 真断言)
- [ ] audit: confirmed 修法人工抽查误报 <20%
- [ ] AOT 重发布 0 IL 警告 (Regex/STJ source-gen 对齐)

## 5. 排除项

- 不做多轮 refine 循环 (单次 critic 调用; 重写由主生成承担)。
- 不做无锚直入库 (LLM 单源 = 观察态, 不进生成上下文)。
- 不做跨语言规则铺开 (规则随修法记忆自然生长 — 主题锚定使预铺开不必要)。
- 不动 ThinkMemory (思考依据语义) — 修法经验独立 FixMemory。
