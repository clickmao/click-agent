## 1. 现状代码事实

### 1.1 **不存在"生成脚本"能力 —— 这是本轮定位到的头号断链**

- 两条脚本执行链都要求**脚本已存在于磁盘**：
  - skills 链：`SKILL.md` 包内 `scripts/main.py`（脚本随 skill 发布）
  - 插件链：`ScriptPluginRunner` 直接吃现成 `scriptPath`
- **全链路无"LLM 产出代码 → 落盘 → 执行"的通道**：`grep` 全仓无脚本合成/写入路径。
- 结果：任何"帮我写个 X"的任务，**只能一段式由 LLM 在回复里吐代码**，不落盘、不执行、不校验、不可迭代 —— 长任务必然断在第一步。

### 1.2 无工具注册表 / 无 function calling

- 无 `ToolRegistry`、无 tool schema、无 function-calling 协议；工具=skills（静态目录 + 名单）。
- `CapabilityScanner` 只做**探测**（工具是否在 PATH），不提供"声明需求"。
- `Permissions` 是空壳（有类型无接线），`IImageRenderPlugin` 等插件契约存在但宿主未接。

### 1.3 MCP：**明确排除**（用户既有铁律，勿再动摇）

- 项目立场（记忆 + 代码注释）：MCP 不做；外部生态接入=只做无头浏览器（PuppeteerSharp）+ 前端对接。

### 1.4 零 shell 违规（用户钦定铁律的现存债）

| 位置 | 问题 |

| `[src/agent.skills/SkillScriptRunner.cs:84]` | `Arguments` 字符串拼命令 |

## 2. 真机对照实验（用户点名的方法：跑一次，逐环节对照）

### 2.1 实验 A（改造前）—— `帮我用py开发一个py扫雷游戏`

命令：`dotnet run --project src/agent.host -c Release -- -q "帮我用py开发一个py扫雷游戏"`

| 观测点 | 事实 |
|---|---|
| 意图 | `intent=general`（未识别为"代码开发"类任务） |
| LLM 调用 | **1 次**，12990 ms，promptTokens=642 |
| 产物 | **无文件落盘**，代码只存在于回复文本 |
| 机器验证 | **无**（无 py_compile、无运行） |
| CLI 步骤显示 | `[04] 返回区段标记 python (已路由插件)` —— **"已路由插件"是纯显示文案，无任何校验动作**（"宣称≠实现"类，与 R365 三缺陷同类） |
| 用户实际拿到 | 一段可能含语法/逻辑错误的文本；需自己复制、粘贴、建文件、试跑 |

**对照我自身上下文（同任务）：** ① 检查解释器可用性 → ② 写文件到磁盘 → ③ `py_compile` → ④ 真实执行/冒烟 → ⑤ 读输出 → ⑥ 迭代修复 → ⑦ 交付**文件路径 + 验证证据**。
→ 逐环节差异：**第 ①③④⑤⑥ 全部缺失，②被"扔给 LLM 在回复里写"替代**。

### 2.2 实验 B（改造后，同一句话，同一模型）

| 观测点 | 事实 |
|---|---|
| CLI 步骤 | `[04] 返回区段标记 python` → **`[05] PY 落盘 + py_compile 1/1 通过`** |
| 产物 | **`./data/artifacts/py_20260913_035648_1f3f027c.py`（4573 B，137 行）** |
| 机器验证 | py_compile exit=0 |
| telemetry | `{"point":"script_artifact","module":"python-artifact","kv":{"path":…,"bytes":4573,"sha8":"1f3f027c","compile_valid":true,"exit":0}}` |
| **独立复核（不信 agent 自述）** | 我方另跑 `python3 -m py_compile <artifact>` → **exit 0 ✓**；`ast.parse` 通过，137 行 |
| 幂等性 | 内容寻址命名（SHA256 前 8 位）→ 同内容不重复写 |

**结论：T1/T2/T3 链路闭合，且有独立复核证据。** 剩余 T4/T5/T6（运行级验证、工具需求自述、迭代修复环）未闭合。

## 4. 剩余缺口与推荐设计（探索结论）

### 4.1 T5：工具需求自述（无 MCP 路线）

建议最小协议（本地、零生态依赖）：

```
ToolNeed { name, why(触发条件), inputs:[{name,type,required}], outputs:[{name,type}],
           locality: Local|External, evidence(为何现有 skill 不满足) }
```
- 触发：`SkillDispatcher` 返回 `no_hit` / `low_confidence` 时，要求模型**显式产出 ToolNeed**（结构化段，非自然语言）；
- 消费：① 本地可满足（PATH 有解释器/二进制）→ 直接走脚本通道 ② 不可满足 → 记录 + 可问用户（复用探索项 2 的 menu 协议）。
- **本地定位**：扩展 `CapabilityScanner`（已有"探测 PATH 工具"能力）→ 提供 `Resolve(toolName) → path|reason`。

### 4.2 T6：脚本合成-执行-修复环（长任务核心）

在 T1/T2 之上加两步：
1. **运行级验证（沙箱）**：`python3 <artifact>` + 超时（如 10s）+ stdout/stderr 捕获 + 非零退出码 → 结构化结果；GUI/长驻程序必须走"参数化 smoke"（如 `--selftest`/`--headless`），否则跳过并**诚实标注"仅语法验证"**。
2. **修复环**：失败 → 把 stderr 尾部 + 产物 diff 回灌给 LLM → 再产出 → 再验证，最多 N 轮（N 可配，默认 2），每轮留痕（与探索项 3 的 `StepArtifact` 同一数据结构）。

### 4.3 长任务断链的根因（与探索项 3 共识）

- 产物不持久化 + 执行器不传上游产物（runner 签名 `Func<PlanNode, CT, Task<NodeExecutionResult>>`，哑 runner 忽略上游）→ 跨步只能靠上下文猜。
- T1 的产物落盘正好是**长任务的天然锚点**：`data/artifacts/*` + 台账版本 = 可续跑的检查点。

## 5. 关键约束

1. **零 shell 铁律**：所有 spawn 用 `ProcessStartInfo.ArgumentList`；现存 2 处违规（`SkillScriptRunner.cs:84`、`ScriptPluginRunner.cs:154`）必须在动本域前修掉。
2. **执行安全**：任意脚本执行必须有超时 + 输出上限 + 工作目录隔离；默认不开"运行级验证"，需显式开关（`AGENTFRAMEWORK_PY_RUN`）。
3. **诚实边界**：语法通过 ≠ 逻辑正确；不得把 `py_compile` 通过表述为"已验证可用"。
4. **零反射 / AOT**：台账与报告结构用简单 record/手写序列化；禁反射式 JSON。
5. **AOT 体积**：新增插件不得引起 >5% 体积劣化。
6. **MCP 不做**（用户钦定），工具生态走"本地定位 + 前端接口"。
