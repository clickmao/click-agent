## 1. 目标（为什么）

R418 已把「过程/成本」维度落成仪器（`eval/probe/process_metrics.py`），但**探针只有单轮**：
`solve_agent`（`eval/probe/run_probe.py:430`）每题只跑一次 `agenthost -q <prompt>`，
判分单元也只有一次提交 ⇒ 「轮数恒为 1」「首次通过率 ≡ 整题全对率」（R418 诚实边界②）。
用户 KPI 口径是「每题 tokens / **轮数** / **首次通过率**」⇒ 必须先让**轮数**能分化。

## 2. 侦察事实（已验证，勿凭印象改）

- `eval/probe/run_probe.py:430-447`：`solve_agent` 一次性调用，命令 =
  `agenthost -q <prompt> --output-mode text --session-id probe-<ts>-<tid>`；**每题独立进程**。
- 探针归档回复（`data/probe/replies/agents<seed>-*.txt`）是 CLI 转录，含
  `── 执行中 (turn 1) ──` + `prompt 构建完成: ~N tokens` ⇒ 现有提取器能读 turn 与 prompt 侧 token。
- `eval/rover/r413/drive_task.py`（95 行）**已经在做多轮**：TCP `{"v":1,"type":"req","api":"chat.send"}`
  逐轮发 `TASK["turns"]`（`eval/rover/r413/task.json` 为 8 轮脚本），逐轮落 `turns-*.jsonl`
  （`turn/text/reply/ok/secs/events`）；远端调用数取自桩侧 `calls-*.jsonl`（外部真值）。
- 该多轮 harness 的 `ok` 是**传输层**成功（桩恒应答 ⇒ 恒 true）⇒ **不能**当质量/首次通过率用。
  质量必须来自**判定器**（`eval/probe/grade.py`）。

## 3. 决定性微实验：已跑 · **PASS**（2026-09-14）

**结论：同一 `--session-id` 跨两次进程调用，链续上下文成立。**

- 证据：`eval/rover/r419/probe_session_continuity.py`（日志 `/tmp/r419-cont.log`）
  - turn1 `记住数字 4271，只回「好」` ⇒ 回复 `好`，`promptTokens=4178`，`(1656ms)`；
  - turn2（**新进程**，同 sid `r419-cont-0914135525`）`我刚才让你记住什么数字？只回数字` ⇒ 回复 `4271`，
    `promptTokens=3925`，`(4315ms)`，`contextSnippets=10`。
- **副产物（关键坑，已改写 §4 口径）**：两次进程的转录里都出现 `── 执行中 (turn 1) ──`
  ⇒ **`turn N` 标记是「进程内轮次」，不是会话轮次**；多进程多轮下**不能**用它数轮数。
  轮数必须取**发送次数 / 归档文件数**（外部真值），否则会把 2 轮读成 1 轮（恒等判据复活）。
- 另一事实：本例 `llmModel=deepseek-flash`（未挂 role ⇒ 前置门关闭，走远端）⇒ 多轮成本读数
  天然含**每轮 prompt 侧 token**，可直接与 R413 的 -58.5% 口径并读。

## 4. 设计（多进程同 sid 路线，§3 已验）

1. **多轮题面**：给每个 `json_mini`/`topo_min` 题加一条**修正轮**（turn 2），文案取自该题的
   `tight_gen` 隐藏用例（例：「用例 X 你判错了，只重发修正后的完整程序」）。
2. **判分单元不变**：仍是**整题全对**；turn 1 全对 ⇒ 首次通过；turn 2 才全对 ⇒ 记「修复成功」。
3. **KPI 三元组**（对齐用户口径）：
   - `tokens/题` = Σ(每轮 `promptTokens=` 或 `prompt 构建完成: ~N tokens`)（**prompt 侧**；链不落 completion 侧）；
   - `轮数` = **实际发送轮数**（= 归档文件数 / 发送次数；**不得**读 `turn N` 标记，见 §3 坑）；
   - `首次通过率` = `turn1 整题全对` / 题数；另列 `修复率` = `turn2 修复成功` / `turn1 未过题数`。
4. **归档命名**：`data/probe/replies/agents<seed>-<tid>-t<N>.txt`（沿用 R418 命名空间，加轮次后缀）。
5. **成对负控（必做）**：① 注入「turn 2 也故意不回修正」的缺陷解 ⇒ `修复率` 必须为 0；
   ② 正控：oracle 多轮满分 ⇒ 修复率 1.0。无正控时仪器错与「题太难」不可区分（R415 教训）。

## 7. 约束与铁律（继承）

- 质量只取**判定器产物**；过程只取**归档原文**；外部真值优先于被测代码自报计数器。

## §7 首跑复盘 → 设计修订（本轮实测，非计划）

### §7.1 首跑暴露的两个问题（都不是「题太难」，而是仪器/设计缺陷）
1. **判定器遇坏字节整臂崩**（`grade.py:127`）：`subprocess.run(..., text=True)` 按严格 UTF-8 解码被测程序 stdout；
   被测程序打出截断多字节（实测 `0xe9`）⇒ `UnicodeDecodeError` 冒泡 ⇒ 整个真机臂 `STEP_EXIT=1`（批判 3）。
   修：`run_code` 改**字节捕获 + `errors="replace"`**，坏字节如实记为该用例不过，并回传 `bad_encoding` 计数（分类可见）；
   负控 = 程序只打 `b'\xe9'` 必须判 `wrong_output` 且 `bad_encoding==1`（**不得抛异常**）；正控 = 修正后正常程序仍 `ok`。
2. **修正轮前提为假**（原实现 `if turns > 1:` 对每题都发修正提示）：对**首轮已全对**的题发「你的隐藏用例没过」=
   虚假前提 ⇒ 实测把 2/3 已对的题改坏成 **0/3**（`p002: ok→partial`、`p003: ok→runtime_error`，回归 2 题）。
   归档为对照观测：`eval/rover/r419/evidence-always-correction/`（含 RUN.json + README + sha256）。
   修：`--correction {onfail,always}`，**默认 `onfail`**（只在首轮未过时发，前提为真）；`always` 仅作对照臂。

### §7.2 判据修订（预注册变更记录，只加强不放宽）
原判据 C「首次通过率 < 两轮合并整题全对率 或 已标饱和」在 `onfail` 下退化为**真空绿**：饱和时 C 不执行。
改为：
* **C0** `correction_mode == "onfail"`（前提下真）；
* **C1 非回归**：`两轮合并整题全对率 >= 首次通过率`（只允增益）；
* **C2 账本一致**：`增益 > 0 ⇒ 修复率 > 0`；`增益 == 0 ⇒ 修复率 == 0`（不许把「没修」读成「修了」，也不许修了不记）；
* **饱和 ⇒ 判 2（未分化）**，输出 `RESULT=SATURATED_NO_DISCRIMINATION`：饱和不是通过（R417 反饱和教训）。
