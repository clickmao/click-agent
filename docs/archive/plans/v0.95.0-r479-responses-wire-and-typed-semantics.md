## 问题（用户口径纠正）

1. 「传输过去的是 JSON」≠「入链 prompt 自身是结构化的」——既有实现把本地指示/权限/用户输入**混在同一段散文/消息里**，靠整包 JSON 表达结构；结构信息无法被压缩、也无法被机检。
2. 「LLM 返回后本地该做什么」散落在各调用点的分支里（chat 侧 `EmptyBodyDiagnosis` / 动作环 / 空正文恢复），**没有单一校准出口**；本地 LLM 与远端 LLM 走不同判据面。
3. 工具声明面只有 chat 形态的静态常量；Responses 形态（平铺 `name/description/parameters`）无处派生 ⇒ 若直接手写第二份常量必然漂移。

## 设计（只增不改；判据只取协议字段）

### A. 真实输入数据格式 —— `src/agent.modelqueue/ResponsesWire.cs`
| 面 | 内容 |
|---|---|
| `ResponsesInputItem` | typed 输入项：`Message`（role + content[]）与 `FunctionCallOutput`（call_id + output）；**工具回灌独立成项，不混进 user 文本** |
| `ResponsesWire.BuildRequest` | 手写 JSON（零反射 / AOT 安全）：`model` / **`instructions`（本地指示·权限类内容，独立字段）** / **`input[]`（用户输入，独立字段）** / `tools[]` / `max_output_tokens` / **`store:false`** / `prompt_cache_key` |
| `ResponsesParser.Parse` | `JsonDocument` 零反射解析：`status` / `incomplete_details.reason` / `output[]`（`message.output_text`、`function_call`、`reasoning.summary`）/ `usage`（`input_tokens`、`input_tokens_details.cached_tokens`、`output_tokens_details.reasoning_tokens`） |
| fail-closed | 不可解析 / 无状态无输出 / output 全为未知类型 ⇒ `Failure` 非空；未知 item **计数**不静默丢弃 |
| 真值口径 | `ResponsesUsage`：**未上报 ≠ 0**（`Present` / `CachedPresent` 分列）；`NewTokens = input − cached` 仅在两侧齐备时可得，否则 `null` |

### B. 内部精准语义（校准 LLM 返回后本地动作，含本地 LLM）—— `src/agent.modelqueue/LocalDecisionMap.cs`
单一函数 `FromResponses(result, actionLoopEnabled) -> LocalDecision{Action, Text, ToolCalls, Cause, Retryable, Banner, Reason}`，
**本地与远端同用**（协议同形 ⇒ 语义同一，不为本地另立判据）。规则（顺序即优先级，**只取协议字段**）：

| # | 条件 | 动作 |
|---|---|---|
| ① | `Failure` 非空 | `Fatal`（上层按通道失败；文案取上报告警） |
| ② | 工具调用计数 > 0 ∧ 动作环开 | `RunTools` |
| ②' | 工具调用计数 > 0 ∧ 动作环关 | `VisibleFailure`（`cause=ToolCall`，**禁重试**） |
| ③ | `status=completed` ∧ 正文非空 | `Answer` |
| ④ | `status=incomplete` ∧ `reason=max_output_tokens` | `Retry`（`cause=LengthExhausted`） |
| ⑤ | `status=completed` ∧ 正文空 | `VisibleFailure`（`cause=UpstreamStop`） |
| ⑥ | 其余（未知状态/未知原因/failed） | `VisibleFailure`（`cause=Unknown`，fail-closed 禁猜） |

文案**单源**：一切失效文案仍经 `EmptyBodyDiagnosis.Banner`（R478），本类不新写第二处文案实现。

### C. 工具声明面单一事实源 —— `src/agent.modelqueue/ActionToolSpec.cs`
一份规格派生两种线格式：`ChatToolsJson`（嵌套 `{"type":"function","function":{…}}`，**与既有 `ActionToolDecl.ToolsJson` 逐字节相等**，单测锁死）与 `ResponsesToolsJson`（平铺）。名称白名单与执行面同源。

- 真值口径：`usage` 缺字段 ⇒ `unreported`，禁冒充 0（R474–R477 铁律）。
