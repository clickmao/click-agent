## 设计（只增不改；判据取协议字段，不取用户文本关键词）

### A. 空正文定因（机制面）
新增纯函数面（AOT 安全、零反射、可单测）：

| 面 | 内容 |
|---|---|
| `EmptyBodyCause` | `ToolCall` / `LengthExhausted` / `UpstreamStop` / `Unknown` |
| `EmptyBodyDiagnosis.Classify(finishReason, toolCalls, reasoningChars)` | 规则组：① `tool_calls` 计数 > 0 ∨ `finish_reason == "tool_calls"` ⇒ `ToolCall`；② `finish_reason == "length"` ⇒ `LengthExhausted`；③ `finish_reason` 为空/`stop` ⇒ `UpstreamStop`；④ 其余 ⇒ `Unknown` |
| `EmptyBodyDiagnosis.Banner(cause, finishReason)` | 用户可见文案；**必须带上游真实 `finish_reason`**，禁再断言未取证的成因 |
| `EmptyBodyDiagnosis.Retryable(cause)` | `ToolCall` ⇒ **false**（协议级请求动作，抑制推理的复述提示不可能改变它，重试必空 ⇒ 省 1 次调用 + 32k 预算）；其余 ⇒ true（保持既有有界恢复 1 次） |

调用点（`ModelQueueRouter.CallAsync` 空正文分支）改为：`Classify` → `Retryable` 为 false 则**不重试**，直接落诚实文案并保留 `ToolCalls` 上抛（动作环开着时仍能执行，`ActionLoop` 以 `resp.Success && ToolCalls.Count>0` 为入口，保持 `Success=true` 语义不变）。

### B. 归属因果化
- `QueueResponse` 加 `RequestId`（调用入口生成，`Interlocked` 单调 + 会话前缀；AOT 安全）。
- `llm_call` 打点加 `request_id` / `finish_reason` / `tool_calls_n` / `empty_cause`；`llm_call_recover` 加 `first_finish_reason` / `retry_finish_reason` / `retry_skipped`。
- 链侧产出用户回复时落 `request_id` 绑定（同一 id）⇒ 轮次归属可按 id 严格 join，不依赖时间窗。
