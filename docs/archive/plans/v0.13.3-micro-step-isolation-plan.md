# v0.13.3 A6: 微步骤隔离执行 (Micro-Step Isolated Execution) 设计文档

> 状态: 设计中 (用户钦定 2026-09-08, 文档先行)。承接 A5 (隔离任务长上下文稳定性)。
> 用户定义 (逐字要点):
> - 在有限上下文中, **skill 调用能力不能丢失** — 应该如何设计?
> - 参考 v0.13.0【探索】能力: 通过关键字触发链接或反向链接到目标数据依赖或文档;
> - 上下文不足时, 将【当前任务步骤 — 注意不是任务, 而是当前步骤】继续细分成微小问题,
>   通过数据隔离方案将有效信息归纳到上下文后**单独执行该步骤**
>   (与无关话题边界隔离 subagent 能力类似), 执行完毕后**恢复主上下文**;
> - 【更正2】上下文长度**未达警告阈值** → 常规方案, 不执行微细分隔离;
> - 【注意】长期且能力间互相关联的跑测迭代优化任务, 需要**大量确定性数据和负样本真实评测, 先收集数据**。

## 一、触发模型 (更正2 语义: 阈值门控)
```
当前步骤执行前:
  est_tokens = 当前上下文 token 估算 (prompt_total + 预期输出)
  ├─ est < WARN_THRESHOLD (config, 默认 6000) → 常规方案 (现状行为, 零改动)
  └─ est ≥ WARN_THRESHOLD → 微步骤隔离执行 (本文 §二)
```
- 阈值 config: `context_budget.warn_threshold` / `hard_threshold` (9000, 必须隔离+丢弃策略)。
- 打点: `context_gate` (est_tokens, threshold, mode: normal|isolated_micro)。

## 二、微步骤隔离执行 (与隔离 subagent 同构)
### 2.1 步骤细分 (StepDecomposer)
- 输入: 当前步骤 (TaskPlan 节点 Text + Parameters), **不是整个任务**;
- LLM 一次调用: 把步骤拆成 2-5 个微小问题 (每问可独立回答, 带自己的数据依赖);
- 细分打点: `micro_step_split` (parent_step, micro_n)。
### 2.2 数据依赖归纳 (参考 v0.13.0 探索 — 关键字触发链接/反向链接)
- 每个微小问题标注数据依赖: 关键字 → 正向链接 (snippet/文档/URL) + **反向链接** (哪些历史片段引用了它);
- 归纳器只把该微问题依赖的有效信息 (从主上下文/RAG 提取) 放进微上下文 — **主上下文不复制全量**;
- 归纳打点: `micro_context_assemble` (micro_id, injected_tokens, source_n)。
### 2.3 隔离执行与恢复 (与隔离 subagent 同构)
- 每个微小问题在独立 session subagent 执行 (主记忆零污染), skill 调用能力全量可用 (skill 注入按微问题意图路由);
- 执行完 → 结果摘要回注主上下文 (≤200 tok/条), subagent 销毁;
- 主上下文继续原步骤 (下一微问题或收尾);
- 打点: `micro_step_exec` (micro_id, ok, tokens, skill_hits, ms) / `micro_context_restore` (restored_tokens)。
### 2.4 skill 保持语义 (用户钦定: 有限上下文 skill 不能丢)
- skill 匹配在微问题粒度重跑 (微问题意图可能 ≠ 原步骤意图);
- skill 描述注入按需裁剪: 只注入 top-1/top-2 候选 skill 全文 (非全目录) — 上下文省 60-80%;
- 断言: 隔离微步骤的 skill_hits 必须 ≥ 常规模式同步骤 (不丢失) — 负样本防线。

## 三、跑测与数据收集 (用户钦定: 先收集大量确定性数据+负样本)
### 3.1 确定性样本 (MS-N 系列)
| id | 场景 | 断言 |
|---|---|---|
| MS-N01 | 短上下文 (<阈值) 步骤 | mode=normal, 行为与现状一致 (更正2) |
| MS-N02 | 长上下文 (≥阈值) + 2 依赖微问题 | micro_step_split≥2, 每问 skill_hits≥1, 结果回注, 主上下文恢复 |
| MS-N03 | 微问题引用反向链接数据 | 归纳上下文含反向链接目标内容 |
| MS-N04 | 隔离执行后主记忆零污染 | 主 session 无 subagent 内部中间产物 |
### 3.2 负样本 (MS-F 系列)
| id | 诱饵 | 期望 |
|---|---|---|
| MS-F01 | 微问题依赖信息未归纳进微上下文 | 微问题诚实报"依据不足", 不幻觉 (打点 source_n=0) |
| MS-F02 | skill 在微上下文中被裁剪丢调用 | 断言失败 → 修复 skill 按需注入 (不允许静默丢) |
| MS-F03 | 细分后微问题依赖原任务全局状态 | 全局状态通过显式传递 (摘要), 不得隐性依赖主上下文 |
| MS-F04 | 阈值边界抖动 (est 在阈值±5%) | 决策稳定 (连续 3 次同决策, 防抖动) |
| MS-F05 | 微问题执行失败链 | FailureEscalation 插入 (用户确认/静默探索, v0.13.2 §四) |
### 3.3 先收集数据 (用户钦定)
- 第一阶段不写执行器: 先在现有批测打点上收集 est_tokens 分布 (prompt_total 已有) → 确定真实 WARN_THRESHOLD 与触发率预估;
- 语义对样本: 同步骤在 normal vs isolated_micro 两模式跑 A/B (答案一致性 + skill_hits 对比 + token 总量对比);
- 数据落 eval/results/micro-step-baseline.json, 阈值与期望收益由数据定, 不拍脑袋。

## 四、与既有能力关系 (能力间互相关联 — 用户钦定)
| 能力 | 关系 |
|---|---|
| 隔离任务 (A5) | 同构机制复用: session 隔离/销毁/零污染断言直接复用 |
| 探索 (v0.13.0) | 数据依赖归纳 = 探索的关键字触发/反向链接复用 |
| 思考链 (T3) | 微问题 = 思考链的 ExploreStep 粒度下探 |
| 粘性路由 (v0.13.1) | 微问题独立问询也走 sticky-route (相似问题首用成功模型) |
| FailureEscalation (v0.13.2) | 微步骤连续失败 → 升级插入 |
| 压缩/召回 audit (A1-A4) | 长上下文底座失效的检测器与修复器 |
