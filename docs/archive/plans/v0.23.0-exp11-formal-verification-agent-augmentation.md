## 1. 核心结论（可行性裁决）

1. **可行，但必须分层，不能当作"让 agent 自己写证明"**。
   证据面最强的一条是：**验证器与生成器能力互补** —— LLM 负责提议（生成候选、拆子目标、生成引理），形式化内核负责裁决（通过/反例）。DeepSeek-Prover-V2 的路线（子目标拆解 + RL）在 671B 上达 MiniF2F-test 88.9%、PutnamBench 49/658；其 7B 蒸馏版正是我们 exp10 的本地引擎目标。
2. **收益最大的不是"数学变强"，而是"错误早停 + 证据复用"**。
   同族系统实测：加入编译反馈后能力从 19.75–36.00% 提升到 58.75–62.00%（**+32.3 pts**），检索增强再平均 **+6.8 pts**（无反馈时 +12.4，有反馈时仅 +1.2 —— 说明反馈是主因，检索是补充），且**搜索使 REPL 反馈调用下降 29.8%（1496→1050）**。→ 形式化反馈能把"在错误路径上继续烧 token"变成"当场剪枝"。
3. **最大的风险是"形式化忠实性缺口"，且量级已被测出**。
   完整 agent 编译通过率 89.5%，但**语义忠实率仅 60.5% → 缺口 29.0 个百分点**；跨 8 个系统统计缺口区间 **3.0–29.0 pp**；人工复核中 95/114 个"编译通过"的拒绝案例被确认为语义失败。→ **"编译通过"绝不能当作"结论正确"**。
4. **可离线重放的证据链是 token 节省的结构性来源**。
   把"重新推理一遍"换成"复用一次已验证的证书"：一次生成、多次复用；证书自包含 → 审计/回放**无需再调 LLM**（已有系统实测：120/120 全对、反事实压力下 100% 源忠实，而同工具基线 95%、无工具基线 50–80%）。
5. **工程量级已被证明是"可交付的"**：一个"计划先验 + 静态验证"的守护系统参考实现约 **1900 行核心代码 + 130 个测试 + 2 个依赖**，且**验证路径零 LLM 调用**。

## 2. 方案架构（click-verify，五层）

| 层 | 名称 | 职责 | 是否花 token |
|---|---|---|---|
| L0 | 契约层 | 节点/工具接口契约（前置条件、后置条件、不变式、数据分级）；**编译期/源生成落进静态前缀** | 0（零 token 注入） |
| L1 | 本地验证内核 | `agent.rover` 本地 Prover（GGUF Q4_K_M、mmap、CPU+GPU）+ 确定性检查器（Schema/约束/污点/SMT 子集） | **0**（本地算力换 token） |
| L2 | 证据与缓存层 | 证明/引理工件（自包含、可离线重放）+ 指纹去重 + 引理库 | 命中即 0 |
| L3 | 闭环层 | LLM 返回 `{claim, formal, witness, grade}` → 本地验证 → 通过落地 / 失败回注反例或最小 unsat 核心 → **有界重试**后重新规划 | 仅失败时的回注 |
| L4 | 信任与经验层 | 信任台账（VERIFIED / SUPPORTED / PLAUSIBLE / SPECULATIVE，**只降不升**）+ 经验沉淀为"思考逻辑 skill" | 0 |

**硬约束（不可违反）**：① 不违反 R351 拆除令 —— agent.rover 是**自研新模块**，LLM 主体仍是 API 调用；② 零 shell、零反射、STJ Source Generator、AOT 为发布形态；③ 验证路径**不得**依赖 LLM 拍脑袋判定 `Location` 类结论。

## 3. 形式化用例库（可落地清单）

1. **数学/证明类**：子目标拆解 → 本地 prover 验证（对应 exp10 引擎）。
2. **工具调用策略合规**：调用前做符号化检查（SMT/SAT），不可满足即**阻断调用**并把最小不可满足核心回注提示（实测：策略违例下降、任务准确率不降）。
3. **计划静态验证**：计划的符号引用 + 污点传播 + 安全自动机（无需 LLM，参考实现 ~1900 行）。
4. **经验性主张的真值锚定**：把"我认为 X"降级为"有证据的 X"，无证据时**诚实弃权**而非猜。
5. **代码契约**：前置/后置/不变式（对应本项目"产物必须真跑通"闸门）。
6. **轨迹与后置条件验证**：对 agent 执行轨迹做形式化建模（工作流 + 后置条件 + 运行时自检）。

## 4. 与 5 KPI 的因果链 & token 节省机制

| 机制 | 机理 | 预期量级 | 验收判据（可机检） |
|---|---|---|---|
| M1 验证下沉到本地 | 原本要"远程复核/二次确认"的调用改由本地内核完成 | 每次验证省 1 次 LLM 往返 | `verify` 期间 `llm_call=0` |
| M2 契约前置注入 | 契约进静态前缀，减少澄清轮（澄清是纯开销） | 澄清轮 → ≤0.5/回合 | 用户回答频率**不升高** |
| M3 证据/引理缓存 | 已验证结论作稳定前缀复用 | 命中率 ≥97%（红线, R394 提高） | 缓存命中率不退化 |
| M4 错误分支早停 | 验证即剪枝，失败即回注修正 | 失败节点重试 ≤1 次 | 重试次数、无效 token 占比 |
| M5 形式化符号作压缩中间表示 | 符号串比等义自然语言推理串更短 | 同题 tokens ↓ | 同题优化前后对比 ↓≥15% |

## 5. 风险与反证（诚实边界）

- **忠实性缺口 3.0–29.0 pp**：必须用"非形式化→形式化"的**双向可读性检查 + 反例注入**做减损；缺口未测前，`VERIFIED` 只能当必要条件。
- **形式化 gaming**：模型可能"改写题目使其可证"（与规范 gaming 同源）。缓解：冻结目标陈述 + 人工/规则审计变更足迹。
- **长轨迹衰减**：有反馈时忠实率从 1–2 步的 **81.3%** 掉到 19–24 步的 **12.0%**。→ 闭环必须**限制单次闭环深度**并强制重新锚定目标。
- **本地 7B 能力上限**：7B 蒸馏版是"最强 7B"但仍远弱于 671B；因此 **L1 不能只押 prover**，须配确定性检查器（Schema/约束/污点）兜底。
- **成本转移而非消失**：本地验证消耗 CPU/内存（本机 2 vCPU/3.6 GiB）→ 必须 mmap 惰性 + 热张量常驻 + 主动回收（exp10 已实现账目）。
- **"验证覆盖 ≠ 正确性"**：未覆盖部分不得打 `VERIFIED`，须降级为 `PLAUSIBLE`。

## 6. 分阶段路线图（含回退）

- **P0（采样可验证）**：只做 L0 + L1 的确定性部分（契约 + Schema/约束/污点），在"已本地化"的节点上零 token 验证；开关 `AGENTFRAMEWORK_FORMAL_VERIFY=0` 可整体回退。
- **P1（闭环）**：接 agent.rover，落地 `{claim, formal, witness, grade}` 协议 + 本地验证 + 有界重试；验收：`llm_call=0` 的验证占比 ≥30%，历史用例通过率不下降。
- **P2（缓存与台账）**：L2 证据缓存 + L4 信任台账 + 经验沉淀 skill；验收：同题 tokens ↓≥15%、缓存命中 ≥97%、用户回答频率不升高。
- **回退条件（任一触发即回退到 P0 前）**：任一 KPI 恶化、忠实性缺口未量化即宣称 VERIFIED、验证路径出现 LLM 判定、AOT 发布形态被破坏。
