## 3. 判官多态的机制假设（可机检、可证伪）

前提事实（三通道）：
1. `ModelQueueRouter.cs:303-304` 判官路径 `CacheReuse = false`（R429 钉死）⇒ 缓存态不是"设计上"的变量；
2. 采样已 greedy（`LlamaCppClient.cs:7`：仅 temperature 采样器 + temp 0）；
3. 归档交叉表：`好，按这个来。` n=18，**prev_class 17/18 同为 `stub_ack`** 却三态并存（Adopt 6 / Correct 9 / Neutral 3）⇒ **prev_class 不能解释**。

⇒ 两个互斥假设，真机单变量可判：
- **H1（模型/路径非确定）**：**同一** (system, prompt) 重复调用出现不同字母 ⇒ 违反 R429 决策路径确定性 ⇒ 契约缺陷（真缺陷，须修）。
- **H2（输入差异）**：同输入恒同字母，多态全部来自 prev **原文**差异（`_lastReplyBySession` 在不同轮/不同臂取值不同）⇒ 判官对 (msg, prev) 是确定的，R445 的「消息面」结论需收窄为「(msg, prev) 面」。

探针（真机、零产品改动）：`eval/rover/r446/judge_determinism_probe.py`
- 4 组 (msg, prev) 取自归档语料；每组在**交叉序列**中重复 3 次（A B C D A B C D A B C D）；
- 每请求：system=`CorrectionJudgeSystem`、user=`BuildJudgePrompt(msg,prev)` 逐字复刻、`max_tokens=512`、`cache_prompt=false`、greedy；
- 判据：**D1** 组内 3 次字母全同（H2）／出现分歧（H1）；**D2** 跨组不得同字母混同（负控：探针有判别力）；**D3** 记账 `tokens_evaluated == prompt_n + cache_n` 逐请求成立；**D4** 服务端 `-np 1`（R430）否则作废。
