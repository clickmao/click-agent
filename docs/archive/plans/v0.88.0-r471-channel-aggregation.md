## 1 问题
R470 铺了三个通道字段并把「真实 43 条调用 100% 落入 `shared_prefix`」写成结论。**但聚合器不认识这些字段** ⇒ R470 的结论只存在于**证据脚本的派生规则**里，产品遥测侧无物可读。

机检（预检，本轮先做）：`data/telemetry/host.jsonl` 43 条 `llm_call` 中，**含 `cache_channel` 字段者 = 0 条（0/43）**。即 R470 的 `shared_prefix: 43` 是**派生值**（用 `(prompt, last_prompt)` 现算），不是产品实发。若不显式分开，任何后续聚合都会把**派生量当实发量**读走 ⇒ 空心 + 不可外部复核。

⇒ 本轮靶点 = 让聚合器**只读实发字段**，并在真实流上诚实地报「实发 0 行」而不是「实发 43 行」。

## 2 口径（预注册，先落盘后跑）
- 实发面（唯一口径）：逐行只读 `kv.cache_channel` / `kv.shared_prefix_hit_tokens` / `kv.shared_prefix_hit_rate`。
  - 缺 `cache_channel` 字段 ⇒ 计 `unreported.absent_field`，**既不算 0、也不算 `shared_prefix`**（禁冒充）。
  - `cache_channel` 值不在 `{same_session, shared_prefix, unknown}` ⇒ 计 `unreported.invalid_value`。
  - 非 `shared_prefix` 通道的两字段**必须显式为 -1**：≥0 ⇒ `double_count` 判红（禁双计）；字段缺失 ⇒ `wiring_hole` 判红（接线不完整，fail-closed）。
  - `shared_prefix` 通道内 `hit == -1` ⇒ 入 `hit_na`，**不进命中求和**（「0 命中」与「未上报」必须可分）。
- 对照面（独立单列，**禁止与实发列相加/混算**）：`derived_recompute` 用 R470 同规则离线重算，仅供比对。
- 守恒式：`emitted.rows + unreported.total == calls`（不闭合即判红）。
- **判定口径一字未动**：`effective_hit_rate` / `cacheable_tokens` / 97% 红线语义与取值不变；退出码语义扩展为「1 亦含分通道判据判红」。
