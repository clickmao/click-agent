## 1. 存在理由（为什么必须换路线）

R449/R451 两次都用「源码派生重建器 → 自己拼 prompt → 直发 llama-server」的**探针**路线。R451 已把重建文本与产品实发文本对齐到 `tpl=280`、`seed_sha16` 逐位相同、17 条 pin 对残余 delta 全落成长块，**但同一份文本下产品判 7/7 Skip、探针只判 3/7 S**，且探针 ack 行出现 `gen=6` 裸字母 / `gen=512` 复读 prompt 自身结构（模型处于「续写文档」而非「助手作答」模式）⇒ 残余失锚在**调用/解码面**（聊天模板应用方式/端点、采样与 `n_predict`/stop、上下文尺寸），**不在文本**。

⇒ 结论：**重建路线天生脆弱，弃之**。改由**产品自身**跑真实语料：产品自己发 prompt、自己做判决、自己写遥测 ⇒ **锚自动成立**（零重建 ⇒ 无可失配的中间环节）。

## 2. 设计

三臂，同一 AOT 产物（`/tmp/pub_r450/agenthost`，R450 发布后未改 `src/`），同窗口顺序跑：

| 臂 | 语料 | 前置门 `AGENTFRAMEWORK_GATE_PREFILTER` | 目的 |
|---|---|---|---|
| **RC** | `task-M20.json`（R450 网格，7 条认可族） | 开 `1` | **正控**：同窗口验证门仍能 Skip（期望 7/7）且成本复现（期望 `tokens_total=32968`） |
| **RP** | `task-REAL.json`（51 轮真实语料） | 开 `1` | **生产行为**：真实流量上有多少次 r1 调用 / 多少次 Skip（**外部效度真读数**） |
| **RJ** | 同 RP | 关 `0` | **判官强制面**：让门判吃到**真实 (msg, prev) 对**，取判官在真实分布上的 A/C/N 分布（对照规则标签，非同一器） |

### 2.1 语料保真（prev 链）

产品门判的 prev 来自进程内 `_lastReplyBySession` ⇒ 顺序喂轮即可，但**桩的应答必须等于下一轮语料里的 `prev_reply`**，否则门判面对的是「假上一轮回答」。实现：

1. `build_real_grid.py` 按**会话会话序**取窗口（首轮为种子轮，其余为测量轮）；
2. `reply-seq.json[i]` = turn i+1 的 `prev_reply`（会话末轮用常量兜底）；
3. `stub_seq.py` **轮感知对齐**：产品会在 user 消息后追加「[本轮参考上下文]…」⇒ 只能前缀匹配（前 64 字符）；被吞并轮（产品计划复用、0 远端调用）会跳过 ⇒ 指针只前进，逐请求落盘 `match_turn`/`align_gap`/`used` 供机检。

### 2.2 语料口径（诚实登记）

- 语料 `eval/rover/r449/real-corpus.jsonl`（1,542 行）按会话分组后**只有 3 个真会话**：`20260906_070359_b183e6e4` 1,035 行 / `20260905_132828_cbfa2160` 157 / `20260905_102140_6ce72e21` 38 ⇒ 真实流量高度集中（**67% 来自单一长会话**）。
- 本轮窗口：b183e6e4 取尾 33（种子 + 32 测量）、cbfa2160 取头 9、6ce72e21 取头 9 ⇒ 51 轮，48 测量；规则标签 new_task 23 / adopt 15 / correct 10；`user_len` p50=24、max=6137；`prev_chain_ok` 46/48。
- **语料卫生缺陷（本轮新检出）**：1,542 行中 **276 行来自 cron 会话**（如 `cron_b15eb2f40a69_…`，`user_len` 达 8 万字符）⇒ R449 的「排除 cron」声明未落到本文件。本轮窗口**不含** cron 行（三会话均为用户真会话），但该缺陷须回写 R449 证据说明。

### 6.2 预注册判据机检（P1–P4）

- **P1 PASS（外部效度真读数）**：生产配置下真实流量 **门 r1 = 0、Skip = 0**，由**产品自身遥测**产生（零重建）。⇒ 用户钦定的「一轮任务 token ↓≥30%（主要来自少发不必需的 LLM 请求）」在**真实分布上实现额 = 0**。
- **P2 成立但须改写框定**：判官 prompt 是 **S/P 二字母**（S=无新增可跳），**不是** A/C/N；落到 r1 记录的 14 票全是 S，且**全部被机械认可族守卫否决**（`gate:skip_rejected_nonack`）。
- **P3**：桩对齐 36/51（`unmapped=0`，dump→语料逐条可对）。**修正预注册框定**：门判 prompt **不含 prev 段**（`【用户消息】… 答案:`）⇒ **门判 = f(msg)**，故 prev 兜底的 14 轮**对门判读数无影响**（只影响未测的关系判官通道）。
- **P4 未触发**：RP 的 `gate_r1_n=0` ⇒ 未推翻「前置门在生产路径生效」。

### 6.3 一等发现（产品侧，均由产品自身证据支撑）

1. **守卫是承重结构，不是冗余**：真实流量上判官投出的 S 票 **14/14 = 100% 被机械认可族守卫否决**，其中 **13 票落在「继续下一轮」**（用户钦定的驱动类消息：仅要求执行下一轮）。若守卫缺失，这 13 轮会被本地跳答 ⇒ **用户指令不被执行**（质量硬线失守）。⇒ R444 的 `Skip ⇒ Ack` 等价性前置在这批真实数据上直接兑现了安全价值。
2. **真实流量可跳面 = 0，三条独立佐证**：① R449 机械面 `ack = 0/1542`；② 本臂前置门绕过 r1 **0 次**；③ 判官强制面 14 票 S 全被否决 ⇒ 即使撤掉前置门，Skip 仍为 0（只是多花 14 次本地 r1）。
3. **真实收益只剩「本地」那一份**：生产行为省下的是 14 次本地门判 r1 调用 = **7,204 tok / 51 轮 ≈ 141 tok/轮**，是**本地算力**，**不是**远端 API token ⇒ 与用户 KPI 口径（远端请求数）无关。
4. **另一条真实省 token 通道（与门无关）**：**吞并轮 7/51 = 13.7% 远端调用为 0**（产品计划复用/澄清应答吸收）。这是真实分布上唯一有量级的「少发远端请求」来源。
5. **门判输入面**：门判 prompt 无 prev 段 ⇒ 「r1 真假判别」在门这一层只读本轮消息内容（三块：S/P 规则+8 few-shot / role 块 / 成长块）。

### 6.4 器具缺陷（本轮实发，已修并重跑）

- **`RC-c1` 的 token 膨胀**：我的「轮感知匹配器」在网格臂上按**前 64 字符前缀**匹配真实语料轮 ⇒ 「继续…」类短轮**跨语料命中**，桩返回 160 字符真实回复（而非 15 字符常量）⇒ 远端 prompt 逐轮变长（39,364 vs 32,968）。
- **修**：加 `R452_MATCH=0` 走空轮表 ⇒ 桩恒返回常量回复；`RC-c2` 复现 32,961（Δ −7 tok = 字符估算 `//2` 的舍入级残差，**非产品行为差异**：逐轮 `actual` 序列与 R450 逐位相同）。
- **教训（通用）**：凡「按输入文本对齐」的重放器具，**匹配键必须限定在本次跑的语料内**，且**必须有一个已知期望值的正控**（本轮正是 `tokens_total=32968` 这条预注册数字当场抓住了缺陷）。

### 6.5 诚实边界

1. **起手偏差**：`MemAvailable` 2,420 MB < 2,650 MB 闸 ⇒ `context_size` 下修为 **3584**（原 4608），读数前声明；门判 prompt 实测 452–467 字符（≈300 tok）⇒ 远低于 ctx，无截断风险；真实轮最大 `user_len` 6,137 只走**远端桩**（不受此 ctx 约束）。
2. **覆盖缺口**：51 轮中 **15 轮未产生门事件**（其中 7–10 为吞并轮）⇒ 这 15 轮的门的走向 **未测（n/a）**，不得按 Pass 计入。
3. **桩应答非真回复**；门判不读 prev ⇒ 对本轮判据无影响；**关系判官（读 prev）通道未测**。
4. **规则标签是关键词规则**（非地面真值）：本轮 S 票的 13 票落在规则标签 `adopt` 上，而 R449 已判定「驱动类消息不得作采纳标签」⇒ 两器都不足以定「语义上该不该跳」，**守卫（更严的机械族）才是当前唯一可靠闸**。
5. **零 `src/` 变更** ⇒ 未重发布 AOT、未跑全量测试（本轮不动产品代码）。
6. RC-c1 读数**作废**（器具缺陷），仅作缺陷留痕。


## 7. 附·预注册期声明的诚实边界（保留原文，编号顺延）

1. **本轮偏差**：起测前 `MemAvailable` = 2,420 MB < 2,650 MB 闸 ⇒ 按 R451 先例**读数前**下修 `context_size: 3584`（原 4608），语义声称：门判 prompt ≈ 数百 tok、网格 prompt ≈ 450 tok ⇒ 短 prompt 无语义变化；**长轮（`user_len` 最大 6,137）有 ctx 截断风险** ⇒ 逐轮记 `gate_prompt_len`，超阈值单列 n/a。

5. **无 push**（推送暂停令未解除）；RC 复跑若 `tokens_total ≠ 32968` ⇒ 先查 ctx 偏差与桩字面，不得直接归因产品变更（`src/` 自 R450 未改）。
