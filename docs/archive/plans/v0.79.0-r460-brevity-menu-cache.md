## 2. 实测问题（R458 run2 读数，非估计）

| 项 | 实测 | 说明 |
|---|---|---|
| T5 回复 | **241 字符** | 块里列了 8 项 + 三行解释 ⇒ 模型逐项复述 |
| T6 回复 | **146 字符** | 插入语 78 字符（"插一句: …"） |
| 承接注入块 | 8 项 | `MaxArtifacts=8` |
| 调用数 | 17 | codex 13 |
| prompt ∑ | 54,927 | codex 91,002 ⇒ 我方 −39.6% |
| 命中率 | 90.4% | 红线 97% |
| 稳态命中 | 91.6% | miss 均价 **310** tok/调用（codex 236） |

命中率的算术：`hit = 1 − miss/prompt`；我方 prompt 均价 3,231（codex 7,000）⇒ 同样绝对 miss 下比率被结构压低。
故本轮同时给两件事：(a) 压每轮**新内容**（miss 分子），(b) 记绝对量口径。

## 3. 机制修改（禁提示词补丁）

1. `ContinuationBrief.MaxArtifacts` 8 → **3**，块改紧凑 2 行；截断诚实性保留（"…共 N 项, 只列最近 3 项"）；新增 `MaxBlockChars=200` 上界。
2. 新增 `BuildMenu(artifacts,total)`（≤3 项，每项 ≤24 字符，首项接地**真实产物名**）与 `BuildAsk(...)`：
   门问句与兜底反问**同源**⇒菜单在两条路径上都不依赖模型自觉。
3. `EvidenceGate` 承接分支改调 `BuildAsk`/`BuildMenu`；**空态不再给通用示例菜单**（"搜索资料/写文档/…"）。
4. `PlanResumeService.HumanizeVoidNotice` 78 → ≤`MaxNoticeChars`(48) 字符，保留两事实、零内部术语。
5. 器具面：适配器加 `ADAPTER_DUMP_FULL=1` 落**实发全量消息**（禁重建），`attr_r460.py` 逐块量注入体量。

## 4. 预注册判据（`eval/rover/r460/prereg-r460.json`）

- **P1 精炼** T5 ≤170 / T6 ≤110 / 承接块 ≤200 字符
