## 1. 为什么必须重跑

R449 的探针用**畸形的重建 prompt**（模板越界多抽 16 字符 = 3 个标签重复）作为输入，产品**永不产生**这种输入 ⇒ 其 `gen=6`、正控 3/7、负控 0/13 全部是**器具自伤**，真实流量侧读数一律 `n/a`。
R450 已把重建器修到 `tpl=280`，并在**同一成长态**下证明「**实发 == 重建**（delta=0、453 字符逐位相同）」⇒ 器具锚成立。R451 = 用**带锚的器具**取真读数。

## 2. 预注册判据（读数前写就，承 R449）

- **I1 正控（判别力）**：网格 M20 的**认可族**（7 条真实门判、产品侧已实测 `7/7 Skip` + `accuracy=1.0`）在探针下**必须 ≥5/7 判 S** ⇒ 否则器具与产品行为不一致。
- **I2 负控（不过判）**：13 条**非认可**夹具（纠正/否定/新话题/驱动）**必须 ≥9/13 判 P 或 C** ⇒ 否则门「见谁都放行」。
- **I3 忠实性**：探针每条 prompt 的 `len` 与同 run 遥测 `gate_prompt_len` 逐轮比对，残余必须**只落在成长块计数**（会话累积态），模板段 **delta=0**。
- **I4 判据门**：I1 ∧ I2 过 ⇒ 真实流量读数**有效**；否则 **VOID**，真实流量一律记 `n/a`（与 R449 同处置）。

## 6. 执行结果（2026-09-15）

- **判决 `VOID_INSTRUMENT`**（`eval/rover/r451/verdict-r451.json`）：I1 3/7 < 5/7。
- **本轮唯一的正面进展**：把失锚**从模板段赶了出去**——`tpl=280`、`seed_sha16` 与 R443 逐位相同、17 条 pin 对残余差全落成长块 ⇒ **prompt 文本不再是嫌疑**。
- **残余失锚定位**：调用/解码面。证据 = 同一份对齐文本下，产品 7/7 判 Skip，探针 3/7 判 S；且探针 ack 行两种形态（`gen=6` 裸字母 / `gen=512` 续写 prompt 自身结构『用户消息：…答案：S』）⇒ 模型处于**续写文档**而非**助手作答**模式。可疑差异：聊天模板应用方式/端点、采样与 `n_predict`/stop、上下文尺寸。
- **反空心结论**：I2 平凡通过（13 条非认可 11/13 P）**不构成证据**——同一调用面下判官近似恒定 P，只有 I1 才能拦。两控成对的意义在此轮直接兑现。
- **下一步（R452）**：**停止重建路线**，改由**产品自身**跑真实语料门判（零重建 ⇒ 锚自动成立），读数取产品自身遥测。

## 5. 排除项

- 本器具**只覆盖门判 prompt**（`JudgeTurnAsync` 的单字母判决）；`JudgeRelationLocalAsync` / 压缩通道 / 本地 skip 回复**不在本轮范围**。
- 真实语料**不筛**则 D 类 361 条贡献 193 假采纳 ⇒ 本轮 D 类读数**必须**带「驱动类 ≠ 采纳标签」的排除说明（R449 用户钦定）。
- 本轮**不改产品代码**（只跑器具 + 落证据）；若读数指向产品缺陷 ⇒ 另开轮修，不在本轮"顺手"改。
