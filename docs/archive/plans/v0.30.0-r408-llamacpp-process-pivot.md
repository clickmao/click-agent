**诚实修正（对我方不利，必须记）**：
1. 上轮汇报的 llama.cpp「7.3 t/s」是**并发污染读数**（当时全量回归在跑）⇒ 干净读数为 **11.1 t/s**。
2. 差距因此从 15× 修正为 **55×**（11.1 / 0.2017）。
3. **本引擎 AOT 比自家 JIT 慢 1.29–1.86×**（`forward` 同题：AOT `per_token_ms=4110.9` vs JIT `3191.0`；`generate` 步 AOT 4957 ms vs JIT 2671 ms）。原因 `待确认`（不预设 ISA 结论）。

差距归因（**直测，不是减法**）：

| 通道 | 读数 | 判定 |
|---|---|---|
| I/O | `disk_read_bytes=0`、`majflt=0`、`minflt=15960` | **纯页缓存命中，0 盘读** ⇒ 排除 I/O |
| 线程 | llama.cpp `-t2` 反而更慢；本引擎 `computebench` 2 线程仅 1.29–1.34× | 排除线程 |
| 阶段 | `timing{attn_ms=7875.8 ffn_ms=61080.7 lm_head_ms=923.0 total_ms=69885.6}`（17 token） | **FFN=87.4%**（FFN 权重占每层 88%）⇒ 时间 ∝ 权重字节 |
| 内核吞吐 | `streamed_bytes_per_pass=930612435` ÷ FFN 3.59 s ≈ **181 MB/s**；`computebench` 实测 Q4_K **192 MB/s** / Q6_K **211 MB/s** | llama.cpp ≈ 10 GB/s ⇒ **~55× 全在 dequant+dot 内循环** |

⇒ **不是「托管代码不行」，是我方反量化内核是逐元素标量实现（每 256 元素块 1 KB 栈缓冲 + 小块 `TensorPrimitives.Dot`），差在算法而非语言**。但用户已钦定 D3：走 llama.cpp。

## 2. 决策与边界

- **走 llama.cpp**，且**不 P/Invoke**（D2）⇒ 只能是**进程边界**：托管侧 HTTP/stdio 客户端 + 每 RID 一份 llama.cpp 二进制。
- 因此本工程**托管代码零原生依赖**不变（AOT/零反射铁律不受影响）；变化只在于「推理能力来自外部进程」。
- 代价（诚实记录）：放弃了「单文件自包含、无外部二进制」的原约束（用户 D1→D3 已显式改判）。

## 3. 设计（逐问题回答）

**Q1 进程形态？** 「长驻 `llama-server` + HTTP/SSE」，不采用「每次调用起 `llama-cli`」：模型只加载一次，`/completion`（SSE 流式）+ `/v1/embeddings`（同一进程同时供生成与嵌入）。已核实 vendor 构建含 `llama-server` target（`LLAMA_BUILD_SERVER=ON`、`GGML_NATIVE=ON`）。
**Q2 二进制从哪来？** 解析顺序：`AGENTFRAMEWORK_LLAMA_BIN`（显式路径）→ `PATH` 上的 `llama-server`；**都没有 ⇒ 显式 `provider_unavailable` 失败，绝不静默兜底/不退回自研桩**。自动下载发行件列为 `待确认`（本轮不做，避免无网环境假绿）。
**Q3 跨平台怎么保证？** 托管侧零 `DllImport`/`LibraryImport`、零平台硬编码路径、零 shell；平台差异只体现在「按 RID 提供哪个 llama.cpp 二进制」（与 PuppeteerSharp 取 Chrome 同构）。
**Q4 端口化纪律（沿用既有铁律）？** 执行面做成可替换端口 + ① 数值对账（生成 token id 与 `llama-cli` 基线逐位比对）② 被使用计数（`RequestsServed`/`TokensGenerated`/`ProcessStarts`）③ 无设备负控（缺二进制必须失败）。
**Q5 分词与聊天模板？** 交给 llama.cpp（`--jinja` + 模型自带模板）⇒ 退役自研 BPE/PreTokenizer/Jinja 解释器（R406 成果随之冻结归档）。
**Q6 嵌入？** 同一 `llama-server` 的 `/v1/embeddings` ⇒ 退役 `agent.embedcpu`（含 R404 那颗「自写前向 cos 0.21–0.34 静默算错」的雷一并消失）。
**Q7 AOT 影响？** 托管侧用 STJ 源生成 + `HttpClient`，目标 **0 IL 警告**；llama.cpp 在进程外，不进托管程序集。
**Q8 KPI？** 同题同参前后对比：t/s、每 token 耗时、输出 id 一致性；打点入 `eval/rover/`。
