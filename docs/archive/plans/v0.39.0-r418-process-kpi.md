## 2. 侦察事实（已完成，直接可用）

- 归档回复在 `data/probe/replies/`，**36 个文件**含指标行；可用字段（实测 grep）：`promptTokens=`、`llmModel=`、`contextSnippets=`、`forecastTendency=`、尾部 `(NNNNms, intent=...)`（如 `(24418ms, intent=code_generation)`）。

## 3. 实现结果（已完成）

1. **`eval/probe/process_metrics.py`（新，349 行）** —— 过程/成本提取器：
   - 质量取自 `data/probe/probe-*.json`（**判定器产物**，外部真值），过程取自 `data/probe/replies/*.txt`（**归档回复原文**）；
   - **归属铁律（本轮新增，承重）**：① 优先用 run 自带的 `reply_ns` 做**精确名**匹配（`--tag` 或新 seed 命名空间）；② 无 `reply_ns` 的旧批次退化为 **时间窗**匹配（窗 = `[ts - elapsed_s - 5s, ts + 60s]`，取自 probe JSON 的 `ts`/`elapsed_s`）；③ **窗内多于 1 个候选 ⇒ 判歧义记 n/a，绝不取第一个**；④ `ts` 不可解析 ⇒ 不做窗匹配（不猜）。实测：修窗前旧批次会**张冠李戴**（`probe-agent-seed20260913` 等 3 份 run 读到同一批回复），修窗后 `ambiguous=0`、无法归属者一律 n/a（`na_sum=61`）。
   - 口径：**n/a ≠ 0**，均值分母剔除 n/a；**首次通过率**只数 `mode==ok ∧ turns==1` 的题，`turns` 未知的满分题**不数入分子**且单列 `first_try_unknown`（保守）；报告显式标「只有 prompt 侧 + 墙钟，无 `completionTokens`」。
   - `--selftest` **14/14**（含成对正负控）：缺回复不改判质量为过；n/a 剔除分母（`1500.0` 而非按 0 摊的 `1000.0`）；畸形 wall 记 `malformed`；`ts` 不可解析 ⇒ 不猜；**越窗回复不得归属**（反张冠李戴负控）；同 tid 多候选 ⇒ 歧义；首次通过率对 `turns=None` 的保守处理。
2. **`eval/probe/run_probe.py`**：`run(..., ns="")`，回复文件名 `%s%s-%s.txt % (safe_solver, ns, tid)`，`ns` 缺省取环境 `PROBE_NS_SEED`（`main` 置为该 run 的 `seed`）⇒ 文件名形如 `agents20260916-p001.txt`；摘要 JSON 增 `reply_ns` 供下游精确归属。旧带 `--tag` 行为不变（`agentm6-p001.txt`）。selftest **18/18**。
3. **digest §3** 增成本列：`tokens/题`、`tokens/满分题`、`turn≤`、`墙钟均(ms)`、`过程 n/a`（源 `data/probe/process-metrics*.json`；缺 ⇒ n/a）。
