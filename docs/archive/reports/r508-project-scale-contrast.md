## 4. 结论（含被证伪项）

1. **「规模更大 ⇒ 本侧落后」在本轮不成立**：p1/p2/p3 三题（含 12 条硬用例的项目级题）两侧全部整题全对；本侧默认臂 token 分别为 codex 的 −14.9% / +7.5% / **−90.4%**。
2. **「本侧弱的根因是步数上限太低」被证伪**：加长预算（32 步）在同题上把 12/12 打成 **11/12**，且 tokens ×~5；显式短预算（3 步）两次均 12/12。⇒ 依「打分<上版即回退」原则，自适应预算**默认关闭**，仅 `AGENTFRAMEWORK_ACTION_ADAPTIVE_BUDGET=1` 显式启用（机制与单测保留）。
3. **真实前置缺陷在仪器侧**：codex 臂基准一度因 adapter 的 tool_calls 翻译缺陷归零 —— 不修会把「臂坏」误读成「本侧强」。
4. **残余不稳定用例**：`restart_drops_expired` 在契约 v2 的 6 次本侧跑次中 2 次失败（均为长/默认预算臂），3 步臂 2/2 通过。**摆动 vs 预算因果未分离**（n=1/臂，temperature>0）。
5. 修复后门禁：全量套件 **1636/1636 绿**（+2 新单测；首跑 1635/1636 的一例为 socket 抖动，二次全绿）；AOT 重发布 `PUB_RC=0`、`IL_warnings=0`、15,413,200 B、`sha256=ef90928e…`、`env -i --version` rc=0；NC `SELFTEST=OK`；判据前置（独立物化 + `python3 -I -B` 实跑 + 逐用例）对每臂每题执行。

## 5. 诚实边界

- n=1 跑次/臂（p3 本侧 6 次跨窗口），**不作统计显著性宣称**；`restart_drops_expired` 的摆动与预算/上下文长度的因果关系未分离。
- codex 臂 44 调用/885.8k tokens 含其自带沙箱探索与重读开销，与本侧「工作区 + 四工具」静态面不同源；按 H5 **禁作总量优劣断言**，仅按题内同用例对照。
- 判据只覆盖程序题（可执行产物）；数学/见证型题仍为 `not-applicable`。
- `run-r508b`（契约 v1）读数已作废并单列，不得与契约 v2 数据混算。
- 交互/人性化 KPI（提问/菜单/人话字）本轮未测；R507 器只覆盖程序题回复面。
