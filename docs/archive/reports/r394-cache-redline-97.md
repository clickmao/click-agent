# R394 — prompt 缓存命中率红线 95% → 97%（口径权威单点变更 + 结构性归因机检）

**用户令 (逐字)**: "token命中率红线报警改为97%"。

## 1. 因果链

红线不是一个数字，而是**首要 KPI 的判定权威**。它必须满足两个条件，否则是"台账装饰"：

1. **单点权威**：阈值只能有一个来源（C# 常量 `PromptCacheRedline.Threshold`），Python 侧
   `scripts/kpi_cache_hit.py` 的 `REDLINE` 必须与之**机检锁死**（防漂移测试），任何其它文件里的
   字节级代理断言必须**从常量派生**，不得写死数字。
2. **阈值 ⟺ 结构必需项**：阈值提高必须同步改"加厚前缀"的定量依据，否则文档会停留在旧阈值的
   算术结论上（本次真发现：`verification-registry.json` 与 `master-plan` 的 "95% 需前缀 ≥2496"
   在新阈值下已失效）。

本轮的**真缺陷修复**：两处机检（`SessionInjectionPlannerTests` 等）仍带 R380 之前的**陈旧 90% 标签**
（属"字节级代理"，改了常量它也照旧绿） ⇒ 改为**从权威常量派生**。这与审计标准一致：
"没测到 ≠ 测过通过"，代理断言写死数字 = 判定空心。

**顺带更正一处陈年口径残留**：文档原写"红线等价于每轮增量 ≤ 前缀/9"。该式属 90% 旧口径
（`hit/(hit+miss)`，增量进分母）。**R380 口径依 `min(本轮, 上轮)` 后，增量与判定无关**：
有效命中率 = 命中上限 / 上轮前缀 = `1 − (64+r)/P`（r = P mod 64）。只有 prompt **收缩**才换分母。

### 3.3 越线归因：**结构性**，非装配缺陷（本轮机检判决）

命中上限 = `(⌊P/64⌋−1)×64`。把 6 个实测轮逐条对上限对账：

| 会话 | 轮 | 需要命中 P | 实测命中 | 结构上限 | `hit==上限` | 缺口 | `64 + P%64` |
|---|---|---|---|---|---|---|---|
| cli-a436e194 | 2 | 981 | 896 | 896 | ✓ | 85 | 85 |
| cli-a436e194 | 3 | 1356 | 1280 | 1280 | ✓ | 76 | 76 |
| cli-3a338c2a | 2 | 2001 | 1920 | 1920 | ✓ | 81 | 81 |
| cli-3a338c2a | 3 | 2428 | 2304 | 2304 | ✓ | 124 | 124 |
| cli-9c7087f9 | 3 | 2536 | 2432 | 2432 | ✓ | 104 | 104 |
| cli-14ccd46e | 2 | 2551 | 2432 | 2432 | ✓ | 119 | 119 |

**判决：6/6 实测命中 == 结构上限 ∧ 缺口 == 单元对齐损耗（`64 + P%64`）** ⇒
越线 100% 归因**前缀厚度不足**，装配侧缺陷（`messages[0]` 改写 / 历史重写砍头 / 发送≠回放字节 /
增量异常）**0 例**。这也解释了为何同一批会话在旧 90%/95% 口径下"看着达标"：
不是变差了，是**尺子变严了，而前缀没变厚**。

## 4. 诚实边界

1. **97% 在当前会话前缀（≈0.98k–2.55k token）下结构性不可达**。上限 `(⌊P/64⌋−1)×64/P` 在
   P=2551 时仅 0.9533 —— 已实测吃满。达标需前缀 **≥4224 token**（最坏对齐稳健界；对齐最优 ≥2176），
   即把 `SessionBaseline` 加厚约 2 倍。
2. **与"降低 tokens"存在张力**：加厚前缀会抬高每轮 prompt 绝对量（命中部分单价低，但非零）。
   本报告**不擅自决定**，留作用户裁定项（见 §5）。
3. 本轮只改判定与文档口径，**未改装配结构**；因此越线明细中的 7 条历史记录仍在台账中
   （越线闸门不遗忘），符合"修复后新会话应达标"的设计。
4. `未上报 41` 条不并入比率（口径铁律：不得冒充 0%）。
5. 阈值 97% 是**用户钦定**，本报告不对阈值合理性做评价，只对"阈值 ⇒ 结构必需项"的算术负责。
