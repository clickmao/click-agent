## 2. 因果链：为什么首轮真跑是 0%，而真实能力是 100%

```
真跑 p001 (interval_sum) → agent 落盘 py_57906c9279782c29.py (2026B, py_compile ✓, run exit=0)
        → 判定器报 no_code (0/6)
                 ↑ 根因: 判定器只认 ```python 围栏; 产品真实交付 = CLI 回复区裸代码 + 落盘产物
        → 修 ① 多路候选(围栏/回复区/产物路径) ② 取"最长可编译前缀"(尾部混入状态行)
        → 同一份回复重判: mode=ok, 6/6
```

**这是本轮最重要的方法论证据**：`no_code` 不是能力缺失，是**判定口径假设错**。若不修，KPI 会把一个满分 agent 记成 0 分 —— 与"空心指标"是同一类失效，只是方向相反。

## 4. 负控（判据不可自证）

- **生成器**（21/21）：各题族参考解 vs 校验解**双路径**一致；**故意注入假答案时两条路径不一致 ⇒ 拒绝发题**（2 条）；退化参数下仍能发题且答案可穷举复核。
- **判定器**（13/13）：正确解满分；空回复 `no_code`；语法错 `syntax_error`；死循环 `timeout`；**真差一** `wrong_output`；单值硬编码 `passed<total`；**math** 的 `FINAL` 正/缺失/错答三态；**真机形态两条**（无围栏 CLI 回复+尾部状态行、回复只给产物路径）；**反向负控**：把比对函数换成恒真 ⇒ 差一解被判通过（证明判据非空心），恢复比对 ⇒ 再次被抓住。
- **编排器**（11/11）：`oracle` 满分；`extra`（多余输出）⇒ `wrong_output`；`loop` ⇒ `timeout`；`syntax` ⇒ `syntax_error`；`nocode` ⇒ `no_code`；`hardcode`（硬编码公开样例）⇒ **通过率 22.2% 但整题判不过** ⇒ 确立"整题全对才算过"的计分口径；math `wrongfinal` ⇒ `wrong_final`。

## 6. 诚实边界

1. **样本小且饱和**：6 题 100% ⇒ 对"能力提升"**零灵敏度**（参照 BGE 的教训：饱和就无区分度）。当前题族偏易，M6 必须加硬（多步/长轨迹/证明型/专门攻击"看似对"的解法）。
2. **数学题的"证明型"未覆盖**：现在只判最终答案（`FINAL:`），不判推理链；"答案对但过程错"无法分辨。
3. **沙箱不是安全边界**：仅隔离工作目录 + 超时 + `-I -B`，**不禁网**（本机离线、且题面不涉及网络；不可当作安全沙箱宣传）。
4. **真机读数含模型侧波动**（同题不同次可能不同）；单次运行不构成能力结论，须多轮/多题集对比。
5. **`agent` 适配器为单轮一次性调用**（`-q`），不含多轮交互能力测量。
6. 与 r371 的 D 链读数**不可直接对比**（题集不同、判据从"人工核对"升级为"隐藏用例自动判分"）。

## 7. 下轮候选

1. **M6 加硬题集**：多步任务（需落盘/多轮）、证明型数学（判推理链而不只判答案）、反例族（构造"看似对"的解法库，做对抗测试）。
2. **常态化**：静默 cron（零输出=正常，退化才出声），与 `bge-gate-fusion(静默)` 同约定。
3. **对比口径**：同题集上"优化前 vs 优化后"的成对读数（用户钦定评价口径），避免单次绝对值误读。
4. **skill 触发验证**：新 skill 是否真被注入（`type: knowledge_hint` 命中只注入知识），需通道级证据，不只看静态门禁。
