# R480-C: 目录关联摘要 / 摘要→分类 对【探索】聚焦精准度的负面影响

状态: 已完成（代理面第一跑）
轮号: R480-C
器具: `eval/recall/focus_probe_c.py`（Python 代理面）· 预注册: `eval/recall/prereg_r480c.json`（先于首跑落盘）· 产物: `eval/recall/focus_c.json`

## 用户问询（逐字）
「目录关联信息摘要是存疑的，因为主流agent都用全量grep说明了，摘要信息丢失严重可能会非标影响最终效果，但摘要变成信息分类会不会好一些，大分类，子分类1到n同时它也会影响我们当前的【探索】这个能力，需要测试，不确定对精准度【对任务步骤需要的信息的聚焦能力】带来多少负面影响」

## 语料与口径
真实本仓语料: 5,747 文件 / 98.0 MB / 1,456 个叶子目录; 步骤查询 600 条（由目标文件自身 tf*idf 派生，非人工标注）; 用时 19.1 s。
节点摘要 = 确定性抽取式词面 top-12（**非 LLM 生成**）; 覆盖度只在 ≥3 文件的目录上统计（避免单文件目录稀释）。

## 结果

| 臂 | 漏掉率 | 聚焦@可见集 | 可见文件 | 可见字节 | top10 含 gold | r@10 | r@50 | 中位秩 |
|---|---|---|---|---|---|---|---|---|
| A 全量 grep（零截断） | 0.0000 | 0.001221 | 1252.77 | 30,802,457 | 1.0000 | 0.3667 | 0.4633 | 92 |
| A' grep 取 top-10 | **0.6333** | 0.036667 | 10.00 | 560,364 | 0.3667 | 0.3667 | 0.4633 | 92 |
| S1 一级目录摘要（排除式） | **0.8183** | 0.005525 | 416.58 | 6,635,196 | 0.0000 | 0 | 0 | 0 |
| S2 二级分类（大分类→子分类1..n，排除式） | **0.0583** | 0.005983 | 421.51 | 6,829,298 | 0.0000 | 0 | 0 | 0 |
| S3 分类评分只参与排序（grep 兜底不截断） | 0.0000 | 0.001221 | 1252.77 | 30,802,457 | 0.3650 | 0.3650 | 0.4617 | 90 |

摘要信息丢失: 目录摘要 top-12 词覆盖该目录词量 均值 **36.93%** / 中位 **33.97%**（47 目录）⇒ 丢 ~63%。

## 判据
| 编号 | 断言 | 结果 |
|---|---|---|
| C1 | 全量 grep 漏掉率 = 0 | ✅ |
| C2 | 二级分类漏掉率 > 5% | ✅ 0.0583 ⇒ **分类不可作为排除式过滤器** |
| C3 | 剪枝臂零漏掉且 top10 不劣于 grep-top10 | ❌ 臂缺陷（可见集被 top-10 截断，与 A' 同构）⇒ posthoc 重列 |
| C4 | 目录分类聚焦 > 全量 grep 聚焦 | ✅ 但收益仅 4.5–4.9×，且以漏掉为代价 |
| C3b(posthoc) | 分类重排改善中位秩 | 92 → 90（r@10 36.67% → 36.50%，**top-10 上为零/负增益**） |

## 结论
1. 「摘要信息丢失严重」被量化证实: 词面摘要只保留约 1/3 词量。
2. 分类**当过滤器**不可用: 一级漏 81.83%，二级降到 5.83% 但仍有约 1/17 步骤目标不可恢复。
3. 分类对「聚焦精准度」的增益很小（可见集仍有 ~420 文件 / 6.8 MB，因为目录粒度太粗），换来的是不可恢复的漏掉。
4. **真正的负面影响源不是分类，而是候选截断**: 同一查询同一语料，全量零漏 → top-10 漏 63.33%; 全量 grep 的中位秩是 92（排序本身很弱）。
5. 设计裁定: 分类只可作为**排序特征/剪枝**（永不排除）; 截断必须可回退; 地址自描述（R480 `RecallLinks`）承担精准定位，与排序信号互补。

## 诚实边界
- 代理面（Python），**不测**产品面 `agent.recall`（C#）延迟与实现行为。
- 节点摘要为抽取式词面，**未测** LLM 生成摘要臂（需本地 llama-server，起手闸未开）。
- gold 由文件自身派生，聚焦量是代理量，不是语义正确率。
- 语料 98 MB 单仓；**未测** 1e5 文件档的 miss 率随规模走势。
